# Private inspect CLI witness — authored, not executed

Three new files, with no change to the protected source, public CLI selector,
original inspect functions, six-image report bundle, generator, image or tests.
Only AST/text authoring has run. The opcode port has not been constructed;
no component admission, native entry, VM or CLI has run in this scope.

## Independent issuer

`issue_preselected_inspect_record(absolute_manifest)` is explicit preparation
**before CLI selection**. It calls the existing real `admit_inspect_program`:
exact source/image and 13 host pins, before/after reads, actual mapping and
control metadata. Issuance therefore includes real native activity when it is
eventually exercised. It is not a Source mock or an op35 side effect.

The issuer selects the loaded program-tools module and requires its actual
dictionary to be the admitted owner's dictionary. Both current functions are
checked against independent passive templates. The two template bodies are
copied exactly from frozen policy source and independently compared with the
original program-tools bodies. They are never called; their code objects are
captured when this new module loads. Comparison includes `_CODE_FIELDS`, all
recursive constants/code, exception tables, names, locals, flags and signature
counts. Only filename, first line and line table are excluded. Unknown constant
kinds are refused before equality protocols can run.

This establishes an explicitly selected, code-checked definition namespace,
not historical `sys.modules` provenance. A name, builtin importer success,
`ModuleType`, or self-reported anchor tuple is not sufficient. The private
issuer and existing admission implementation belong to the trusted code
closure; this is not a hostile-Python sandbox.

The private registry holds the original module/dictionary, both actual
functions, code objects, defaults/keyword-default objects and values, builtin
mapping, real admission, source/image hashes, mapping/entry identities, and
original owner invoke/guard methods. Tokens have no data fields. Validation
requires exact token type and a registry entry whose weak reference resolves
to that object. A dict, receipt, lookalike or `object.__new__`-forged token has
no authority. Weak-release cleanup removes only the matching entry.

## Real selected path

The private loader passes the original report `path`, already captured `raw`
and `bundle` unchanged to the original six-image loader. It neither reads an
inspect manifest nor issues a token. An already admitted exact `NativeReportCli`
can alternatively be passed to `select_inspect_report_cli`.

Missing, unknown or stale tokens retain the original report CLI. The positive
path holds the exact existing control, formatter, discovery, routing,
parser-context and verified-report owners. Its inherited discovery/parser
`run` is unchanged. `prepare` first calls the original report preparation,
checks the actual weak-session report closure, then wraps it. All operations
other than 10 and 35 delegate to that exact closure, including op9.

Op35 retains the original prefix and its permission reads. The port is
restricted to actual CPython 3.14.4 and finds the unique original two-import
instruction slice. It keeps original globals, builtin mapping, constants,
names and local slots. The first module's POP_TOP stays in the copied bytes;
the second actual module operand is returned with the six selected providers.
The original two IMPORT_NAME and all IMPORT_FROM operations still execute in
order. There is no replacement getattr, public alias probe, or third business
import. Actual IMPORT_NAME resolves through the function's captured f_builtins
mapping at its execution point; the adapter does not separately probe or
assert the identity of __import__.

A different returned module fails the existing-record identity comparison,
even with copied names/anchors/providers. The operand is selection evidence
only and cannot create authority. Its carrier and operand are released before
the unchanged `common.update(...)`. Only successful update publishes the new
session witness. Failed or reentrant update cannot observe an early witness.

Op10 first captures the exact common provider and its completed op35 witness,
transfers the provider off its named local onto the call stack, then evaluates
`value(a)`. Reentrant argument evaluation cannot substitute a later witness
for this captured provider. After evaluation the existing record, captured
witness, provider identity and current function/owner state are checked. The positive
route calls the captured original `invoke_bound_inspect` function with the
actual admitted owner, entering its existing HIA prepare/finish path. The
negative route calls the captured provider exactly once and does not inspect
a foreign callable's attributes. Native entry errors are never retried as
foreign calls.

## Observable limits

The port introduces a private Python frame. Globals/builtins and initial
local contents are preserved; frame identity, code metadata, traceback frames,
arbitrary trace/profile/monitoring and refcount introspection equivalence are
not established. Import exceptions propagate without wrapping or retry, but
their traceback includes the new private frame. This is not whole-CLI
equivalence under frame-observing callbacks.

The second module is held until the port returns. It is released before the
original update, but exact destructor/weakref/GC timing and refcounts are not
inherited. The explicit record strongly holds module, namespace, functions and
admission; adapter/session closures retain its token. Existing mapping-cache
retention remains. These lifetimes require actual controls. The adapter holds
sessions through weak references, not a bound-method cycle.

Public definition/provider changes and unknown tokens have foreign paths.
Arbitrary changes to the private issuer/registry or original owner
implementation are outside the admitted domain. Successful issuance does not
assert ambient builtin, filesystem or process provenance.

2. Issue a real token from the actual inspect manifest/image and 13 host pins.

6. Keep original Source10/busy successor and all original 43 CLI IDs, order and
   assertions unchanged. Exercise the actual six-image report/discovery/parser
   chain. Op9 and unrelated effects must retain its original closure.

The three new paths need explicit source/implementation closure registration
before a portable qualifier can claim them. The inspect component's 13 pins
do not automatically cover this new adapter. No default selector is changed;
no cold, matching-current-source or whole qualification is asserted. Existing
180+3, 20s, 1MiB and 10M budgets remain. No source copy or executable is included.
