# Inspect R3: explicit predecessor readback and final VM4 completion

This package is author-only. No reader, binder, project import, compiler,
Native call, VM call or product group has been executed by this package's
author. Root owns each actual invocation. The original R2 attempt stays
`FAIL`, including its complete traceback, physical frames and outer return.

## Actual reason and narrow change

The R2 producer `BufferStore.put` returns five fields: `bytes`, `mode`,
`sha256`, `git_blob`, `file`. Its logical-buffer mode is exactly `100644`.
The actual Native witness catalogue and the eight VM observations have this
same shape. The parent `buffer_read` mistakenly required four fields.

The full R3 support file has exactly that schema correction: it requires
all five fields and that exact logical mode, and includes mode in both full
inflated-byte pin comparisons. The compressed file's real POSIX mode stays
separately checked by the original regular-file descriptor. No file is
chmodded. The 16 MiB ordinary `capture` limit, streaming INDEX reader,
decompression EOF/tail checks and all original budgets remain unchanged.
`BUFFER-REFERENCE-INVERSE.json` reverses the complete file to its frozen R2
bytes. All other functions remain the original complete bodies.

## Original coverage is preserved, not rerun or reclassified

The actual R2 Source18 predecessor has two successful owners. The actual
R2 Native/VM attempt launched nine owners: one compile, all seven Native
groups containing 17 methods, and the first VM group containing eight
methods. Every one of those children and owners completed successfully.
The ninth parent stage failed only after the child returned, in the parent
buffer-reference reader. Its four-method final VM group never started.

The independent R3 prefix reader validates these facts from complete raw
bytes. It does not substitute counts or a status summary for the records.
It reads all original R2 physical files and both complete Root outer scopes
with held/named seven-stat and full SHA/Git pins, recording complete pathsets
and ordered shards outside the R2 tree. It rereads all five original source
domains, all 2496 runtime files, the original ordinary B3, controls, maps,
generation evidence and host identities before and after. It validates all
original Source/Native/VM IDs, actual request/command/runtime bindings,
180+3 receipts, source guards and Root 1800+3 outer cleanup.

The compile readback binds all eight recorded observations, the complete
1 MiB output and actual image prefix, the source, thirteen real hosts,
manifest and original stdout/receipt ABI. The old build did not retain a
full compiler workspace, so this reader does not invent one or call a
receipt header a full workspace capture.

For every one of the 13,586 actual Native entry calls, the original frame
audit is rerun against all original BEFORE/AFTER and streaming INDEX bytes.
The reader additionally reads each of the six actual logical buffers,
checks the exact five-field references, source equality, extents, image,
return and request fields decoded from the real before buffers. It
reconstructs the original first-match catalogue in group/call order using
the original eight predicates and four actual fault records. The original
VM8 full-buffer comparison then reads both the actual VM and selected
Native bytes. It does not claim that all 13,586 Native calls were replayed
by the VM.

Success is named
`PASS_READBACK_OF_R2_NATIVE17_VM8_WITH_PARENT_SCHEMA_FAILURE`.
The R2 parent remains `FAIL`; its nonexistent tenth stage must still be
absent. The reader performs zero products and zero project imports.

## One explicit new completion owner

The actual prefix result hash is bound only after Root has executed and
reviewed the independent reader. No future result pin is fabricated.
`run_completion.py` accepts that exact hash, freshly reads all original
prefix physical payloads again, and admits the original complete source,
runtime, Source18, build and Native predecessors. It creates a new
`/workspace/hia-cli-as-dict-inspect-qualification-r3-dda7` scope.

It launches only the original `inspect-vm-actual-lost-returns` group, with
all four original IDs in original order and the exact original inner VM
test code, execution kit, source map and twelve-witness catalogue. The new
guard wrapper has a complete whole-byte inverse to the old wrapper: only
its explicit R3 authority, new outer output path and restriction to this
one unfinished cohort are added. The original Source child body is also
retained, though the new fixed request forbids invoking that cohort.

The original owner implementation is called once with 180 seconds plus
3 seconds cleanup. Every VM call keeps 10,000,000 steps, 8 MiB heap and
depth 128. Source guards, runtime guards, owner/ECHILD requirements, full
buffers, test bodies and assertions are unchanged. No compiler or Native
group is launched by R3. Parent full prefix checks happen outside that
owner just as the original Native predecessor checks did. Root's separate
outer watchdog remains 1800+3. The historical interval between R2 and R3
is not represented as one original 1800-second attempt.

All partial owner, child, wrapper, test, exception and VM buffer files are
left in the new scope on failure. There is no automatic retry. The final
parent independently compares every before/after buffer of the four new
VM witnesses and freshly rereads the unchanged complete R2 prefix and
source/runtime domains after the owner returns.

Only if all these checks pass may the new combined status be
`PASS_EXPLICIT_R2_PREFIX_PLUS_R3_VM4_COMPLETION`. Its report explicitly
partitions Source18, Native17 and VM8 from R2 and VM4 from R3, records
both scopes, and says the old single attempt is still `FAIL`. This is not
ordinary encoding, current-cold, default CLI activation, all-frame VM
equivalence or whole-stack qualification. Frozen R6 is not modified or
implicitly admitted; its later source/result binding remains a separate
explicit successor.

## Resource and storage boundaries

The new product keeps the original actual-filesystem 1 GiB free floor.
No source, runtime, image or prior buffer tree is copied. New writes are
metadata shards plus the final four VM observations and their actual
compressed buffers, in separate fixed output roots. The readback and
completion plans do not enlarge the ordinary 16 MiB capture or original
4 MiB predecessor-shard bound. INDEX, STATE and physical full-tree reads
use the already reviewed complete streaming reader. Metadata maps and
ordered descriptor lists remain in memory; this is not a claim of
constant total memory. Original R2 files and their seven-stat identities
must remain unchanged throughout.
