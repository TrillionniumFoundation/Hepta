# Independent Patch qualification terminal readback

This author package performs no product execution. Root may execute its single
stdlib reader after reviewing the fixed launch. It imports no project module,
starts no child process, invokes no machine image, and writes only to its new
independent output directory. The existing product attempt and source remain
read-only.

## Actual scope and retained boundaries

The fixed input is the original 20-owner qualification attempt under
`/workspace/hia-patch-terminal-quarantine-qualification-r2-dda7`. Its original
matrix is Patch Source11, CLI Source8, three build owners producing eight
images, Patch Native12, twelve separate CLI Native owners, the three external
quarantine methods, and VM12. These are 55 original methods plus three new
methods. The reader independently checks the exact IDs and their event order,
all subtests, original source bodies, and original limits. It does not reuse an
earlier run's test result.

The original 3211 mother source is retained. Source8 ran against the real,
independent 3210-file product view. The only omitted mother file contains the
three additional controls; those methods were actually loaded from the exact
external authority. The current Patch14 map differs from its retained map only
at the approved runtime and the data generated by the original generator.
Original R5 witness10 remains `FAIL_UNCHANGED_NOT_REQUALIFIED`; CLI43 was not
rerun here. Development compiles do not establish current-source cold or whole
native qualification.

## Independent reads

Nineteen preparation functions are reused byte for byte. Five functions from
the previous successful independent terminal reader retain a complete inverse
projection. Only their read/pin helper identifiers are adapted. Native orphan
inspection delegates the exact VM buffer directory to the separate VM reader;
no Native reference is skipped. STATIC-PROJECTION.json records every function
before and after. New code reconstructs this run's wrapper requests, inner
requests, all actual image bindings, and the complete ordered matrix.

Every buffer reference is read and fully decompressed anew. The bookkeeping
dictionary does not suppress duplicate reads. Each actual BEFORE and AFTER is
checked against its six complete buffers, current image, and final INDEX when
present. Missing or unreturned observations and orphan objects are preserved
explicitly. Process ECHILD and process-group absence are checked independently
and never converted into a claim that every frame retired.

VM12 is compared with the current Patch Native12 snapshot. All ordered shard
rows are reread; the first matching frame for each original predicate must be
the actual selected catalog row. All six VM buffers and all six corresponding
Native buffers are independently decoded for each selected observation. The
original 10M fuel, 8 MiB heap, and depth128 are fixed. Twelve selected frames do
not establish replay of every Native frame. `all_frames_retired` and
`all_native_frames_replayed` remain false.

All regular files in the attempt and outer directory are freshly read into the
complete raw inventory. Complete pathsets and seven-field metadata are checked
before and after. Full source/runtime guards are repeated at the end: current
3210, mother3211, retained R3 3210, protected R8 3180, and runtime2496. The old
preparation root seven-stat snapshot is historical; the now-existing attempt
legitimately changed that root. The reader checks its stable physical authority
and freezes the current terminal directory state instead.

## Failure behavior and limits

The reader handles a completed original ordered prefix and records a failure
as `PASS_FAILURE_EVIDENCE_VERIFIED` only when its original evidence is complete
enough to verify. It does not invent missing child reports or buffers. A reader
assertion, malformed record, or incomplete schema remains a reader failure with
its traceback and every read descriptor retained. There is no automatic retry.

The already-completed product limits remain owner180+cleanup3, compile20s,
10CPU, 1MiB output/workspace, and the original 1GiB start floor. The reader checks
those actual receipts and entry observations; it does not pretend its later
readback runs inside a past product deadline or alter that past budget. Its new
outputs are readback evidence, not product frames or replacement raw records.

Author-time execution is limited to text assembly, AST inspection, and pinning
existing metadata. The terminal reader itself has not been executed by its
author. Root owns its subsequent single readback execution.
