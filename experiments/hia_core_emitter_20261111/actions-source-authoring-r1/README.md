# Core and Emitter v2 source authoring on Actions

This is a frozen, **unexecuted source-only control**. It has no authorization to trigger its workflow by itself. The root agent reviews A and B, then may create the single declared execution ref.

The source job checks out the real commit `80ec04ae7489209b122c874531d194c67b30dfed`, tree `963e980c2486e1f7c74fa42bc8132ef6b1b8b690`, with all 4,023 leaves. HEAD, index, every leaf's actual bytes and mode, and the complete physical file/directory namespace are verified. Both physical and byte inventories are retained before and after generation. The source checkout is never rewritten; newly generated HIA and ABI bytes go into a new private output root.

The reviewed control A and product source use separate, credential-free detached checkouts. The authoring process uses the unchanged guardian and process owner with an actual 180-second deadline and three-second cleanup. Actions checkout, setup-python, and final artifact delivery are preparation/custody work outside that authoring deadline. The two-GiB disk line is only a source-authoring reserve; it is not the formal full-run eight-GiB/inode requirement.

The selected interpreter is the Actions installation of CPython 3.14.4. Its actual executable path, resolved file, bytes, SHA256, version, implementation, prefix, platform, and Git executable are recorded. No desktop `b2d6...` binary identity is assumed. Nonempty Git/loader redirections are rejected; child selectors/Python redirects are removed without repurposing HOME.

The new candidate must preserve the 33 entire original AST bodies, all 36 IR modes, and the finite 2,428-instruction/312-literal/510-slot inventory. The new 39-unit generation is still prospective until the job actually executes. Every unit is saved, public-Core assembled, and checked against the original 1 MiB/16,384-line/128-function/1,536-block/256-block-per-function/8,192-instruction/2,048-SSA-name/16-argument caps. Literal transport remains HIALIT01; main protocol and bundle admission are HIALOW02/v2.

The job performs no B3/native compilation, VM run, product caller, installed-wheel check, cold qualification, global contract regeneration, or default activation. The existing v1 results and the separate cloud Python3.12 finite-IR observation do not qualify these new generated bytes.

The finalizer first requires a receipt for this exact command, current inputs, 180/3 owner, natural exit, and closed ECHILD. It then reads every original unit, ABI, source inventory, stdout/stderr, and report identity. Any failure remains HOLD. The workflow always uploads the private output root and original stage logs, including failures; it never uploads the source checkout or Git credentials. An uploaded artifact alone is not PASS; the original FINAL.json and owner receipts must be checked.

The two desktop controls remain unexecuted and preserved. Unknown TimSort activity is unrelated and is neither cancelled nor replayed by this independent runner.
