## 四、P0：顺序 Safe Core 证明链

### 三种证据分别记录

| 证据类型 | 当前可支持的结论 | 仍不能推出的结论 |
|---|---|---|
| 通用模型定理 | 抽象资源状态、封闭表达式类型、分配事实与视图、有限 capability 图重命名和边界投影等，具有各自明确前提 | 生产类型检查器、实际指针实现及全部编译后端的通用正确性 |
| 逐程序全输入验证 | 对选定程序、位宽、算术与错误语义的约束进行全输入检查 | 任意来源程序或任意 C/C++ 的正确迁移 |
| 有限执行和破坏性控制 | 真正构建、执行、错误拒绝、生命周期和恢复的可复查观测 | 超出已声明输入域、调度或设备的普遍证明 |

主组合 `3707b871…` 的 r3 中，实际顺序程序全输入验证的 profile 为 `hia.sequential-acyclic-scalar-all-exports.v1`：本轮只覆盖确切 Core 中 `add_with_dead_literal`、`calculate` 两个公开标量 export 及其可达直接 callee，验证全部输入下正常返回、LLVM 结果一致且无 abort／poison。它明确不证明 ownership 或资源安全、验证器／编码器精化、原生机器码或 C ABI；循环、递归、FFI、硬件和并发均在范围外。类型、所有权、初始化和错误处理的实现检查，抽象模型定理，以及这个选定程序的全输入结论分别记录，不能合并称为源语言到机器码的通用证明链。

## 五、P0：强 AOT 性能基线

已实现显式启用的 `guarded-outline-v1`。真实条件分支、除零拒绝、所有权释放和原有整个函数的初始化决定被保留；结构检查与选定恒等式的求解验证有明确范围，没有被描述成完整 LLVM 后端精化定理。

基线是 Rust 1.95.0，实际参数为 `-C opt-level=3 -C lto=fat -C codegen-units=1`，另固定 `panic=abort`、`overflow-checks=off`、`force-frame-pointers=no`；既有常规实现也有显式字节实现。目标为 generic x86_64，没有 `target-cpu=native` 或 PGO。协议在执行前固定，覆盖两类既有工作负载、四组长度与种子、31 个离散长度（最小 0、最大 340,157），并非该区间内所有长度。每组 3 个种子，批负载 1/16/64；每个种子／计时请求有 3 次 warmup 和 21 个计时批次，分组统计汇合为 63 个批次观测。中位数比值上限为 1.10，批次 p95/p99 比值上限均为 1.20；批次尾延迟不能冒充单次调用尾延迟。

| 独立冻结实验 | 303/372 | 69 |
| 完整组合 r1 | 308/372 | 64 |

最终四组的通过数分别为：历史回归 67/84、历史保留集 71/96、此前 wrapper 长度组 77/96、新注册长度组 78/96。四组都有未达标比较，不能只挑有利长度作性能结论。

最终 r3 保留 3,348 个计时请求记录、216 个正确性记录和 84 个拒绝边界记录。样本和失败未被剔除，各轮未取最优值代替最终版本。

## 六、P0：NDU 的正确性与净收益

最终应用实验为三个场景，每场景三次重复，共九个 NDU 策略 episode，并与固定策略、精确 DP 和轻量控制按同信息进行比较。其中三个 tiny episode 未启动原生会话，其余六个会话共执行九次实际原生请求。在注册的有限模型中，这九次返回计划的预测目标值与同信息精确 DP 的差均为 0 ns。这不是实测服务成本差，也不等于程序全局最优或计入求解成本后的胜出。

| 场景 | NDU / 最佳控制的服务时间中位数 | 净收益胜出 |
|---|---:|---|
| tiny | 1.02707 | 否 |
| amortized | 1.14221 | 否 |
| invalidate-recover | 1.27984 | 否 |

| 策略 | 9 个 episode 的累计服务时间 | 注册规则下的完整分摊成本 |
|---|---:|---:|
| 固定 | 0.981106 秒 | 12.437043 秒 |
| 精确 DP | 1.047695 秒 | 12.503633 秒 |
| 轻量控制 | 1.025602 秒 | 12.481539 秒 |
| NDU | 1.152510 秒 | 60.779900 秒 |

完整分摊列按各策略的独立使用视角计算，包含已声明的桥构建、共有离线准备、服务及外层命令成本；不能把四行相加当作实际总实验墙钟。历史依赖获取、人力、长期驻留与证据保留等未完整测量，因此这列也不等于完整生命周期经济成本。NDU 服务时间本身也没有胜出：比精确 DP 高约 10.00%，比固定策略高约 17.47%。

invoke/skip、驻留、复用和失效恢复均在实际记录中：6 个 session、9 次请求、27 次 skip、3 次不启动 session、12 次复用、3 次 epoch 退役和 3 次重新获取。原生 raw 对照完成 2,976 次调用、744 个四臂配对，零错误、所有 witness 一致；每臂均为 744 次调用，NDU 相对 DP 的累计服务时间比值在单次启动模式为 1.03950、驻留模式为 1.04212。这些不是完整分摊成本比值或单次调用尾延迟。应用 cohort 没有触发预算 guard 的可选动作扣留分支；该分支另由独立 deadline 控制覆盖。

Lazy witness 对前端有实际改善：每轮 256 个模型扫描的请求构造总时间中位数，从 166.249938 ms 降至 125.602485 ms，约减少 24.45%。这里共有 11 个扫描样本；64 次真实原生核对保持一致。这项局部节约没有形成整个应用的净收益。

本轮可以支持“框架可接入、模型结果可校验、完整成本可测量”。NDU 净收益关闭条件仍未满足。

## 七、P1：真实 C/C++ 迁移和历史库复用

已增加明确启用的 unique-owner released-slot 复用 profile。C++ 中释放后仍存在的空 owner 槽位可以再次接收对象；HIA 侧建立新的线性绑定，避免把已消费的资源标识复活。分配长度、初始化和清理关系跟随当前实际 owner。

两个变体分别运行 2,211 个案例，使用原始 C++、独立 HIA 和独立 C 调用者对照生命周期。原有 profile 保持严格范围，新增拒绝控制覆盖 raw escape、空读取、陈旧边界、自采纳和分支生命周期不一致等情况；故意错误的释放顺序和缺失 drop 也有拒绝或差分证据。

真实 GSL 升级已扩展到 3.1.0、4.0.0、5.0.1。5.0.1 以实际上游 pin 和许可证文件绑定，处理新的引用构造方式与字段变化。覆盖的是声明过的 final_action 类方法和工厂实例化范围，不是整个 GSL。

SQLite 在本轮复验的是既有四字节 codec profile：3.46.0 和 3.53.2 各转换 `sqlite3Get4byte`、`sqlite3Put4byte` 两个函数；每版本覆盖 2,556 个输入，报告记录 5,112 项函数观测（`native_function_observations`），原始 C 与迁移结果均符合独立 oracle。本轮没有增加 SQLite 版本或转换语义；这两版选定函数源码字节相同，不能把这项复验当作处理真实函数变化的升级。 资格范围限于 `SQLITE_BYTEORDER=0`、`GCC_VERSION=0`、`MSVC_VERSION=0` 的 portable 分支，并以有效、已初始化的四字节分配和可变调用独占访问为前提；没有迁移 SQL 引擎、推断裸指针有效性或执行该 profile 的 Rust 裸指针 ABI 桥。

nlohmann/json 3.11.3 和 3.12.0 在七种主机／编译器组合上作为未修改的上游库，通过 C++ 桥与编译后的 Hepta 消费者复用。它证明这条受约束的生态接入路径可运行，不能称为整库已被安全重写。

人工迁移和维护时间仍未完整测量，不能把自动测试耗时替代为人工成本，也不能把未知人工成本写成零。任意 C/C++、任意模板与 ABI、宏条件分支、复杂异常及外部副作用的全面迁移仍未验收。

## 八、P1：Agent 开发收益

本轮完成了唯一一次冻结主实验：2 个模型 × 4 个自拟双文件维护任务 × 2 种语言 × 2 种编辑接口，共 32 个单元、63 次尝试，没有缺失单元或额外主实验。

模型为 Qwen2.5-Coder-1.5B-Instruct Q4_K_M 和 Granite-3.3-2B-Instruct Q4_K_M，运行于已绑定的 llama.cpp b11669。语言为 HIA 和 Rust；接口为整文件替换与精确补丁。四个任务为 `average_floor_stamp`、`clamped_delta_bias`、`stride_span_v2`、`floor_multiple_v2`。同一模型的各臂采用相同预算：最多 2 次尝试、每次最多 1,536 个输出 token、180 秒请求期限、8,192 上下文、4 线程、温度 0、种子 0、禁用提示缓存。CPU 亲和性为 8–11，不代表独占主机。

两种接口都验证原始文件 SHA 和准入条件；补丁须唯一精确命中。模型获得相同的公开任务说明与公开验证反馈。只有首次公开验证通过后才执行一次隐藏 oracle；隐藏失败不返回模型作修正反馈。本次唯一成功是 Qwen 的 Rust 补丁臂在 `clamped_delta_bias` 上的第一次尝试。

## 九、P2：硬件、ABI 与并发的实际范围

当前确切源码的 17 个成功原生 CI 产物覆盖：

| 主机 | 编译器 |
|---|---|
| Linux x86_64 | GCC、Clang |
| Linux AArch64 | GCC、Clang |
| macOS 15 AArch64 | Clang |
| Windows 2025 x86_64 | MSVC、Clang |

七组 C ABI 与声明的 stb_divide profile 使用对应已验证的 Rust 后端路径。每组观察 21,453 个不同输入、两种配置的 42,906 对调用，并记录类型错误、错误回显、目标 trap 和声明覆盖控制。被捕获的 C 应用还在 Linux x86_64/AArch64 上经直接 HIA LLVM 路径原生执行；这与七平台 Rust 后端范围分别记录。

C++ 桥在每个上游版本／主机组合上保留 98 个功能观测、32 个生命周期案例、1,024 次并发调用，以及陈旧读取、重复销毁、输入覆写和被拒绝变更等控制。普通 owner 的 live delta 为零；注册表保留的 2 或 3 次分配单独列出，没有被当成零内存占用。

取消是已声明边界上的协作取消。主机资源 continuation 实验恢复剩余后缀，并保留同一资源 owner；这没有证明 OS 崩溃恢复、任意外部效果回滚或任意时刻的异步取消安全。

设备、MMIO、DMA、通用多线程内存模型和任意外部 native 代码隔离仍未验收。原生 CI 运行是主机特定的实际执行证据，不是对物理设备或敌对宿主的证明。
