# Source-only compositional byte facts

This is an isolated source-generation experiment, not a proof-checking runner.
It neither invokes Lean nor changes an existing workflow or acceptance protocol.
All twelve obligations remain unproved and all authority flags remain DENY_ALL.

## Evidence motivating the experiment
The four-process diagnostic at remote580d425b (tree53764535) timed out in Part02.
Its last observed marker was after linear_length and before linear_byte_range.
That is an asynchronous reporting frontier, not proof that preceding roots
finished, not a per-lemma timing, and not identification of a unique bottleneck.
The original full connection remains UNCHECKED; earlier failures are retained.

## Unchanged data and conclusions
The generator authenticates the unchanged exact11 preparation. Its independent
restricted parser follows the actual Bytes→b0 List Nat expression DAG, not the
unconnected t0 suffix convention. All five complete byte streams are independently
reconstructed and matched to the original byte oracle. Original Raw/Bytes data,
serialization/parsing propositions, all4215 prior transport facts, original66
connection targets and ten exact negations remain. Only the proof bodies of the
five length and five range roots are replaced; their names and types are exact.

Each input receives595 named combined facts: exact list length and every byte≤255.
Short literal facts propose numerals checked by ordinary `decide +kernel` proof
text; named append/cons facts compose explicit child evidence through three fixed
helpers. Python's calculation is a proposal, not a Lean proof. The existing length
root uses the exact length component and small numerical bound; range uses the
component for the actual unchanged Bytes alias. No new assumptions enter roots.

## Two independent checks
A byte-offset edit ledger reverses every helper/fact insertion, all ten replaced
root proof bodies and all new axiom prints, recovering every original source byte.
An independent inserted-source verifier separately parses statement/proof frames,
reconstructs the authenticated byte DAG and verifies explicit dependencies, proof
templates, namespaces, roots and exact inventories. It does not call the emitter.
An emitter-fault adversary must fail even if regeneration repeats the same bug.

The helper definition and three theorem texts are pinned. Their library lemma
names were checked in official Lean4.19 sources, but no elaboration/kernel run has
occurred. Correct source structure cannot establish proof correctness or speed.

## Bounds and ownership
No existing acceptance/diagnostic validator is relaxed. Old validators reject the
derivative. The source-only protocol has no process, admission or partial-success
API. Existing imports, parent ownership and rejection metadata remain unchanged.

Fixed parser limits: RHS nesting32/tokens4096,4096 byte vertices/8192 references,
expanded bytes32768, plus unchanged source and original transport bounds. The
original expressions fit these limits. Namespaces, scope, canonical numbers,
unknown syntax, forward/cyclic references and complete-byte mismatches fail closed.

All retained old and transformed source files are counted separately. A conservative
future marked Part02 reserve is counted too; this does not generate a marker layer
or authorize a run. Total source≤8MiB, each source≤2MiB; transformation manifest≤32KiB.
A future separately reviewed runner would retain unchanged olean32/128MiB caps,
60s/process,540s launch cutoff,600s command and four nonaccepting invocations.
No current runner is changed or supplied here, and no additional CI is triggered.

Auxiliary facts may increase elaboration time and olean sizes. A future kernel
experiment requires a new reviewed proof/marker/runner contract with fresh parents,
full evidence identities and all unchanged caps. This experiment does not establish
that a complete module fits60seconds or that the full DAG can pass.
