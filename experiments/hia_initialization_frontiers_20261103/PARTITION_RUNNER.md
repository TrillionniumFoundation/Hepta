# Exact eleven-module research protocol

> Historical finite Core/native observations; removed harnesses are not
> delivered product entry points or current-source qualification.

Implementation and local/mock tests are not Lean acceptance. This isolated
protocol is UNCHECKED until the precise published head completes its locked
kernel run. No production runtime, initialization, admission gate, performance
threshold, or global proof obligation changes.

## Source boundary

The separately versioned source proposal and validator live in
`retired harness core-syntax-partition-sources`. They retain the independently validated
original structured preparation and recover its complete declaration streams
from six contiguous certificate partitions. Types, bodies and proof texts are
unchanged. The fixed names, cuts, complete-input root ownership and exact target
inventories are specified in `CONTIGUOUS_CERTIFICATE_PARTITION_PLAN.md`.

The new protocol must not accept an arbitrary eleven-stage manifest. It binds
exactly Baseline, SyntaxData, CertPart01 through CertPart06, Connections,
TransportRejections and WrongArm. Original ten-stage validation remains intact.
A malformed, unknown or mismatched protocol refuses without fallback. The
preserved original preparation must itself use the old structured protocol;
recursive or nested partition preparations are not valid oracles. Original
negative-location metadata remains bound to O; a separate independently derived
negative_declaration_locations map records actual new module/line coordinates.
Moving import headers must not silently relabel old line numbers as current.

## Execution boundary

`python -B -m tools.check_core_syntax_partitioned --lean PATH --output-directory DIR`
is the dedicated entry point. It uses the existing locked checker/support,
fresh-root isolation, same-run parent hashes, source checks, strict axiom
inventory and executor. It does not invoke the marker/noncomputable diagnostic
or invoke an extra version probe. Parent modules must have successful complete
receipts before any dependent process starts. For this protocol the frozen
manifest, RUN record, each started/completed receipt, and actual stdout/stderr
bytes are also hash-checked before and after launches, separately from olean
hashes. Parent receipt references are
recorded without introducing a self-referential receipt digest. Every partition prints its own
full inventory, and the independent source validation binds its per-input
coverage to the original 843 targets.

Maximum eleven Lean launches, 60 seconds each, no new launch after 540 seconds,
600-second external command and 15-minute CI job remain unchanged. Eleven
worst-case processes need not fit the wall limit: exceeding a deadline fails,
without skipping later checks or retrying. Source caps remain 2 MiB each and
8 MiB aggregate; olean caps remain 32/128 MiB. Existing diagnostic and filesystem
limits remain in force. Complete source is frozen before execution; a hash is
an identity binding, not a proof of provenance or semantic correctness.

No individual partition or successful prefix constitutes the complete syntax
connection. Only all eleven admitted modules, the complete original 66-target
inventory and all ten exact negation certificates can set the narrow kernel
syntax-connection result. All twelve global obligations and all Core/exporter,
body-prefix, resource, quota, initialization-elision, native, production and
performance qualifications remain unproved/false under DENY_ALL.

The new log printer uses only the fixed eleven-stage evidence names and checks
the frozen identities from the final result before emitting any evidence. A
mismatch produces no evidence output. Missing final evidence remains explicitly
incomplete. The final result cannot authenticate its own bytes; this does not
claim protection against a malicious host rewriting the result and all hashes.
There is
no directory walk, arbitrary file upload or additional artifact action. Existing
separate ABI/C++ jobs retain only their previously authorized evidence. Original
failures and both declaration diagnostics remain in PR history and must not be
rewritten as successful proofs.

## Validation before publication

Run the exact Python-only workflow inventories, including source reconstruction
and execution adversaries. Use the existing pinned solver environment; do not
install or run local Lean. Independent review must check full-byte recovery,
namespace and import isolation, target unions, hash/lease bindings, process and
source limits, failure at every stage, and the absence of automatic fallback.
Only after that review may an authorized exact-head CI run establish whether
this layout is feasible. More balanced declaration counts are not timing data;
a single root certificate or repeated import can still exceed the old budget.

The Python-only workflow retains the prior 289 controls and adds 16 source plus
12 execution controls, for 317 total. The source suite is deterministically split
into the first/last eight sorted unique test IDs; both jobs first require the
complete 16-ID inventory. Each matrix job retains its existing 180-second test
limit and five-minute job limit. Tests use mocks/fake files and never run Lean.
The kernel workflow calls only the dedicated partitioned entry point, not the
previous declaration diagnostic concurrently. All permissions remain read-only,
exact-HEAD checkout and unchanged source checks remain, and no upload is added.
