# Compositional byte-facts reporting diagnostic

This separately versioned experiment is nonaccepting. It validates the unchanged
complete exact11 input, the reviewed complete byte-facts transformation, and a
reversible marker derivative in that order. Existing acceptance and diagnostic
validators remain unchanged and do not accept this derivative.

## Physical sources and fresh parents

All eleven original sources and all eleven transformed sources are retained,
plus the marked Part02 source. Executed files use canonical Lean module paths.
Archive paths cannot satisfy imports. Every physical retained source byte is
counted before any subprocess. The transformation inverse restores every original
byte, while the independent inserted-source validator authenticates all explicit
byte-DAG dependencies, unchanged root statements and full five-input binding.

The only allowed sequence is fresh Baseline, transformed SyntaxData, fresh
CertPart01, and marked transformed CertPart02. The first three require exact
56/35/703 inventories, zero exit, complete streams and frozen same-run parent
module/receipt hashes. Failure stops the sequence. There is no fallback or retry.
Part02 binds its complete1298-name inventory. A completed process must have that
exact permitted-axiom inventory before it is reported as inventory checked.
Neither that result nor any target olean is admitted as an accepted parent.
No fifth invocation can start. All seven later stages remain unscheduled.

## Reporting and integrity

At most24 deterministic String markers lie at complete declaration boundaries,
including selected auxiliary byte-fact boundaries and the original root facts.
Independent byte-interval removal recovers the complete unmarked transformed
Part02, whose inverse recovers the original. Marker events report asynchronous
output positions only, not completion of earlier proofs or lemma timings.

Three manifests bind the original preparation, source transformation and marker
layer. RUN links their hashes. Source identity includes the parser, emitter,
independent insertion validator, pinned helper fragment, marker layer, runner and
existing dependencies. Frozen evidence includes all retained sources, actual
parent outputs and receipts, support/binary identities, capture streams/events
and any untrusted target output. Hashes retained before a mutation are not replaced
with the mutated hashes. The exact evidence set and internal manifest/receipt
lineage are checked before presentation, then hashes are checked again.

These checks assume a trusted process and host; a mutually rewritten result and
hash container are not external cryptographic attestation. Host loss can leave
incomplete evidence. Python/mock checks and source review establish no Lean proof.

Every outcome retains all twelve global obligations as unproved, full connection

A fresh exact-head kernel run is a separate step after source/protocol review and
current authorization/HEAD verification. No workflow change or run is implied by
