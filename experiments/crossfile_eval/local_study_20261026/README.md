# 真实本地小模型协议与失败成本实验：2026-10-26

**40/40 个预注册样本已保留，真实生成请求 40 次；合法工具动作 0，任务完成 0/40。**

这批数据证明本地真实生成、隔离协议、预算与失败账本走通。它没有证明 40 个有效 coding agent，更没有证明 Hepta、语义工具或智能汇编的生产力优势。当前模型没有产生有效实现变更，代码回归率和每次成功成本均无定义；不能把各臂零成功解释为语言能力相当。

其中 40 次在 512 输出 token 上限处停止，未产生被协议接收的工具动作。这是冻结输出上限和提示策略下的结果，不是对更长输出、约束解码、其他提示策略或强 coding 模型的能力结论。

## 冻结设计

- 两个不同的真实权重：HuggingFaceTB/SmolLM2-135M-Instruct 与 HuggingFaceTB/SmolLM2-135M base；同系列、同规模，base 未经 instruction tuning。
- 五个既定任务 × Rust/Hepta × 文本/语义工具，共 40 格、每格一次；严格使用原随机顺序，没有重抽、重试、提示修复或挑选结果。
- 每次模型调用冻结为 CPU bfloat16、2 线程、显式 ChatML、原生 8192 上下文、最多 512 个新 token。每格总预算仍为原计划的 32000 输入、12000 输出、44000 总 token、300 秒、32 工具调用。
- 相同 ChatML 封装保留所有任务文件、语言说明、工具模式和反馈；没有裁剪长输入或扩大模型上下文。
- 编译器严格绑定 `91ab73f35b5fede9582b2b1066a0f38d910426c51239fcfe557154fc3fd850cb`，对应已发布源提交 [bf5b7fc](https://github.com/TrillionniumFoundation/Hepta/tree/bf5b7fc05fd459292773d7bc67f36f60ca464f87)。后续编译器修正不属于本次测量；任务不覆盖新增 executable_core 指令集。
- Provider v1 对应独立源提交 [92a13e1](https://github.com/TrillionniumFoundation/Hepta/tree/92a13e1e21b80f4979828b3f02c38bb3017780c5)，与编译器身份分别记录；研究后的通用配置加固不会回写本次服务或 bundle 身份。
- 两模型的官方 commit、所有资产哈希、软件 wheel 哈希、服务代码与客户端 bundle 哈希保存在原始归档和冻结计划中。权重和第三方运行库未打包。

## 证据与核验

- `plan.json`：原始完整计划、随机 schedule、模型/预算/编译器/适配器绑定。
- `comparison.json`：原有比较器的完整输出。其 `complete_adapter_attested_pilot` 表示回执和完整分母满足框架条件，不代表模型完成了有效 coding。
- `ledger-audit.json`：逐个核对请求/响应、模型/服务身份、任务/源文件/工具/预算、原始 token ID 和累计回执；使用冻结 tokenizer 重建全部输入 ID 和输出文本。
- `raw-evidence.tar.gz`：全部 40 格 run/cost 记录、每条原始模型输入/输出/token IDs、服务与 bundle、运行时/权重锁、精确源快照、执行脚本、早期 74+128 token 的真实资格失败样本、workspace fixture 资格、资源事件与非运行文件清理清单。
- `manifest.json`：归档内各文件和交付文件的 SHA-256。归档不包含任何模型权重、第三方运行库或凭据。

本地账本一致性属于可信推理宿主的可复核观察，不是独立硬件证明或商业账单证明。五个 production workspace 的 native 隔离资格单独通过，属于 fixture 控制，不计入模型成功数。强 coding 模型、多模型家族、更大任务集、有效实现变更和回归行为仍需后续预注册实验。

## 复核方法

解压归档后，运行其中 `audit-source/local_model_audit.py`，传入 `inference-evidence`、`matrix` 和新输出路径；不需要 API key。若要重建 tokenizer 对应关系，按原 service 模型顺序提供两个 `--model-dir`，使用归档中的官方 commit/资产清单取得相同字节，并安装锁定运行时。原始源快照包含评分器和 native 资格接口，private oracle 始终只属于协调器，没有进入模型客户端 capsule。

新机器的解释器、编译器和运行库身份若不同，应冻结新计划；不要修改原计划或冒充同一个冻结运行。单模型 transport 资格、两个同系列小模型的协议失败实验与有效 coding 生产力实验是不同的证据层级。
