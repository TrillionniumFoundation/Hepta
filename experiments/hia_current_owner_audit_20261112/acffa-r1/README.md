## Result that matters for deletion

The old stack cannot be deleted. Several genuine HIA policy owners now exist, but their ordinary entrypoints use explicit manifests and retain the original Python owner when unselected. Even when selected, Python/CPython still supplies object observation, allocation, exception/foreign-call semantics, code custody and IO. Large business, proof, runtime and alternate-backend owners remain Python; NDU interfaces still call original Rust executables. A native executable or `_native` suffix does not establish HIA language ownership.

Current CI also blocks an acceptance claim: both fixed acffa push/PR runs failed **Step38, original51 ELF callers**, after complete component Step37 passed. Their original small custody package has been retained; the exact failure cause still awaits original report frames at this checkpoint. A third same-tree CI failure is a separate observation. This audit does not guess the cause, change the result or substitute a new run. TimSort source authoring `078d` remains UNKNOWN without a job ID; no generation/native result is inferred.

## Dependency order and concrete next owners

1. **Recover and repair the actual ELF caller failure first.** Component success and finite development51 success do not erase two current exact-tree caller HOLDs. Retain the full original51 ordered IDs, all anomaly checks, source/image binding and 180-second owner. After that, native TimSort must preserve the original comparator/effect/exception schedule; Python sorting cannot be used as the replacement policy.
2. **Finish the general direct-backend control.** Current acffa still runs Python `_Emitter.__init__`, `ordered_blocks`, `wrapper`, `render` and outer `_emit_program_machine_with_encoding`. The selected Function bundle does not replace these methods. Root's later emitter candidate is a distinct source identity and must obtain its own evidence. Shared linking, object inspection, byte ABI wrappers, publication and build receipts remain subsequent owners.
3. **Close concrete CLI IO/format slices.** The HIA CLI effect dispatcher still calls `read_bounded`, verification, editing, publication and `output_json`. The bounded-reader candidate at `7d5a4c` is static only, has no installed/default hook, and still needs dynamic `_reject`, finalizer, exception-context and one-shot finish validation. Pretty JSON is a separate root-owned candidate. The original 8-MiB input boundary and explicit smaller limits must remain, as must old caller 3/5-second budgets.
4. **Separate Agent policy from persistence and business authority.** HIA journal, six Store authority modes, page policy and worker report are useful complete slices. They do not replace the ten-table SQLite schema, transaction/WAL durability, context/proof/budget logic, slot CAS, adoption/rollback, leases or process execution. Replace these as coherent state-transition owners before replacing the storage engine, preserving request intent, original-job reconciliation and atomic effect/response semantics.
5. **Close supported whole-entry composition before default activation.** Encoding37, state6 and instruction41 are independent selections; only byte selection leaves operand/state decisions in Python. Likewise worker report does not imply native request admission, nor Store authority imply native file/JSON ownership. Pin the composed source/image graph and observe all actual selected stages.
6. **Retain proof, alternate-target, runtime and Rust obligations.** Z3 models, Python VM/lifecycle controllers, LLVM/AArch64 and structural inspectors, transformations and NDU Rust algorithms are actual owners. They cannot be removed merely because the common direct x86 path has advanced. Independent reference tests remain valuable evidence and are not converted into product-native claims.
