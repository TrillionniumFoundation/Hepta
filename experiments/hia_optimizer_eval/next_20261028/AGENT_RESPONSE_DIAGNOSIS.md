# Agent 失败诊断与下一项可执行改进

本文件只分析已保留响应的结构，不修改、重新编译或重评分任何模型答案。

## 已观察到的具体问题

两家系的 12 次完整升级响应都直接把文件名放在 JSON 顶层，例如 `api.rs` 与 `client.rs`，或两个 HIA 文件名。冻结提示明确要求唯一顶层键 `files`，但这些响应没有该封装，因此全部在 `E_UPGRADE_RESPONSE_FIELDS` 处被拒绝。它们没有进入候选编译、公开原生测试或 hidden 测试。不能从这些记录推断文件正文一定正确，也不能将手工补上封装之后的假想成功记为模型成功。两个没有完整响应的 HIA 升级请求仍计为预算超时。

按实际 scored submissions 计（与任务格分母不同），共有 46 次提交：30 次响应/JSON/允许编辑合同拒绝、8 次实际原生语义失败或陷阱、5 次通过本次原生测试、3 次预算超时。另有 4 次格式 probe。主实验仍是 32 格，升级仍是 8 格；自动第二次提交不增加任务格数。

Granite 的主实验有 15 次响应被拒绝，包含错误的 site 字段、错误的顶层字段、重复 JSON 键和不完整 JSON；剩余一次是 timeout。Qwen 则有 13 个真实 native 候选进入验证，其中 5 个通过，另 8 个结果错误或触发陷阱。即使解决响应封装，已经观察到的语义错误也不会因此自动消失。

## 下一轮可执行方案（尚未实施或计为结果）

1. 给 HIA 与 Rust 同时提供仅约束响应合同的输出 schema：要求顶层 `files`、允许的文件名和内容类型，或主任务的 `edits`/site 字段。不要把正确操作、常量或源码放进 schema。保留相同 checker、语义任务、预算和实际 token 计量。这是在生成时遵守已声明接口，不是事后改写模型答案。
2. 将当前只有错误码的公开响应诊断补为机器可读的实际字段/期望字段及位置，仍不提供 hidden 输入或答案。先通过固定正负控，再在任何新答案产生之前登记新协议。
3. 新一轮使用预先冻结的新任务与输入，原始格式约束作为对照，schema 约束作为另一个实验条件；不得覆盖本轮数据。较长 HIA 模块的响应成本还需要单独比较事务式结构化 patch 与完整函数替换，并给 Rust 同等编辑范围和工具信息。

这些是由当前原始响应提出的后续假设，不是本轮已证明的效率提升。所有超时与拒绝继续留在分母，人工及工具构建时间仍需另行测量。
