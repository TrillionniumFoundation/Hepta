The existing native compiler and component kernels still depend on hosted ordinary-entry decisions, instruction-byte construction and serialization work. This candidate moves three further responsibilities into checked-in HIA while keeping their actual ordinary callers, installation resources and failure behavior reviewable.

- **CLI control and presentation:** both HIA images handle the 15 action selections, argument/option decisions, version-specific negative-number recognition, help/errors, Unicode/color/wrapping and effect phase acknowledgements. All 15 action business bodies, foreign IO/publication and successful pretty JSON materialization remain hosted.
- **Instruction bytes:** HIAX6402 implements 37 x86-64 commands. Ordinary explicitly selected `Code` construction and backend identity use the pinned native image. Operand/foreign admission, mutable code state, labels/fixups/relocations and the general object/backend pipeline remain hosted.
- **JSON wire:** HIAWIR03 adds bounded immutable-key caching after successful original preflight and fixes callback lifecycle observations. Original byte/node/depth budgets, refusal order and 3/5-second caller limits remain. Custom observers/formatters keep their separately declared boundary.
- **Qualification and source custody:** v8 adds complete CLI, cache, encoding and installed-wheel evidence admission while preserving the original full runner and guardian gates. The source transport preserves exact commit bytes, all tree/blob objects and real parent headers with an explicit depth-one shallow boundary.
