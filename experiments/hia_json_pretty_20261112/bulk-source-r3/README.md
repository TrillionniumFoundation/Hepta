# HIA JSON layout: bulk copy and indentation source revision

This is a distinct unexecuted-native source revision. It does not alter the already queued baseline native development run 43134139906 or its frozen 31 cases.

The previous layout emitted every byte and every indentation space through a helper that reread and rewrote the little-endian workspace counter. The measured development IR execution for the valid depth-128 fixture required 20752690 operations. This source keeps the original literal/quoted token bytes as a span, scans quote and escape state in HIA, and copies that span with the existing buffer.copy_range primitive. Indentation uses the existing buffer.fill_range primitive after a complete range check. Neither opcode, the language, nor a compiler/caller limit was changed.

The same 31 fixed development cases pass. A separate 64 KiB valid string and 1024-element array also pass against exact expected bytes and source/output/workspace guards. The depth fixture now records 496462 interpreted IR operations with the same 33282 output bytes and SHA. Bulk IR operations count as one instruction in this development interpreter while their actual machine implementation still processes bytes. This is evidence of reduced repeated IR control, not a measured native speedup.

The source remains an admitted-compact-JSON layout component, not a general JSON parser, foreign-object encoder, key sorter or public CLI replacement. It retains string/number spellings and incoming key order, two-space indentation, no trailing newline, the original 8 MiB incoming wire ceiling and the existing status classes. Valid callers provide private disjoint buffers and keep input unchanged. Nonzero status invalidates every output byte and the output length; the earlier failure-output contract remains applicable.

The seven functions, 80 blocks, 293 operations, maximum 488 unique SSA names and eight parameters/edge arguments are inside every original compiler limit. A first mechanical draft was rejected by the development validator because one close-pop edge omitted the new span-start value. Its source and exact rejection are retained. The correction passes the original start value and was then validated and exercised. No public Core parser or native compiler has run on either r3 draft.

Next actual validation must independently assemble/verify the source, build a fresh source-bound development image, run all old 31 IDs and added boundary/scale cases under the unchanged five-second new native-child deadline and outer180/cleanup3, and inspect complete raw results. A valid string exactly at 8 MiB, nonzero workspace and success followed by refusal must be included. Failure is retained as failure, without enlarging a deadline. Original CLI, installation, full retained and cold gates remain separate.
