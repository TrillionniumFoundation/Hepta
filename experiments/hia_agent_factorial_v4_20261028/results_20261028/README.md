# Agent 效率实验 v4：基线未达标，主对照未启动

**这次完成了基线校准与实验框架检查，没有完成 HIA / Rust 开发效率比较。**
两款固定模型都未通过原定的“三题、首次回复全部正确”门槛。遵照用户要求，
16 格主对照保持 **0 次请求、0 格尝试**，没有将未尝试的格子算作失败，
也没有通过降低门槛、重试或人工修复来改变结果。

## 实际观察

| 独立 Rust 校准任务 | Qwen2.5-Coder 1.5B Q4_K_M | Qwen2.5-Coder 7B Q4_K_M |
| --- | --- | --- |
| 两文件算术修改 | 实际 Rust 编译拒绝 `u64 + u32`，provider 算术也未修正 | 固定 240 秒请求超时，没有完整回复 |
| 两文件 API / 宽度升级 | 调用方将参数转为 `u64`，与新 `u32` 参数不匹配 | provider 直接返回 `u32` 乘积，与 `u64` 返回类型不匹配 |
| 返回 owner 修复 | 仍读取已经 move 的 `Vec`，Rust 编译拒绝 | 编译及原生执行完成，结果 16 / 73，预期 17 / 74 |
| 原始资格门槛 | **0 / 3，不合格** | **0 / 3，不合格** |

最后一项不能归因于评分歧义。实际提示明确要求把 `x + 1 modulo 256`
写入第一个字节，并给出 17 / 74 的公开示例。7B 修好了返回 owner 的使用，
但仍保留 `buf[0] = x`。该响应的资源合同通过，功能结果错误；隐藏验证没有
被触发。其余三个任务提示也明确了参数宽度、数学算术和单次 provider 调用。
这项阅读核对不证明提示最优，也不能推出模型在其他预算或工作流下无法编程。

两轮终局记录均为 `valid_observation=true`，运行期间源码、工具和模型身份
未变；所有由实验创建的模型进程均有退出记录。超时后只为下一个独立任务
启动了新进程，没有重新尝试超时题。主实验此前没有启动。
