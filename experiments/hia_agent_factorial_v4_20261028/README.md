# Four-file owner-maintenance factorial study, v4

This prospective study preserves every earlier experiment and its failures. It
separates the language factor (HIA/Rust) from the context interface factor
(full/query), with identical editing authority within each language. Both
interfaces replace the same two complete function definitions. No finite menu
of correct/incorrect repairs is supplied. Two unchanged files remain part of
the actual compilation and whole-program checks.

The four new finite tasks cover saturating arithmetic maintenance, a provider
width/API upgrade, a returned owned byte buffer, and replacement of one of two
live owners. These are purpose-built four-file projects, not a production
repository corpus. HIA source files compose into one Core module; this does not
qualify independent HIA object-module linking. Query/full changes a presentation
bundle, so small-sample contrasts cannot establish a population causal effect.

`PROTOCOL.json` fixes model order, independent capability calibration, task
names, limits, resource checks, feedback, hidden-test handling and the descriptive
gate before inference. Qwen 1.5B is tried first; only the declared calibration
failure permits selecting the pinned 7B model. Main tasks and prompts do not
change after calibration. The selected model is explicitly not an unbiased
sample of model families. If both models fail calibration, the larger model's
main cohort remains capability-unqualified and cannot establish an advantage.

Only actual requests to the owned offline llama.cpp process count as model
attempts. Reference implementations and hostile variants qualify the evaluator;
they never count as agent answers. Native binaries, complete raw responses,
compiler diagnostics, resource traces, timeouts and source/model/tool identities
are retained, including unsuccessful observations.

Native runs use a finite admitted language profile, sealed executable bytes and
CPU/address-space/wall limits. This is not a general OS sandbox. HIA's native
values and allocator observations are separate from its same-Core VM's actual
loan/owner observations. Rust uses its real compiler and a trusted allocator and
provider-observation harness. These observations do not prove the backend,
loader, libc, OS or hardware.

The aggregate report includes every attempted cell and costs of unsuccessful
model selection. Missing timeout usage stays unknown. Hidden cases run once,
after the first public pass, and are never supplied in feedback. There is one
automatic public-feedback repair, no hand repair, no best-of rerun, and no
reinterpretation of historical failures.

No main model result is supplied by this protocol file. A result must bind a
clean, committed integrated source tree and its unchanged implementation bytes.
# Baseline qualification is a prerequisite

`PROTOCOL_AMENDMENT.json` prospectively supersedes the original protocol's
permission to run an unqualified main cohort. It implements the user's explicit
condition: a model must first pass the original independent baseline checks.
The main entrypoint refuses before creating its output directory or sending
requests if neither model qualifies. The original protocol, observed failures,
3/3 first-response gate, models, prompts and budgets remain unchanged. Stopping
at calibration is incomplete qualification and cannot demonstrate HIA advantage.
