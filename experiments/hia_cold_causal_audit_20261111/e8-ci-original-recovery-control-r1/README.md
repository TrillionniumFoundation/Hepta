# Exact e8 CI originals: unexecuted custody controller

This is a new, create-only archival operation. It does not rerun either CI job, execute project code, import project modules, construct a compiler, or change any product deadline. Both original CI failures remain failures. The PR artifact is bound to its actual synthetic merge checkout, separately from the push checkout.

The six frozen controller files and exact external artifact pins are in CODE-FREEZE.json. REQUEST.template.json and LAUNCH.template.json deliberately contain no signed URLs and are not launchable. A later unique invocation will use freshly returned official artifact download URLs in its private stdin. URL bytes and the complete private request remain only in the private task root; public evidence records their digests and endpoint hostname. The two GitHub artifact metadata files are serializations of the original SDK objects, not original HTTP response bytes; they contain no signed transport URL.

The unchanged guardian owns the one download/inspection child under a 900-second custody deadline and the original three-second cleanup. The h request permits 960 seconds. Each artifact receives exactly one HTTPS GET with no redirect, retry, ambient proxy, or encoded body. Both original ZIPs must match their externally provided size and SHA256 during transfer, then pass two independent full-file reads around selection. Partial and failed outputs remain in the new root.

All central-directory entries are checked for canonical relative paths, duplicate names, file/parent conflicts, type and mode constraints, encryption, compression, and finite expansion bounds. Only the fixed 147 JSON members per artifact are decompressed and copied byte-for-byte. Each selected file is independently read back; its original CRC and SHA256 are retained. The complete central-directory metadata and selected originals are packaged into a new archive whose every member is independently reread. Unselected original member payloads and nested phase archives are **not** independently replayed. Hashing a complete original ZIP does not establish semantic correctness of every contained binary.

The final verifier requires the actual guardian configuration and complete input identities, original child-log hashes, a natural zero return, no kill/overflow/interruption/error event, leader reaping, kernel ECHILD, and no remaining direct children. The driver intentionally reports only a pending-guardian custody status. Final acceptance is archival evidence, never product qualification.
