# Matching-cold UNPACK gates — independent integration draft

This directory contains proposed source files, not a tested product checkout.
The frozen product `006accd3d73d48b9ef39c821be55a5346cd48ce0`, development
capsule A `418062f8d4771e09e4f5acd8e6ecd05ff4612fd6`, and workflow B
`7207a911aa9c7f6f218f70d145b3c87ec5d54e91` remain unchanged. Their actual
development run is independent. Neither its eventual result nor earlier
development results can satisfy this new reader.

## Concrete proposed behavior

The exact old thirty mandatory gates remain a prefix. Two new gates are added:
`core_unpack_complete_composition` and `core_unpack_selected_complete_callers`.
Both are granted only by the same conjunction:

1. The current strict cold report, its actual nested report and actual final B3
   image pass the existing `admit_cold_build` path. All new reader, adapter,
   finite-control, transaction, test and ledger sources belong to that closure.
2. The unchanged complete Core qualifier executes all 15 + 51 + 50 methods,
   once and unsplit, with the old complete Python UNPACK policy poisoned. Its
   own caller and component Core39 builds, ABI, unit images, real returned-step
   matrix, both lazy yields, private globals fixture and installed wheel remain
   subject to the original Core reader. The UNPACK builder uses the same B3 and
   source closure. Its manifest, image, ABI, bridge, selector and all six actual
   compiler originals are independently read.
3. A second process owner executes the exact four shim controls, six finite
   native controls, and the complete ordinary eight (two source and six native).
   The two retained finite source files are copied byte-for-byte; their
   `__main__` IDs, inner experimental schema and false cold flag are preserved.
   The new outer reader binds their actual invocation, complete input hashes,
   report and stdout/stderr to the current cold companion image. It does not
   relabel their inner metadata or inherit a historical PASS.
4. The additional eighteen reuse this operation's fresh matching-cold caller
   Core39 and UNPACK images. This is explicit reuse of checked current artifacts,
   not another claimed compiler execution. Before/after bindings include all
   Core unit manifests/images, the bundle/build/ABI, and the UNPACK six compiler
   originals. The complete116 producer and owner originals must stay unchanged.
5. Both original product owners must naturally finish under 180 seconds plus
   three seconds cleanup: exact command/request, actual raw owner JSON, wrapper
   projection and SHA, no timeout or kill, no errors/remaining children, and
   ECHILD/reaped closure. Their actual interpreter is pinned to CPython 3.14.4.
   Only after both are read back may either new mandatory gate be true.

The preliminary `owned-callers` admission deliberately grants zero gates. It
cannot qualify a complete run by itself. The second CI command re-reads both
operations and all their mandatory product evidence.

## Files and integration points

`inputs/tools/hia_core_unpack_gates.py` is the independent reader. Its counters
distinguish outer attempts, normal returns, legitimate exceptions, and actual
native step returns. Exception-producing rejection methods are not required to
return normally. Actual UNPACK continuation/completion steps are required in
each of the three original Core groups.

`inputs/tools/qualify_hia_core_unpack_ci.py` supplies the two original 180/3
owners, an internal composition child and independent readback. No development
manifest argument exists. The original Core116 producer remains unmodified.

The proposed `hia_compiler_owner_gates.py` change adds an explicit optional
installed companion argument at two reader interfaces. With the default `None`,
the old thirty-gate route retains its old argv and behavior. With the argument,
the companion's actual matching-cold build is admitted before the installed
child argv is accepted. The original wheel/resource/ABI/source checks remain.

The proposed workflow preserves every old step, both exact 3.14.4 pins, all 61
generators and the original cold/compile/test limits. It adds the source refusal
controls, two new owned product steps and three retained artifact paths.

The new v10 full runner preserves v9 and the old mandatory maps. It appends the
two new mandatory gates and uses the same adapter/readback. It does not wrap
two phases in a fictitious single 180-second success. The original full retained
suite keeps its 5400-second boundary, and its external guardian keeps 10800.

The ordinary composition test's existing eight IDs and bodies are unchanged.
Only its class fixture receives an additional explicit full-suite admission:
when given both current cold and the completed conjunction evidence path, it
re-reads that evidence and loads the admitted pair. This prevents six skipped
native methods in full discovery without setting a global Core selector. The
existing explicit-manifest development route remains available and never
satisfies the new cold gates.

`tools/hia_selfhost_contract.py` adds all proposed control dependencies and a
requirements section. This draft does not regenerate or claim current support
or coverage JSON. The eventual combined candidate must regenerate those files,
validate complete source identity and run the standard source controls before
matching-cold execution.

## Scope and remaining acceptance

The source-only refusal controls use inert synthetic receipts and AST checks.
They do not execute a compiler, a native entry, a shim, a wheel installation,
the eighteen product controls, Core116, cold replay or the full retained suite.
Any actual source-control result is recorded separately with its exact inputs.

Promotion still requires the real development capsule result, review of this
draft, a new combined source identity with regenerated contracts, standard CI's
current matching-cold B3 and all new eighteen/116 evidence, then the mandatory
full harness. The CPython object runtime, raw foreign primitives and C-API
transaction remain hosted. No default activation or whole-HIA delivery is
claimed. Old failures and unknown runs remain separate originals.
