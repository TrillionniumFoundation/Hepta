# Separate textual-v8 Agent compatibility cohort 20261030b

This is a new, preregistered pilot of textual primitive HIA Core v8 against the disclosed safe Rust profile. It does not replace the e223 public-tools study, the older assembly/recovery studies, or their negative results. Development references are authored controls prepared during implementation, including AI assistance; they are not observations of the model under test and not a human productivity baseline.

## Tasks and public tools

The six contracts cover unsigned Euclidean GCD, byte-window checksum, run counting, a caller-owned mutable borrow, a returned mutable borrow, and allocation/release on both conditional paths. Each has six disclosed public cases. The future terminal set has 96 cases per task from the seed in PROTOCOL.json; implementation controls use a separate development seed and 32 cases per task.

HIA answers are actual textual v8 assembly, parsed by the unchanged assembly frontend and checked by the existing Core verifier. Borrowed helpers are internal functions linked to the disclosed scalar ABI wrapper. The initial prompt includes the complete selected instruction catalog, exact textual grammar, the selected Rust API, public cases and any host wrapper. Both arms can request the same catalog/check/final RPCs.

One ephemeral app-server thread persists through a cell. The host appends only actual public feedback; it does not repeatedly rewrap the entire conversation. The model has at most six explicit turns and three public checks. A new final candidate consumes a check. An accepted digest can be submitted without recompiling it. Every public check invokes the real verifier/compiler and native executable.

Before any terminal hidden evaluation, the model process is closed and the complete retained stdout stream is audited, including events queued after turn/completed. Hidden inputs, outputs, oracle source and acceptance are never sent back to the model. A failed terminal submission cannot be retried.

## Measured boundaries

Per-turn, per-cell and whole-campaign wall budgets are 120, 300 and 3600 seconds. Public compilation, native checks, startup, terminal validation and cleanup contribute to cell wall time. The campaign additionally records its own total duration and common admission work. Raw streams, actual commands, candidate hashes, native artifacts, usage events and failures are retained.

The native candidate in either language executes through the same launcher, with a recorded RLIMIT_AS of 256 MiB, RLIMIT_CORE of zero and an eight-second execution wall limit. RLIMIT_AS bounds virtual address space; it is neither peak RSS nor a proof of full resource safety. Each receipt binds the observed limits, PID and exact executable path before exec. A real 512 MiB allocation attempt was rejected by the limit during development, with the original failure stream retained.

HIA resource cases require actual selected VM buffer.store/load, ownership and loan events, plus native result agreement. Rust uses a safe audited wrapper containing a real std::vec::Vec, with ordered mutable access/readback, helper/caller phases and release. This records the selected API. It is not a machine-store proof, whole-process allocator accounting, or backend refinement theorem.

The local CLI advertises the registered tool-disabling switches. The actual features-list control reports eleven of them disabled, while unified_exec remains enabled despite the requested disable. That failed all-disabled assertion is retained. Both arms receive identical requested restrictions, empty environments, web_search=disabled and a read-only sandbox. Existing hooks and user instructions are preserved. These settings do not prove OS isolation or absence of every MCP/internal access. Any observed direct-tool item or server-side request contaminates the whole cell and stops the campaign before hidden evaluation; absent telemetry is trusted rather than independently proven.

## Token and comparison rules

Raw provider input, cached input, cache-write input, output, reasoning output and total counters are separate. No assumption is made about reasoning/output overlap, and no conservative sum is presented as an invoice. Cumulative usage is differenced per explicit turn and must agree with provider last usage. A per-turn mismatch is terminal and ineligible for single-explicit-turn fairness. Final queued usage is also reconciled: a tail mismatch preserves its observed counters while making comparison usage unknown/ineligible; an observed token-cap breach stops the cell. Missing optional cacheWriteInputTokens remains null; required provider fields can still support a descriptive totalTokens comparison.

The descriptive HIA gate requires all twelve cells, stable identities, complete required usage, no direct-tool contamination, at least as many native successes, fewer provider total tokens, lower total cell wall and no more failed public checks. A six-task authored pilot does not establish population productivity. Provider cache, routing, weights, billing and human review time are not independently controlled or measured; the corresponding claims remain false or unknown.

## Execution sequence

1. Run development tests with an explicitly available RUSTC (or rustc on PATH). Missing native tools fail; the tests do not silently skip. Non-formal unit evaluations may pass explicit tool overrides and record them. Formal public/terminal evaluations retain the PROTOCOL tool pins.
2. Run tools/qualify_hia_agent_v8b_continuation.py controls with a fresh external output directory. It checks all twelve authored cells on public and separate development cases, plus wrong-signature and wrong-result/resource candidates.
3. Commit and remotely publish the exact implementation, then call freeze with the matching controls receipt. All bound files must already match the source commit.
4. Obtain an independent exact-freeze review and remotely publish the FREEZE and review registration.
5. Only then invoke run with a new output directory, the published review path and registration commit. No model call or formal future-case materialization is permitted before that point.

The current development receipts are not formal model results. Failures, unknowns and negative comparisons are preserved. The protocol does not permit a fallback model, transport, altered hidden seed, enlarged budget or rerun selected for a better result.
