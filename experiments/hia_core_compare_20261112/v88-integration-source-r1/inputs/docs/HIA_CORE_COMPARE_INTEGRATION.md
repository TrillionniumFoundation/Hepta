# Explicit numeric comparison integration candidate

This candidate attaches the already authored `HIACMP01` numeric comparison
owner to the current Core source closure. It does not activate the selector by
default. The prior finite comparison experiment remains evidence for its exact
source, interpreter and compiler inputs; it is not a qualification of this new
resource, installed-child or complete-caller integration.

## Preserved algorithm and ordinary boundary

The HIA relation and six predicates, comparison ABI, 256/128/512-byte buffers
and 32-limb windows remain unchanged. All 39 Core HIA
sources and the original Core ABI remain unchanged. The outer opcode-13 target
is bound before the original left and right handle reads, each once. Only an
unchanged original builtin target with two exact `bool`, `int` or `float`
operands enters the companion. Subclasses, foreign objects, replaced targets
and containment operators keep the retained dispatch.

There is no eight-MiB integer cap. The host still owns object allocation,
bit-length/sign transport, lazy whole-magnitude byte allocation, float bit
packing, reference counts and exceptions. Native fixed windows do not imply
constant memory use in that host bridge. The nineteen hosted primitive
families and the complete CPython object runtime are not declared closed.

## Source and package integration

The native resource tuple grows from 92 to 94 by adding only
`hepta/hia_core_compare_abi.json` and
`examples/hia_bootstrap/core_compare.hiaasm`. The installed resource test treats
the ABI as metadata and resolves the HIA through
`hepta.hia_core_compare_selection.SOURCES['control']`. The original Core40
resource inventory, UNPACK companion and other resource mappings remain.

The standard generator sequence preserves its original 61-item prefix and
appends `core_compare`. No-argument generation writes the canonical HIA source;
an explicit `--output` continues to use exclusive creation. The authoring
`SOURCE`, `source()` and `document()` algorithms are unchanged. Standard CI
continues to pin Python 3.14.4.

All eleven original source/Core-VM methods keep their IDs and method bodies.
When their two optional fixture environment variables are absent, the base is
the current source root and a new private temporary evidence directory is
retained. An explicit evidence path retains its create-only behavior. The
original source test, generator and Core installed-test inputs are retained as
separate source fixtures for same-interpreter AST comparisons.

The bridge has one independent lifecycle correction. A permanent closed bit
and epoch prevent an active call from restoring result or packet permission
after a callback catches an invalid reentry. Entry binding, native return,
accounting, limb representation and packet construction are checked before
advancing the continuation. A raised leaf exception is rethrown unchanged;
when a leaf catches the invalid reentry and returns normally, the closed outer
call fails. Normal DONE still grants exactly one finish, which then closes the
session permanently. The prior finite r3 result belongs to the retained older
bridge and is not attributed to this revision.

Nine additional integration controls check the package, argument protocol,
independent readers and retained denominators. Six additional lifecycle
controls use only synthetic Python reply fixtures, including caught reentry
after the entry, both ledgers, representation leaves and transport. They do not
load a native image. The original eleven source/Core-VM method bodies remain
unchanged and independent of these fifteen new controls.

## Explicit installed companion protocol

The installed child keeps its original Core-only argument form and its one
positional UNPACK manifest form. Both original UNPACK observation blocks now
test the parsed UNPACK field. Numeric qualification instead supplies
`--companions-json` with the exact schema
`hepta.hia.core-lowering-installed-companions.v1` and both absolute manifest
paths. Extra fields, missing companions, duplicate JSON keys and ambiguous
argument forms are rejected.

The installed method remains one of the original fifteen methods; the full
Core denominator stays 15 + 51 + 50. It still builds and installs a real wheel,
uses `-I -S -B` with an empty PATH, checks every installed Python/resource byte,
forbids the retained Function/Emitter owners, and executes the original UNPACK
checks. In dual mode it additionally records actual numeric step returns and
forbids the already-bound builtin comparison target during eligible effects.
A separately labeled installed window probe forces a real continuation. Warm
changed/missing ABI and HIA resources must refuse, and the original resource
bytes and admitted identity must be restored.

The build reader validates the same current cold compiler, all four numeric
source inputs, actual image, build manifest and all six original compiler
files, including the entire one-MiB output. The existing Core reader only
accepts a numeric installed argument when this explicit current-cold build is
provided. The original thirty-two mandatory gate keys are unchanged.

## Complete-caller observer and remaining execution

`qualify_hia_core_compare_callers.py` is an explicit new producer. It admits a
new matching-cold numeric build before setting the numeric selector, then
calls the original UNPACK wrapper once. That wrapper still calls the original
default full Core116 main once. Development mode requires all three manifests
and keeps a distinct scope; it cannot be accepted as matching-cold evidence.

The observer records attempts, exact-domain eligibility, returned dispatches,
exceptions and actual numeric step returns separately. Original independent
Core-VM effects remain in their source-test denominator and are explicitly
excluded from native evidence. Complete suite identities delimit groups;
class/module fixture effects have a separate `@fixture:` label and never count
as a passed method. No primitive performs diagnostic file I/O. Instrumentation
cost remains inside the original caller deadline.

No new mandatory gate is granted by this producer or this source declaration.
A later frozen request must execute all original eighteen UNPACK controls and
the complete original116 under their unchanged separate 180/3 owners, the
complete numeric finite8, and the actual dual-companion installed path. Its
reader must join all results to the same current cold B3, both actual Core39
bundles, the UNPACK image and the numeric image. The original thirty-two keys,
three/five-second application limits, compile 20/10/one-MiB limits and full
qualification limits remain requirements. Any failed or missing result keeps
the combined numeric qualification open.

Source generation, source controls, current-cold builds, full native callers
and installed execution must each have their own actual records. This document
does not claim any of those future candidate results.
