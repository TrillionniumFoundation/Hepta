# Read-only Actions supply of the original acffa ELF failure reports

This controller is a new archive operation. It does not rerun either original CI workflow, compile any HIA source, or execute product code. The two original artifacts are each larger than the connector's 512 MiB limit; the original tool refusals are held by root. The fixed external sizes and SHA256 values, actual push/PR identities, 780-source map, and seventeen requested raw paths are copied unchanged from the reviewed `8501` receiver.

`original_receiver.py` is the complete unchanged `8501` source. Its 15,103-byte shared helper span remains verbatim. The new worker reroutes only that evidence module's destination `ROOT`; it calls the original ZIP directory, member retention, archive readback, and header-observation functions. Its OAI transport function is not called. A separate official GitHub API path obtains one authenticated metadata response and one authenticated 302 for each fixed artifact; a new anonymous client immediately downloads the signed location once. The token is sent only to `api.github.com`. No redirect is automatically followed and no retry is made. Signed locations remain memory-only.

The workflow has only `contents: read` and `actions: read`, is gated to one exact `create` branch and attempt 1, and leaves the three original workflows byte-identical. Control A is checked out by exact SHA without persisted credentials. Control B adds only the new workflow and binds A. Root must review both before creating the trigger ref. All commits use `[skip ci]`; no trigger ref is created by this implementation task.

Preparation runs without the read token, records the actual fixed Python 3.14.4 executable, verifies all control/source hashes and the detached A checkout, and creates a new private runner root. The collection step alone receives the read token and execs the unchanged external guardian with 900 seconds and 3 seconds cleanup. The original cold, compiler, full-regression and workload gates are not executed or changed. The default interpreter is control infrastructure, not a new product qualification.

A separate token-free finalizer first requires a complete ECHILD boundary before reading possible child output. A natural successful guardian and source-bound worker are required for custody READY. Closed but failed or killed execution may still have its available original bytes retained, while final status remains HOLD. Missing optional requested members are listed; required cold/gate records must exist. No missing report or product result is synthesized.

The final upload directory has a fixed allowlist. It includes metadata, original owner/worker logs, and the two small `selected-originals.zip` archives that already contain all present requested raw reports plus their complete safe directory/selection records. The original approximately 600 MB ZIP files remain only in ephemeral runner custody and are **not** uploaded. The final payload is hard-limited to 480 MiB and at most 65 short filenames, leaving more than 32 MiB below the connector limit for the outer artifact ZIP framing. If selected originals exceed that bound, the controller holds instead of silently dropping members.

No Python parse, transport, or artifact inspection is claimed by this static checkpoint. Runtime reports must preserve any failure and the precise actual event/control source identity. The original acffa ELF-caller failure and the unexecuted full-v9 blueprint are separate.

Primary references: [GitHub artifact API](https://docs.github.com/en/rest/actions/artifacts#download-an-artifact), [create event](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#create), and [GITHUB_TOKEN permissions](https://docs.github.com/en/actions/tutorials/authenticate-with-github_token).
