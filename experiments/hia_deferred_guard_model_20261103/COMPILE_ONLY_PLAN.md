# Deferred-guard compile-only experiment: review plan

Status: proposed, not run or wired into CI. This plan follows experimental
checker commit 0fffc195. Its independent review found 57 passing tests, 242
well-typed wrong edge operands rejected (one further operand rejected by Core),
and 256 additional matching finite VM/resource traces. None proves general
resource semantics, quota equivalence or native refinement. The known 20 versus
17 VM-step counterexample remains a permanent negative control.

## Question and stopping rule

Does generic sharing of the identical pre-divergence Core region change the
actual x86-64 entry/empty-path layout for these two sources and this compiler?
Preserve unchanged, worse, larger and failed results alongside any changed
layout. Stop after the frozen two-workload, two-arm compile-only campaign.
No target execution, benchmark, speedup inference, runtime admission, production
integration or performance threshold change is authorized by this experiment.
A changed object alone does not justify timing or claim an improvement.

## Frozen inputs and construction

- Exact clean CI HEAD, tree and all working-source hashes before/after the run.
- Only the existing linear and affine release `.hepta` fixtures. The registration
  explicitly records their contents' hashes and the reduction guard maximum
  generated by the existing production proposal, rather than the maximum=4
  used to exercise both branches in VM tests.
- Two arms: the freshly proved entry-selected reduction reference and the
  untrusted deferred-guard proposal accepted structurally by the independent
  experimental checker. Neither is labelled a production-admitted candidate.
- Freeze the complete proposal through the bounded exact-built-in decoder.
  Run the independent checker on that detached proposal; reject `unknown`,
  `rejected`, mismatched source/candidate/reference hashes, or changed checker
  identity. A previous checker report is never accepted as input authority.
- Reconstruct the reference and reverify candidate primitive Core from that
  same frozen object. Compare all identities with the fresh checker report.
  Emit each through the existing `emit_program_llvm`, binding the returned
  Core/LLVM/source identity and exports. Never feed externally supplied IR.
- Complete these checks for BOTH workloads before invoking any compiler,
  including its version command. The experimental checked status is a local
  precondition for this bounded diagnostic, not an admission token.

## Compiler and command envelope

Use the repository's existing signed LLVM 20 installation profile on hosted
Ubuntu 24.04, Python 3.12 and `z3-solver==4.15.4.0`. Verify the LLVM key fingerprint
6084F3CF814B57C1CF12EFD515CF4D18AF4F7421. No local installation is proposed.
Record Clang's full version, binary hash and the hashes/versions of objdump,
objcopy and nm. This is identity evidence, not a locked shared-library or apt
closure; LLVM 20 package patch versions can change between runs.

Each workload/arm compiles once to a relocatable object with the same explicit
`--target=x86_64-unknown-linux-gnu -x ir -O3 -fPIC -c` settings and once with
before/after shrink-wrap MIR tracing. Each trace object must be byte-identical
to its OWN untraced arm. Candidate-versus-reference equality is an observation,
never a success requirement. Extract `.text`, relocation-bearing disassembly
and symbol sizes for each untraced object. Keep full bounded command stdout and
stderr and the trace MIR. Do not link a shared library or executable; do not use
ctypes, dlopen, a native harness or production compile/admission APIs.

This is exactly 8 compile invocations and 24 native-tool subprocess commands on the
successful path: 4 version commands plus two workloads each with two sets of
compile/objcopy/objdump/nm and two trace compiles. Enforce the count at the
executor boundary, not just in metadata. No retries or exploratory flag arms.
Each command has a 60-second timeout and bounded output (16 MB each stream);
the complete runner has a 300-second external timeout; the job has a 15-minute
limit. Git provenance queries, CI setup and test subprocesses are separate from these
24 native-tool commands and must be clearly distinguished.

## Evidence and failure states

Create a new directory outside the source checkout; never reuse an existing
output. Write registration before any native tool invocation, binding all
`hepta/*.py`, the proposer, checker, model dependency, runner, workflow, focused
tests and fixtures. Save frozen proposals, checker reports, canonical Core,
LLVM and LLVM identity metadata for both arms. The checker implementation hash
must match immediately before and after preparation and after all compilation.

Write RESULT initially as `running`; checkpoint after each attempted command.
Final inventory includes hashes of registration and every safely readable,
allowlisted ordinary artifact except RESULT itself. Unsafe trees fail without
following links; they do not yield a purported complete inventory. Final source/tool/hash mismatch, wrong trace bytes,
compiler rejection, timeout, unexpected exception or missing output yields
`failed`. Record incomplete output as incomplete, never reconstruct success.
SIGKILL, SIGTERM or host loss may leave `running` or absent final files: an
external reader must treat any non-completed/missing receipt as inconclusive.
Do not promise finalization after every possible process failure.

Every registration/result/summary retains `authority=DENY_ALL`,
`native_admission=false`, `production_admission=false`,
`performance_qualified=false`, `timing_performed=false`,
`quota_equivalence=false`. Record runner elapsed time only as execution cost,
never workload latency. Assembly observations are descriptive; do not infer
universal behavior or LLVM pass defaults merely from equal bytes.

## Required permanent tests before publishing code

- All 57 existing model/proposer/checker controls, including quota divergence.
- Two actual fixture preparations emit reproducible canonical LLVM and match
  independently checked frozen candidate/reference hashes without a compiler.
- Alter candidate after check, stale source/checker/reference hash, invalid
  fresh proof, solver unknown/missing, or malformed Core: compiler never called.
- Mock complete campaign: exactly 8 compilations/24 commands, two traces per
  workload, complete source/tool/artifact inventory, all DENY flags unchanged.
- Candidate-only and reference-only trace mismatch each fail independently.
- Candidate/reference equal bytes and different bytes both finish neutrally;
  neither produces a speedup or qualification claim.
- Compiler nonzero, timeout, incomplete capture, missing object, output limit,
  post-run source/tool mutation and command-budget overrun all fail closed,
  with available command/error/evidence retained.
- Existing/non-external output is refused. Mock production compilation,
  admission and native execution APIs to raise if accidentally invoked.
- Tests involving mock compilers are labelled orchestration tests; only the
  real Clang20 CI run can establish actual compilation/layout observations.

## CI safety and publication boundaries

Use `pull_request`, never `pull_request_target`; checkout the exact PR head,
read-only contents permissions, persist-credentials=false, no repository
secrets, no caches or deploy/publish steps. Do not run on a self-hosted runner.
Scope triggers to the experiment's files and its exact implementation inputs;
ensure relevant proposer/checker/model/core/fixture changes cannot silently
reuse an old green diagnostic. Record the checked HEAD explicitly in artifacts.
Retain only a newly constructed no-follow, allowlisted staging snapshot (or
a sanitized refusal report), never the raw tree/log paths. `safe_to_upload`
must be emitted only after staging returns successfully; interruption or write
failure emits no upload flag. Use `if: always()`, 30-day retention and no
claims that an artifact upload itself validates the run. A cancelled or missing
CI result is inconclusive. The workflow must not open a PR or upload artifacts
back into repository history.

The older #586 ZIP repository upload remains separately blocked pending user
approval. It is not part of this new experiment and must not be bundled into a
new upload or copied through another route. New workflow publication and its
artifact payload must be reviewed explicitly before execution; this design
commit neither publishes nor initiates a workflow.
