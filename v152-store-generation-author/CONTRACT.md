This prefix creates real executable HIA source for the two frozen codec authors.
It does not install an asset, replace SQLite, implement filesystem durability,
validate table row graphs, compile a Native image or activate a default route.

The complete input source remains the existing 3,210-file actual tree
`7f694b80c7ab76eb9d62402aeea4c331503ddc16` at
`/workspace/hia-cli-as-dict-generation-r1-dda7/source`.

`a8412acd5198b474000742cdf69bcbbd108dfc4e`. No alternate interpreter, dependency

## Full fresh inputs and ownership

Before and after each parent stage and each actual child invocation, the retained
readers read every one of the 3,210 source files and every one of the 2,496 runtime
files in full. Their complete pathsets, actual modes and seven identity fields
must match the fixed maps. No digest cache, closure pruning, summary substitution
or successful prior qualification is used. The two generator authorities' 16
selected source bindings are checked against the same complete source map and
state. Both full author sets and all active controls, fixed metadata and ancestor
directory identities are freshly checked. Initial and terminal full metadata
inventories are retained in the actual output scope.

The original cooperative write fence is retained with one explicit inverse:
the original compiler singleton becomes a list of every actually consumed fixed
input and prior output. This generation prefix does not consume a compiler.
Source, runtime, both author roots, the new execution author root and known
inodes are protected. Completed stage artifacts are re-read and protected in
later children, including the asset used by `--check`. The fence also rejects
child process creation. This remains a cooperative fence, not a hostile-code
sandbox. No public reader, loader or production filesystem contract is altered.

The parent and each supervisor receive the same explicit runtime-bound child
environment. The retained `runtime_child_environment` receives a base without
`LD_LIBRARY_PATH`/`LD_PRELOAD`, then supplies the exact restored library directory.
Ambient runtime search settings do not become authority.

## Actual output and failure evidence

Each actual stage preserves its fixed request and command, complete raw stdout
and stderr, all original owner request/event/receipt files, returned receipt,
child result, stage result and every produced output or partial output. Warnings
are kept. The parent checks the receipt's request hash, actual argv/cwd/env,
original implementation identity, 180+3 limits, exit-before-deadline, cleanup,
reaping and ECHILD. A failed generator, failed output check or incomplete cleanup
stops all remaining stages. There is no retry, rollback, truncation or cleanup of
failed evidence.

Both frozen generators already perform real Core document verification and a
whole inverse of the retained SHA authoring source. Their actual reports retain
the complete SHA edit proof. The control independently replays that proof
forward and backward over the complete strings and compares all report bytes.
This string validation is evidence checking; it neither executes the generated
HIA nor substitutes for later Native/VM controls.
