# Hosted binding and entry contract

This is an authoring contract. No hosted context has been captured, no execution plan has been rebound, and no workflow has been published. The local R2 attempt remains an actual 180-second `QUALIFICATION_TIMEOUT` with complete descendant cleanup. A successful materialization or artifact-upload job cannot change that result.

## Exact changes

`JSON-POINTER-ALLOWLIST.json` enumerates every permitted change, its original value, and the source of its future actual value. It contains 155 nonoverlapping pointers across four documents. The authoring check substituted synthetic sentinels only in memory and reversed them; all four original serialized byte strings were restored exactly. Sentinels are not runtime values, and no synthetic plan was written for execution.

| Document | Pointers | Permitted change |
|---|---:|---|
| Full R2 qualification plan | 120 | Anchored scope paths; HOME, selected interpreter and exact library directory; the actual five tool identities; corresponding control identities; hashes of the three rebound JSON dependencies. |
| Imported generation plan | 6 | The same interpreter/library paths and full identities, HOME, and library directory. Its historical generation request remains untouched and is never executed. |
| Imported C0 storage plan | 17 | Locations of the unchanged historical custody report and two transfer records; two actual original ZIP paths; their six observed stat fields. Its C0 request is never executed. |
| Projection proof | 12 | The original-module and projected-module paths for six existing reversible projections. Every function text, hash, inverse replacement, and assertion remains unchanged. |

The scope-root rule is an anchored replacement of an entire path prefix, with each suffix listed explicitly. It is not a global replacement inside strings, Python text, or historical evidence. The `/argv/2`, `/argv/5`, and `/argv/9` assignments are separate explicit entries because they contain environment assignments or an interpreter path outside the original scope.

The full plan binds the newly serialized identities of the generation plan, storage plan, and projection proof. These three documents must be finalized first. Their dependency identities may not be guessed from a template or copied from the old machine. All other original control identities remain exact, except the explicitly captured host-tool identities. Runtime identities in both plans must be identical.

## Required preparation records, in order

1. **Inputs received.** Preserve the original four JSON files and all fixed transport material before changing a copied document. Verify raw byte count, SHA256, Git blob identity, and POSIX mode against `MATERIALS.json`. The original 10 execution Python files remain byte-identical. The source preparation script is a separate, reviewable harness; it does not import product modules or invoke generators, references, compilers, or tests.

2. **Actual baseline and target.** Retrieve the published base commit `26fd6c4c1a71dc970ae11b00c8a9ff74c5c8508d` and verify its full 3,177-file byte/mode manifest. Build a new ordinary-file source directory and apply only the 22 listed actions. Verify every target file and the exact 3,180-file tree `4c62be4ed66ff107fa6f88c6131313a354868bd9`. Preserve before/after manifests and the actual checkout commit/tree. The two R20-only paths are absent only in this reconstructed older R2 input; no existing checkout or current union is edited.

3. **Completed artifact storage.** Obtain the two immutable original R20 outer ZIPs by their exact artifact IDs. Save the actual API source, transfer request metadata without credentials, response size, and download completion/failure. Reject redirects outside the explicitly approved provider transfer, length mismatch, truncation, and full SHA mismatch. Stream every ZIP member to verify CRC, retaining the member metadata and actual readback outcome. Keep the exact historical REPORT and TRANSFER files unchanged. Save a separate new hosted transfer/CRC report. A repacked or logically equivalent archive is rejected. After complete verification, capture the actual six stat fields used by the unchanged storage guard. A missing archive or failed verification stops before product entry.

4. **Actual interpreter context.** Select the actual absolute CPython 3.14.4 command supplied by the hosted setup, then query that command with `-I -S -B`. Its observed `sys.executable` must equal the selected command and must satisfy the existing regular-file identity reader. Preserve that command, including a venv command when one is selected; do not silently replace it with another interpreter after capture. Record `sys.version`, platform/architecture, relevant `sysconfig` library declarations, and complete `/proc/self/maps`. Require exactly one nondeleted, absolute, regular libpython3.14 object and cross-check its basename against the declared library. Capture named/opened/post-read identity, exact bytes, length, SHA256, Git blob, and mode for both executable and library. If the selected setup path cannot satisfy the unchanged reader, preparation fails; no hidden shim, copied local interpreter, or ambient loader fallback is introduced.

5. **Actual toolchain context.** Resolve `as`, `cc`, `ld`, `objdump`, and `readelf` with exactly the unchanged product PATH `/usr/local/bin:/usr/bin:/bin`. Record each selected path, resolved regular target, full byte/mode identity, and actual version output. Require real GNU `ld` for the original B0 build. The same `ld` identity supplies both its toolchain record and `retained:GNU_ld`; the other five control records use their matching captures. Keep the original hosted setup recipe and its actual command/output records. Installing Clang 20 does not imply that `cc` resolves to Clang; preserve the actual resolution. No local tool hash is relabeled as hosted.

6. **Actual document binding.** Resolve each allowed pointer only from the verified records above. Require the exact original value before replacing it. Do not infer unlisted values, skip missing inputs, modify budgets, change check names/counts, alter the source tree, edit the reference/phase order, or replace executable bytes. Serialize each document in the original JSON format. Compare the actual structural differences to the allowlist; inverse every allowed replacement and require complete original-byte equality. Then write the three dependency JSON files, full-read them, compute their identities, and bind the full plan last. Save all original and bound documents plus an exact pointer-by-pointer before/after receipt. Bind the observed ZIP stat tuple, not a placeholder tuple. Fixed size and regular-file requirements still apply.

7. **Immediate pre-entry guard.** Recheck all material, executable, library, tool, and ZIP identities against the same captured records. The unchanged runner keeps its existing complete-source and projection preflight in their original positions. Its 33 retained-callable checks still run inside the owned child; they are not moved out to buy more qualification time. Require the original 3 GiB instantaneous free-space floor; it is not a reservation or a proven peak. Require the new evidence directory to be absent. Freeze the final actual argv, cwd, environment, and source/runtime/toolchain context. The product environment contains only the original clean keys, with HOME equal to the new scope and LD_LIBRARY_PATH equal to the single captured library parent. It contains no credentials, ambient LD search list, or LD_PRELOAD.

8. **One product entry.** Only after a separately reviewed and authorized workflow may the unchanged R2 runner start its one 180+3 owner. All 17 independent references and both independent observer references are freshly executed within that owner before real B0. B1/B2/B3 and M1/M2/M3, all 38 phases and all 5,052 checks remain inside it. No stored compiler image or old reference output is an input substitute. Native 20-second wall/10-second CPU/1 MiB limits, two phase workers, one archive worker, two pending archives, four unsealed phases, and all original archive limits remain exact.

9. **Terminal and always-retain behavior.** Record the real launcher exit independently of upload success. The gate step must exit with that actual status; do not use `continue-on-error`, `|| true`, or a success-valued wrapper around it. Subsequent artifact steps use `if: always()` and retain the complete actual evidence directory, unsealed phases, partial frames, request/environment/context records, owner raw/returned receipts, stdout/stderr, and preparation failures. Upload or manifest construction cannot perform missing product phases. Missing final qualification output remains missing. If the job is interrupted before cleanup can be observed, report that incompleteness explicitly instead of synthesizing an owner receipt. An outer workflow timeout only contains setup/upload; it never extends the product owner deadline.

## Transport and unpublished work

The fixed content inventory is 44 logical files / 5,769,819 bytes, including the 20 source after-images. `SOURCE-MATERIALIZATION.json` is 904,330 bytes and contains the complete target manifest; the pointer inventory is 99,428 bytes. The original ZIPs total 431,745,519 bytes and are retrieved separately from Actions. The unchanged baseline is obtained from its published Git commit. Final encoding wrappers, the separate preparation harness, workflow text, and actual context receipts will add measured transport bytes; no exact compressed-size claim is made now.

The authoring run verified the 20 after-images and the fixed small execution material. It did not repeat a full baseline or target scan, fetch Git objects, download ZIPs, or run any product. Existing references to historical generation evidence may point to a retired local restore; those fields retain their historical meaning and are not executed by this scope. Any new runtime use of such a path is a blocking preparation defect requiring a new explicit plan.

Before publication, the actual materializer, exact downloader adaptation, workflow, and complete content transport still need authoring and independent review. Actual hosted runtime/toolchain identities and ZIP availability are not yet known. Even after successful preparation this gate may still exceed 180 seconds. Its result will concern the frozen R2 3,180-file scope only; latest-union matching cold, ordinary encoding, entry-layout, R8, aggregate, portable, and whole-system gates remain separate.
