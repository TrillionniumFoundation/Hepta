Its independent terminal acceptance is not inferred from those self-reports.

## Disk metadata design

Only reader bookkeeping moves to a fresh output-local SQLite database: unique fresh-read descriptors; complete metadata path snapshots; ordered observation descriptors; unique decoded-buffer descriptors; referenced-buffer names; all per-journal AFTER metadata; journal summaries; complete raw inventory; complete Native12 predecessor rows; and all catalog candidate metadata. Stored rows contain paths, pins, seven-stat records and frame JSON references, never a cached input payload or a decoded Native/VM buffer. An original full-byte read always runs before its descriptor is stored or compared.

SQLite is used from the existing host reader's standard library. It is not imported by the product. Its page cache is fixed to 8192 KiB, mmap is disabled and temporary storage is on disk. There is no worker, thread, subprocess, remote query, product import, or source-tree write. Transactions commit every 2048 bookkeeping mutations. The database and all partial logs are retained if the new reader fails; a new attempt is not automatically started.

The original concrete fixed-size source authority maps and each one currently decoded JSON file remain in memory. Existing per-file input bounds and checks remain; this is not a universal constant-RSS promise for arbitrary future inputs. The structures growing with the total number of fresh reads, unique physical buffers, full raw evidence rows and Native catalog candidates are disk-backed. A single actual buffer is still decoded fully as required by the original exact-byte comparisons.

## Complete reader outputs

The original `STAGES.json`, `FRAMES.json`, `PARENT-FRAME-REPORTS.json`, `VM.json`, `INVENTORY.json`, `READ-INPUTS.json`, `OBSERVATION-READS.jsonl` and `RESULT.json` retain their full content. `publish` recursively streams both ordinary JSON values and disk-backed arrays/maps using the original `sort_keys=True`, two-space indentation, escaping and final newline. It counts and hashes a complete encoding pass, writes another complete encoding pass, and independently streams every written byte again through SHA256/Git and held/named seven-stat checks. No whole serialized report copy is built.

R3 additionally preserves `FULL-READS.jsonl`: one ordered descriptor for every successful original `read` call, including repeats. Its row count must equal the original `READS` counter. The completed database and full-read log are independently fully streamed and pinned after closure and bound in `RESULT.disk_bookkeeping`. These output reads are not mislabeled as original input reads. The source inputs and original product artifacts remain read-only.
