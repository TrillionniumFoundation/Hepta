# Inspect CLI witness: executable controls, authoring only

This package authors the twelve groups requested for the already frozen three-file op10 adapter. It does not execute a port, issue a token, map an image, import product modules, generate HIA, compile, run tests or run a VM during authoring. The adapter source packet remains `e0a761e27dd2dea5d5b473193fbe76926030bed8`; its three files are unchanged. None is added to the default worker resource roles.

## Actual prerequisite and source boundary

The only eligible base is the independent drive R3 under `/dev/shm/hia-inspect-drive-r3-dda7`, after its exact generation, original Source18, Native17 and VM12 have completed successfully. An old busy-R2 failure or a generation result alone cannot bind this plan. The binder reads the real complete reports, all listed evidence, original owner receipts, exact ordered test IDs and actual image bytes. It rejects every incomplete or failed prerequisite.

`bind_execution_plan.py` then makes ordinary independent byte copies of all 3188 files and appends exactly the three frozen adapter files, producing 3191 paths. It preserves and checks every old file byte/Git mode/POSIX mode and records the complete old and new maps. It never writes the protected source, creates hardlinks to it, runs a generator, changes a registration or overwrites a historical failure. The actual copied view becomes the source root for every child. The three adapter module `__file__` values and full bytes must match this view; the old thirteen Inspect host files do not silently stand in for those three additional files.

The authoring template intentionally cannot execute. A bound plan can be produced only after the real predecessor exists, and still requires a separate explicit review/one-execution authorization. The binding request descriptors contain actual full raw pins and modes, never a wildcard or permission boolean. The future generation/source/native result paths are not guessed into an executable request.

## Real images and the issuance boundary

The future executor first runs the unchanged Source10 and Source8 IDs on the 3191-file view. It then uses the original `build_hia_cli_verified_report_bundle.build_development` for all six real companion images and the original `compile_stage`/`admit_compilation` for Inspect. This is seven original 20-second, 1-MiB compilation invocations in two owned groups. Inspect output must also match the actual R3 Native17/VM12 image byte-for-byte. No C0/u32 compiler, stub owner, synthetic cold receipt or precomputed fake result is substituted.

Each test child performs the following actual setup:

1. Load the real six-image report bundle with `strict=True`, and perform original complete Inspect admission with the explicit absolute manifest.
2. For all seven owners, check that the raw entry is a real ctypes native function, its address is the actual mapped image base, and that every mapped image byte matches the manifest-backed file and digest.
3. Install the unchanged original `inspect_exec_support.FrameJournal` on every owner. A fixed post-return fault gate wraps the Inspect journal before issuance. Disarmed, it calls the journal once and returns the original machine return unchanged.
4. Invoke the real issuer. It must perform its complete admission again, obtain the same cached owner, and capture the exact fixed entry and mapping now present. `state.current()` must pass unchanged. No entry substitution is made after issuance to manufacture positive evidence.
5. Select the real `NativeInspectReportCli` and require the exact same six companion owners. The positive group executes `selected.run` through actual parser, discovery routing, op35, op10 and Inspect. It requires real Inspect entries and zero calls of the original Python inspect/signature bodies.

The initial mapping/admission metadata calls occur before the control journal and are expressly not represented as fully observed control calls. The control window begins after installation of the original journals, before token issuance. Every subsequent actual machine call records its full source/output/workspace before and after, including the native return which a fault gate later withholds. Every stored frame is losslessly decoded and length/hash/Git checked before the child can pass. Missing after observations, observer I/O failures, crashes and owner timeouts remain failures; no frame is synthesized from a receipt.

The compile stages retain their original actual source/request/output/receipt/stdout/stderr evidence. Their default receipt is not advertised as a complete compile-workspace capture. The seven owners' control-window frames are complete F/O/W observations.

## Sequence, evidence and failure stop

The fixed order is Source10, Source8, six-image build, Inspect build, the twelve named groups, retained3, CLI43: eighteen owned stages, 76 test starts (the retained3 overlap with CLI43 is intentional). Every owner uses the original 180-second limit and 3-second cleanup. Every compile keeps the original 20-second/1-MiB rules. No new VM limit or Native17/VM12 relaxation is introduced. The runtime/context helper and `supervisor_env` use the same actual pinned 3.14.4 interpreter/library environment. Ambient loader overrides are not passed through.

The binder must leave the existing 1-GiB free-space floor after its source copy; the executor rechecks the same 1-GiB floor before entry and each stage. These checks are storage preconditions, not performance qualifications. Before and after each stage, all 3191 source bytes and modes, all execution controls, the ordinary compiler and actual runtime are freshly checked. Original owner raw/returned receipts, child request/env, stdout/stderr, test events/subtests, frames and failures stay in the exclusive attempt. A failed child, incomplete cleanup, changed source/runtime/control, absent frame or storage refusal prevents the next owner. No automatic retry or selective rerun exists.
