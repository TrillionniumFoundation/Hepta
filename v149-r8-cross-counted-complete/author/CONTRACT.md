# Original R8 cross-target Counted diagnostic — authoring R1

This package is **AUTHORED_NOT_EXECUTED**. It schedules one diagnostic of the already observed `root-v8-cross-target-loans` fuel failure. It does not qualify R8, adopt R9, change any source, or rerun Native.

## Fixed execution

`LAUNCH.json` contains the exact parent argv, cwd, explicit environment and plan identity. Root must authorize that one launch. The output `/hia-r8-cross-counted-r1-dda7` must be absent, including symlinks. An existing output is never reused. The original 3 GiB free-space floor remains. A 64 MiB evidence estimate is planning information, not a new product budget or storage quota.

The parent uses the original frozen `tools.hia_selfhost_process_owner.run_owned`, with one child and the same explicit environment for the supervisor. The original owner remains 180 seconds plus 3 seconds cleanup. It preserves request, stdout, stderr, raw receipt and returned wrapper fields. A normal reproduction intentionally has `QUALIFICATION_FAILED`, child exit 1 and supervisor exit 1, with complete cleanup and ECHILD. The raw receipt plus the actual two wrapper fields must match exactly; a missing receipt or timeout is not converted to a successful observation.

The child creates exactly one `CountedMachine(checked, 10000000, 1048576, None, 128)` and attempts `f0` once. Source is readonly; output and workspace are mutable. The full original 107 functions, 1456 blocks and 6664 operations are assembled from actual R8 source. No generator, compiler, new Native call, subprocess VM, warmup or retry is added.

## Exact observation method

`counted_machine.py` copies the original successful edge diagnostic class **byte for byte**. Its only overrides are the original constructor and `invoke` wrapper. `_Machine.invoke`, `tick`, `operation`, reports, resource handling and all budgets remain original. The wrapper counts calls and inclusive/exclusive machine steps in `finally`, including unwound partial calls. The exclusive sum must equal the actual machine steps. The source symbol map is read from the actual same-source/image edge `INPUTS.json`; no generator is called to recreate it.

This is an instrumented diagnostic, not a timing comparison. Inclusive costs overlap. Exclusive costs partition actual charged VM steps. The original 10,000,001st attempted step raises the original steps-budget exception; that count is not an increased fuel allowance.

## Six real buffers and failure preservation

Before invocation, each of the three actual `_Owner.data` arrays is saved and read back. An incomplete before observation prevents invocation. Immediately after return or exception, each actual array is independently saved before any result comparison. Failure writing one frame does not skip attempts to preserve the other frames. Raw machine state, resource counters, original exception text, original VM report and full function counts have independent save attempts.

All six buffers are read in full for comparison. The before bytes must equal the original three preimages. The after bytes must equal the original failed partial buffers **byte for byte**, including all workspace bytes. The raw status, error type/code/message, steps and values must equal the prior failure; the original VM report must also match. The expected comparison to Native remains `[source=true, output=true, workspace=false]`, with return equality false. The full spare workspace tail is also checked.

A hard timeout or process kill may leave no after frames. Such frames are **unobserved**, never synthesized from the prior oracle. The parent preserves the incomplete receipt and failed status. No retry follows.

Even when the failure is reproduced exactly, both reports use `status: FAIL` and both processes return 1. `diagnostic_observation_complete: true` describes custody and exact reproduction only. It does not turn fuel exhaustion into a qualification PASS.
