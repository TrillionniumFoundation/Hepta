# Inspect policy development executor: authored, not executed

This kit is a separately reviewable executor and observation suite for the two
frozen `function_signature` and `inspect_program` HIA policy roots. Authoring
and standard-library AST/identity checks are its only completed actions. No
Hepta module has been imported by the authoring check; no HIA has been
generated, compiled, mapped, invoked or run through the VM by this kit.

## Future execution stages

The script has no default execution action. A reviewed caller must give
`--execute-development`, the exact kit-index SHA-256, the complete R20 base
directory and a new independent attempt path. It refuses an existing attempt,
an attempt beneath the original source/kit, or less than 1 GiB free for source,
outputs and failure evidence. This storage preflight changes no HIA budget.
Actual preparation copies bytes, never hardlinks an original, and validates
the complete original and prepared trees before a product stage starts.

1. Run the inspect generator once, run it again, then run its real `--check`.
   After the first call, precisely the three declared outputs may be new. The
   second generation and `--check` must leave the complete tree unchanged.
2. Load and execute the ten original inspect Source IDs exactly. These methods
   retain their own real generator/shape checks; they are not static test stubs.
3. Compile the inspect image once using the fixed B3 and publish its explicit
   component directory. Capture the generated source, complete host bindings,
   actual image and complete compile receipts. The new manifest is independent
   of the default worker resource inventory and optional eight-resource table.
4. Use the existing development builder to build the retained CLI control and
   formatter pair. Independently re-admit both real compile observations. This
   fixture is used only for the unchanged old tests.
5. Execute the original three IDs and original CLI 43 IDs in separate groups,
   with separate loaded/started/stopped/testsRun sets. One old ID occurs in both
   groups by design; counts are group observations, not a claim of 46 distinct
   IDs. Their old bodies, original limits and full source files stay unchanged.
6. Execute the new policy, protocol and four fault groups. Each fault group is
   a separate child containing one fixed test ID. A deliberately uncertain
   frame stays quarantined until that child exits; it is never used to allow a
   subsequent policy effect. The actual process owner must prove ECHILD before
   the next group begins.
7. Derive twelve exact VM witnesses from actual machine frames and execute the
   twelve independent Core-VM test IDs. A missing witness fails; no placeholder,
   synthetic state or previous component observation may substitute for it.

Every child is launched through the unchanged R20 `run_owned` contract with
180 seconds and 3 seconds for cleanup. The explicit supervisor environment and
child environment use the same actual interpreter/library context. They do not
inherit arbitrary ambient `LD_LIBRARY_PATH` or `LD_PRELOAD`. The actual
CPython 3.14.4 executable and loaded library must match the retained R8 input
pins. A missing/mismatching owner receipt, nonzero exit, timeout, cleanup hold,
missing ID, skip, expected failure or any test failure stops subsequent stages.
Each attempt and result filename is new. There is no automatic retry or
overwrite of earlier evidence.

## What the new Native controls observe

The policy controls compare complete ordered results and effect events with
the untouched original functions. A positive oracle must really return; a
negative oracle must raise its declared original exception type. Two copies of
an accidental fixture error cannot satisfy a comparison. Actual policy entry
counts and Python original-code profiler events distinguish native policy
execution, deliberately foreign roots and unchanged Python providers.

The controlled domains include all original verified schema families; detached
deepcopy signature fields; retained block/term/operation aliases; eager SHA and
returned-loan defaults; observed callable aliases; foreign-call keyword
omission; live code/default mutation; mutation between GLOBAL and CALL; changed
module builtin mappings; real DICT_UPDATE mapping/duplicate/nonmapping/error
semantics; overwritten-value finalization; original first provider failures
and outer exception context; and held traceback/local retirement without GC.
Successful provider calls remain actual Python calls. This is a policy owner,
not a replacement for Core verification, decoding, deepcopy or arbitrary
Python object protocols.

The protocol controls separately examine same-frame provider reentry versus
independent nested frames, cross-frame/repeated claims and reentry at the real
machine-call boundary. The frozen R1 frame has no new busy field. The last
control is an explicit possible failure boundary, not an already proved
property and not a silent runtime patch. Any resulting counterexample requires
a separately preserved successor.

The four lost-return controls call the actual machine function first, save its
complete returned buffers, and only then raise a test-owned interruption for
claim, effect ACK, terminal ACK or retirement ACK. They verify unchanged entry
and effect counts on replay attempts and real quarantine ownership. The
interruption is never modeled as a successful acknowledgement.

## Complete buffers and independent VM limits

Every actual six-argument inspect machine call is journaled. Source, output and
workspace are stored losslessly before the call and again in `finally`, with
complete size/SHA/Git identities and content-addressed zlib bytes. Each call's
BEFORE file is published before entering the machine. A crash that prevents an
AFTER capture remains an incomplete actual observation, never a fabricated
match. Journaling preserves all complete calls, including paths not chosen for
the finite VM panel.

The VM panel uses the actual generated HIA program and actual selected
source/output/workspace preimages, with distinct owners. Each invocation keeps
the original 10,000,000 steps, 8 MiB VM heap and 128-call-depth limits used by
the existing continuation controls. Actual machine buffer extents remain at
most 1 MiB each; the compiler's image/output/workspace limits remain 1 MiB.
All three buffers and return values must match exactly. A fuel/trap/assertion
failure saves that invocation's actual complete buffers in `finally`.

Twelve selected transition witnesses are proposed; the actual total number of
journaled frames is not predicted. Passing these twelve would not establish
that every actual frame, every Python object behavior or every CLI action had
been independently replayed by the VM.

## Integration and remaining boundaries

This execution kit does not edit the eight frozen product files, Root R20,
Source registries, default resource groups, the optional resource registry,
public CLI dispatch, Surface's qualifiers or Native's compiler candidate.
It does not publish a product ref, select a default native policy or grant a
cold qualification. No installed-wheel claim is made for the new inspect
component. The original CLI 43 include their own unchanged installed fixture;
that is retained CLI coverage, not new inspect installation coverage.

The current operation-10 consumer still calls its captured Python
`self.common['inspect_program']` provider. The new component can accept that
exact observed callable, but an optional CLI adapter is not wired by this kit.
Original3/CLI43 passing would therefore establish regression compatibility of
the new source, not end-to-end inspect op10 closure. A later explicit adapter,
portable component build and strict matching-current-source cold qualification
remain distinct work with their own original/refusal controls.
