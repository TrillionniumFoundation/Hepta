# HIA ELF object writer policy candidate

The exact original `_name`, `_exact_int` and `write_elf_object` function ASTs are
retained and independently pinned. Thirteen bounded `.hepta` images encode their
control, complete object layout, validation, symbol/relocation decisions and
the seven distinct original lazy projections/predicates/sort-key callbacks.

The original four-bound-argument, 18-packet-primitive, 64-instruction unit and
all source/compiler limits are unchanged. Long `struct.pack` calls are exact
argument-tuple transport, not a wider compiler-call ABI. Fixed eight-value
unpacking is an explicit object-runtime mechanism. Literal bytes, suspended
iterators, regex, sorting, Python object values and variadic calls remain hosted.
Sorting uses the original runtime's real callback scheduling, with projections
and filters entering HIA; it does not claim the incomplete earlier native sort
candidate is equivalent or that the object runtime is already pure native.

Explicit selection is source/ABI/compiler/image-bound and captured at ordinary
emission. Refusal never falls back to the retained writer. Unselected behavior
and public signatures remain unchanged. The separate 14-entry
`MACHINE_OBJECT_BUILD_FILES` role does not broaden any prior resource role.

Development generation and independent Core VM controls passed after retaining
the first test-invocation failures. Current-source cold, real native installation,
complete original callers, composed selected owners and full regression are not
yet qualified. Worker, storage, full object/runtime and bootstrap trust remain
open. No production default, service or old-stack retirement is activated here.

Development evolution: the original 12-image single-owner 111-test gate passed,
while its four-owner composition exceeded the unchanged 180-second owner and
remains failed. All 2,539 original development-source byte identities have been
replayed into a separate custody archive; this is not a frozen qualification or
reconstruction of original filesystem modes. New source lowers exact internal
helper bodies into HIA at their call sites, retaining original callee/argument
observation order and separate helper modes. No compiler cap or packet opcode
is raised. The shared hosted bridge copies an immutable literal identity index
into each fresh session and reobserves a replaced tuple; mutable session handles
or product decisions are never cached. The VM keeps a fresh machine and all
checks but reuses its already-decoded entry. The changed source needs its own
new development, cold, native and full qualification; old results are not reused.

The corrected 13-image development four-owner composition passed all112 tests
(11 component,51 original machine,50 original Core) in153.999493855s under the
unchanged180-second owner. Retained ELF, byte-wrapper, Emitter and Function
owners were forbidden in their captured scopes; all10 ELF modes had actual
native step returns, each companion returned actual HIA steps in both original
caller groups, and all source/bundles were stable. This remains explicit old
compiler development reuse, not an inherited current-source cold/full result.
