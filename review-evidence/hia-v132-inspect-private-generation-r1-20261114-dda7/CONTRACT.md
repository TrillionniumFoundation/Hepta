## Exact work and original bounds

The new stage executes the unchanged generator twice into two independent external
three-file output directories, then executes its real `--check` on the second
directory. These are three separate original 180-second + 3-second cleanup
owners, in that order. Each owner must supply full raw and returned receipts,
authoritative completion and ECHILD; any failure halts all later owners.
The 1-GiB available-space floor is preserved at entry, before each owner and
before installation. No compiler, test loader, native entry, VM, cold builder,
CLI action, or automatic follow-up stage is invoked.

The actual 3.14.4 interpreter and its mapped libpython must exactly match the
prior complete runtime capture. Parent, supervisor and child use only fixed
environments plus that captured library directory. The child runs `-I -B`.
The original fourteen-file execution kit is wholly pinned, but only its pure
support/receipt/old-B3 identity checks are reused. Old B3 is read, not executed.

## Before/after and installation

Every owner is surrounded by full reads of both source inventories: all bytes,
Git modes, actual POSIX modes and seven stat fields (device, inode, bytes, mode,
link count, mtime, ctime). The unchanged audit-hook fence permits the frozen
generator to write only its explicit external outputs, plus the child result;
it is a cooperative Python fence, not a native sandbox. Complete partial
outputs and source maps are retained on failure. There is no retry or rewrite.

Both real output sets must be byte-for-byte equal; `--check` must leave the
second set's bytes and all recorded metadata unchanged. The actual generated
assembly and ports must equal their original full bytes. The generated data
file is parsed as literal evidence and must bind the actual assembly and all
thirteen current host-source hashes, including runtime SHA
`8db7befea61305e52d08abe874ddc252d5cec0072b92e44e55be50a9c439f89d`.
No identity file is synthesized or repaired by the harness.

Only after all checks succeed are three 0644 replacement files allocated in
an external private staging directory and moved over the three private source
copies. The old target remains allocated until its replacement has a distinct
inode. No hardlink, in-place write or chmod of an old inode is used. Every
non-generated private stat and every original base stat must remain unchanged.
A partial installation failure remains FAIL and records the actual partial map;
it is never rolled back or relabelled a successful generation.

Evidence metadata has its producer's actual 0600 or 0644 mode independently
pinned. It is not incorrectly admitted through the source-only 0644 guard.
