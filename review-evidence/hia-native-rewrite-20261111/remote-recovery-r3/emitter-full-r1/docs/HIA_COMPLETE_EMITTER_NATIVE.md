# Complete native Emitter development component

## Status and identity

This is a fresh composition of eleven HIA images implementing the original
private `hepta.hia_program_native._Emitter` boundary. The submitted authors,
test carrier, adapters and CI are source drafts. They have not been run as this
submitted combination. A prior local identity smoke and separate Function and
wrapper results are historical observations only. No result is inherited.

The reference is exact commit
`0ef9541b2fc12f4b01ab5078b05d0b304cfa90f5`.
The original backend is Git blob
`1d0e0344f8300b11b5dd505cbea655170aba5be1`, 46,917 bytes,
SHA256 `bf953a8b85d1ebc6b9d7a90fbbcaa4137e40ed214c2ede2af1a13cfc01b1c07c`.
The private byte-export normalizer is
`4412810e9e6dfba82879dbb9ae19c19ce2de178c`.
The single-role builder pins every author and immutable reference file before
importing it, executes frozen module bytes, and reads the complete source/image
identities back after generation and compilation.

This component requires an actually admitted Core and an actually checked
machine plan. Test-only future-profile and structured-origin fixtures are
explicitly separate private counterexamples. The development Python capture
freezes existing objects into a Graph; it neither admits a program nor emits a
machine instruction. No claim is made for an arbitrary externally supplied
Graph, a header as authentication, full native capture of arbitrary Python
objects, source revalidation, target selection, final object inspection,
publication, installed build, or cold qualification. Those remain separate
owners.

## Roles and calling convention

All images use the six-register flat-image entry convention. R/R/W owners are
compiled through the existing HIA wrapper that borrows the second operand
read-only. Fixed mechanics temporarily protect the complete actual source
mapping and, for R/R/W, the complete second mapping. The third operand is private
writable state. Slot identity, complete capacity and range arithmetic are
checked before an entry.

| Role | Owner | Buffers |
| --- | --- | --- |
| 1 | Normalize foreign exports, initialize Code options, check emitter profile and order | R/R/W |
| 2 | Full original Function frame/slot/edge/call/result/staging plan | R/R/W |
| 3 | Full Function lowering tape | R/R/W |
| 4 | Persistent Function tape to actual Code command/ACK issuer | R/R/W |
| 5 | Scalar and borrowed-byte wrapper tape | R/R/W |
| 6 | Persistent wrapper tape to actual Code command/ACK issuer | R/R/W |
| 7 | Persistent original x64 Code encoder | R/W/W |
| 8 | Pure Code finalizer over the actual sealed Code state | R/R/W |
| 9 | Original late export/text gates and native complete ELF input construction | R/R/W |
| 10 | Complete original ELF64 ET_REL writer | R/R/W |
| 11 | Persistent complete Emitter controller | R/W/W |

Every source is generated and compiled fresh. The new module names intentionally
make these fresh source/image identities; an older image hash or successful
component test is not substituted.

## Input and authority

Initial input is a 128-byte little-endian `HIAEMB01` header followed by one
complete immutable `HIAGRF01` Graph. The Graph root is exactly
`[admittedCore, checkedPlanOrNull, originalForeignExportsObject]`.

The 16 header words are:

1. `HIAEMB01`.
2. Version 1.
3. Nonzero Emitter lease.
4. Nonzero logical request.
5. Actual Graph lease.
6. Nonzero actual Code lease to be created in this session.
7. Actual root ID.
8. Complete Graph byte extent.
9. Actual structured-origin flag, 0 or 1.
10. Seven zero reserved words.

Graph IDs, scalar offsets, dictionary order and type tags are preserved. The
producer must supply the actual immutable issued bytes for the entire session.
Matching integer lease fields alone do not prove source provenance. GROW
reuses the same immutable input and does not authorize a replacement Graph.

The foreign-export value remains unnormalized in the initial Graph. HIA owns
the exact normalization and error order: exact tuple form, count, each row,
names, extents, duplicates, structured/explicit-export restrictions, function
existence/signature and final sorted normalization. The original reference
normalizer is only an oracle in tests; its result is never supplied to HIA.

The checked machine plan remains an explicit precondition. Its complete value
and options are consumed by HIA, including function order, per-function block
order, scratch-register mapping and immediate forms. No host creates a
Function plan, lowering tape, Code packet, label/fixup inventory, symbol table,
wrapper instruction, finalized text or ELF input.

## Original execution and error order

The controller preserves this sequence:

1. Normalize the original foreign-export object.
2. Ask HIA to create the actual Code initialization packet and execute it.
3. Check the original Emitter profile in original source function order.
   Schema is first; block terminators and operations precede the collected
   type check at the original per-function point.
4. Apply the checked function order.
5. Align before each internal function; obtain the full original frame plan;
   issue its lowering tape through actual persistent Code ACKs; commit only
   its completed original symbol/frame/serial observations.
6. Align before every potential wrapper, including a skipped wrapper.
   Preserve scalar eligibility before reserved-name refusal. Borrowed wrappers
   save all argument words before the original four checks and label order.
7. After all original function and wrapper effects, check missing exports in
   sorted order, the original 1..128 resulting-export count, and 16 MiB text.
8. Seal the actual Code state, invoke the actual finalizer, build the complete
   ELF input in HIA, and invoke the actual ET_REL writer.

A semantic error does not erase the actual Code bytes, labels, fixups,
relocations, serial value or previously committed original symbols/frames.
The tests compare those complete observations even on refusal. Protocol BAD
is distinct and permanently poisons that controller state; a stale output
header is never treated as a successful new result.

The original Code and ELF leaves retain their independent partial-write and
64 MiB limits. This new corpus does not replace their previously recorded
boundary proofs. The old 39-group Function and 26-group wrapper suites and
their full per-entry raw evidence remain unchanged and are not rerun or
relabelled as whole-Emitter coverage.

## Controller slots and descriptor mechanics

The controller work slot has a fixed 1 MiB private capacity. This is sufficient
for its bounded inventory/name metadata under the original 1024-function and
identifier limits; code, tapes, input Graph and object data use separate
growing buffers. It is not a new source-program byte limit.

| Slot | Contents |
| --- | --- |
| 0 | Empty read-only view |
| 1 | Complete immutable initial header and Graph |
| 2 | Controller private state |
| 3 | Actual 128-byte controller event |
| 4 | Current peer command |
| 5 | Preparation output |
| 6 | Normalized manifest plus same-source Graph projection |
| 7 | Ordered function inventory |
| 8 | Function frame |
| 9 | Function or wrapper tape |
| 10 | Persistent issuer state |
| 11 | Actual Code byte storage |
| 12 | Actual Code registry/state |
| 13 | Actual finalizer result |
| 14 | Late finish / ELF bridge workspace |
| 15 | Actual complete ELF result |
| 16 | Complete copied Emitter registry |
| 17 | Complete semantic error text |
| 18 | Complete successful result descriptor |

Only fixed `HIACDE01` operations 1 CALL, 2 GROW, 3 ZERO, 4 COPY,
5 RELEASE, 6 PROTECT and 14 VIEW are executed. Operation 7 is terminal.
The actual `HIACDA01` ACK is eight words followed by the requested observed
bytes:

`[magic, lease, sequence, operation, 0, actualEntryReturn, observedBytes, 0]`.

A CALL carries the complete role, three actual slot views and an observed
view. The carrier checks all ranges before the call, rejects operand aliases,
requires writable operands outside controller state, restores original
permissions, and copies the actual observed bytes only after the actual
entry. It never parses Graph semantics or Code/ELF payloads. Every actual
operand has inaccessible guard pages and exact 16-byte canaries.

GROW creates a zeroed mapping, copies every old logical byte, then releases
the previous mapping. All HIA references are offsets. No source pointer is
retained across GROW. There is no new language-wide call quota; the standalone
test process remains under the original CPU, wall and address limits.

## Results

Success is a 256-byte `HIAMER01` descriptor in read-only slot 18. It binds
the Emitter lease/request, source Graph view/lease, complete registry view,
Code lease/last sequence, serial/function/global counts, actual finalized
text, actual ELF, normalized-source view, inventory and final Code registry
counts. The views remain valid until the caller releases the completed
session.

The 32 words are:

`[magic,1,lease,request,`
`inputSlot,inputOffset,inputBytes,graphLease,`
`registrySlot,registryOffset,registryBytes,codeLease,codeSequence,serial,functionCount,globalCount,`
`textSlot,textOffset,textBytes,objectSlot,objectOffset,objectBytes,`
`normalizedSlot,normalizedGraphOffset,graphBytes,inventorySlot,inventoryBytes,`
`labelCount,fixupCount,relocationCount,0,0]`.

The actual 128-byte terminal is:

`[HIACDE01,7,lease,sequence,domain,error,resultSlot,offset,bytes,`
`codeSequence,codeBytes,serial,recordCount,globalCount,request,0]`.

Domain 0 is success; domain 1 preserves original Code encoding refusal and
domain 2 preserves original program-native refusal. Semantic error payloads
are complete UTF-8 text in protected slot 17. The caller may not use partial
text/object buffers as a published artifact after an error.

Internal preparation and late finish events remain 16 words. Their complete
layouts and private offsets are part of the pinned author source, not a
foreign-party ABI. The controller checks each actual event magic, version,
lease, request, operation/mode, sequence, result extent and reserved status
before forwarding it. A GROW or semantic frame does not bypass correlation.

## Evidence carriers

The Python development carrier preserves full input/output/workspace bytes
before and after every actual entry in paged CAS, including exact canaries and
hardware permission checks. It remains the complete intermediate-workspace
evidence owner for the new small-domain crosscheck and private controls.

A second new C carrier executes the same fixed descriptor mechanics in a
fresh process. It is compiled by system GCC for this development test only;
it is not a pure-HIA installed ELF packer. It has no semantic callback and
never constructs instructions or symbols. Its trace saves:

- every actual image byte and complete initial input;
- actual entry role, slot views, capacities and rights;
- every actual return and complete available 128-byte header;
- every complete controller command and actual ACK/observed bytes;
- the complete final 128-byte event and every byte of every remaining slot.

The C carrier does **not** record every intermediate full workspace. The
new two-case crosscheck executes both carriers independently, compares
every native header return, all command/ACK bytes, all final slot bytes and
rights, and retains the Python full intermediate CAS. Its scope cannot be
substituted for the old 39/26 suites.

After all comparisons for a successful case finish and file handles close,
the new adapter may encode its two large temporary raw files as XZ. It
streams every decoded byte against the original, checks complete length,
SHA256 and file mode, writes and reads the complete encoding manifest, and
only then retires those exact temporary raw copies. Any comparison or
encoding failure keeps raw files. The manifest preserves original and
encoded paths and both complete identities. No byte interval is excluded.
Encoding CPU/wall are separately reported and remain inside the original
test-group envelope.

The outer seal uses a JSONL member ledger, streaming tar reads, full member
bytes/mode/hash comparison, a second complete file inventory, and cleared
TarInfo caches. It does not accumulate an unbounded TarInfo or full-file
payload list. The original common source/reference checks still apply.
The evidence format is a new explicit revision, not an altered old archive.

## Revision 2: captured subclass records reach semantic normalization

The first independent FOLLOW38 complete-Emitter run failed in the seventh
`manifest` case, `manifest-invalid-6`, after the first 39 groups and the preceding
six manifest cases passed. The unchanged capture records `InheritedStr("")` as
Graph tag 11. Preparation reused the separately frozen ELF writer's node reader,
whose accepted transport tag range ended at 9, so the actual entry returned
private BAD before the original exact-tuple semantic rejection could run.

Preparation now locally derives that node reader with two changes only: the
maximum defined captured tag is 11, and bytearray tag 10 receives the same zero-aux
payload checks as bytes tag 9. All identifier, reserved word, container edge,
scalar range, integer magnitude, boolean and floating-point shape checks remain.
A tag 11 string subclass remains distinct from exact string tag 4. The existing
normalization therefore rejects it at the original top-level tuple gate, or at
the exact-string pair gate when used as an export name. Tag 10 remains distinct
from tuple and integer as well. This does not change the frozen ELF writer,
coerce captured objects on the host, or admit a subclass into the borrowed-byte
ABI.

The controller, single-role builder and test module change only the source
identity pins necessitated by this preparation change. The original 55-group,
732-case, 50-private-control schedule, all comparison assertions and budgets
remain. A fresh revision must execute that complete schedule; FOLLOW38's partial
results are retained under their original source/image identities and are not
revision-2 PASS evidence. This revision is NEW and UNEXECUTED when authored.
