## Real process and response custody

The fixture uses the unchanged bounded client. A native process has an observed PID, parent PID, process start tick, executable identity and actual limits. The fixture fixes one role-6 node and allocation generation for that process. It decodes complete trace records and requires each input record to have a completed output/workspace record; fatal or truncated tails are refused.

The HIA framer's complete request includes the fixed transport header. The fixture checks that header mechanically and sends its unchanged body to the fixed ELF. It requires the exact full request to occur in the actual role-6 trace. The complete logical response on the pipe must be byte-identical to the final actual role-6 output extent. The response descriptor carries the same context, stable allocation generation, advancing actual entry serial, process lease and original request bytes. These private identifiers correlate custody; they are not authentication for arbitrary caller-supplied byte strings.

Every actual process is then replayed by the retained full six-role VM replay, with only the explicit FS30/FS31 syscall mapping extension. The original input, output, workspace and return value are compared without masks. Native trace records are partitioned exactly once; links, retirements and the unchanged original trace are checked. No OS calls are reissued by the replayer.

## Limits and failure preservation

The new component has one 900-second aggregate deadline spanning source-proof, build, comparison and test groups. Each native-containing process retains the original 90 CPU seconds, 180 wall seconds, 1 GiB address space and zero core size. In addition, each successful common.run receipt must show total reaped process-tree CPU strictly below 90 seconds.
