## 1. 名称查找与导入的实际修复

原观察在真实 HIA Core/Byte 映像上执行，并另行观察三个名字查找端口的异常元数据。104 个配对观察中，原实现有 88 个不一致：公开 helper 被替换、删除或设为非函数后，原生适配仍替换成自己的 helper；Byte 没有维持原分组导入及其 fromlist；缺失名字的 NameError 元数据及异常上下文也不相同。

修复使用定义时保存的原公开入口身份，只在当前绑定仍是该原入口时选择原生 helper。不存在的名字先按原名字查找规则处理。Byte 改为一次原始 IMPORT_NAME 加逐项真实 IMPORT_FROM，保留原命名空间、fromlist、顺序与异常。

随后独立发现被保留的 ImportError 会让导入端口的 `module` 形参延长模块寿命。原 Byte 寿命组 8 项中有 6 项不一致；原 Build 组 6 项中有 4 项不一致。修复在执行 IMPORT_FROM 前清空命名形参，模块仅保留在解释器求值栈上；Build 的源码生成器同步修改，避免下一次生成恢复旧实现。修复后的原 104 项、Byte 8 项、Build 6 项均一致。所有原失败报告仍在完整证据中。

新修订增加 8 个永久测试方法，相关原 91 个测试方法正文逐字不变。这 8 个方法包含 3 个 Source 方法和 5 个 Native 方法，本机 Python 3.12.14 实际执行 8/8 通过，观察到 24,880 次实际原生返回，完整源码执行前后相同。它们没有替代原组件组和原调用组，也不构成 Python 3.14 或冷构建资格。

冻结包 `global/SOURCE-CHECKPOINT.zlib.json` 相对上述 3,255 文件候选包含 20 个完整改动，形成 3,257 文件、树 `0a3fba637afe252f9bdf192b7a24df67b08efcbe`。完整本地证据含 142 个文件，包括原失败、修复后观察、机器映像、输出缓冲区、编译收据、源码前后快照，以及第一轮准备脚本错误使用不存在命令行参数的原失败。17 个片段按索引可无损重建原证据包；每个片段已得到 Git 创建 ACK 并全文读回。

冷构建接入的另一次只读检查发现：新辅助文件 `tests/hia_native_name_resolution.py` 已被 Byte、Build、Verification 构建器列为必需输入，却未加入总 `SOURCE_FILES`。8 个具有显式 REQUIRED_SOURCE_NAMES 的构建器中，只有这三个缺失该同一文件，没有已登记文件哈希不匹配。这个原始遗漏单独保留在 `global/COLD-REQUIRED-INPUT-GAP.json` 和 `global/ALL-COLD-REQUIRED-INPUT-AUDIT.json`。新的联合修订正在补齐登记、精确追加 Byte foreign 机制集合并重新生成；不得把该修补前包当成冷构建可交付件。
