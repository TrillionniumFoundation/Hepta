## Two separately admitted phases

1. Root executes SOURCE-PREPARATION-LAUNCH. This data-only step creates a new
   isolated metadata scope and binds the existing source; no product import or
   source copy occurs. Root reviews its actual BOUND-PLAN/BINDING-RESULT and
   chooses whether to launch the resulting exact PRODUCT-LAUNCH.
2. The Source phase executes the original Source10 and physical-lease Source8
   groups, in order, under two separate original 180+3 owners. Their complete
   ID/event and subtest observers are retained. The original cooperative audit
   fence's only body change is its explicit current protected-root tuple; it
   still rejects subprocesses and writes to protected paths/inodes. It is not
   described as a hostile-code sandbox.
3. Root separately reviews actual Source18. Native preparation requires its
   exact final result SHA, complete actual per-file payloads and seven stats,
   both original owner receipts, all IDs/events and subtests, current source
   identity, runtime and actual generation result. A failed or missing Source
   predecessor cannot produce a Native binding. No future PASS/hash is filled
   into the author plan.
4. The Native phase uses ten original 180+3 owners: one real Inspect compile,
   all seven original Native groups (17 methods), then both original VM groups
   (12 methods). There is no automatic retry. A failed group, final source guard,
   missing frame or incomplete cleanup stops all later owners.
