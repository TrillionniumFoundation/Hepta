## 3. 证明的精确边界

新增证明针对所有有限、闭合的所选能力列表，以及所有单射名字映射；不依赖循环展开次数。
证明保留根关系、父子关系、父借用暂停、排他别名关系、闭合性、能力数量、类型、
external/origin 字段，并满足重命名的恒等和复合律。

“所选”是 CFG 边真正携带的能力图。可执行验证器另拒绝未知能力、重复目标名、
丢失本地 owner/loan 和缺失 root/parent；允许遗忘未使用的 external 参数。
该遗忘投影没有被能力列表长度定理证明，Python 实现与 Lean 模型的对应目前靠生产路径回归与拒绝控制，
没有冒称 Lean 已证明 Python 代码。

## 4. checked reduction：语义保持，强 Rust 门槛未关闭

快路径先提出无符号模运算的低字节改写，再由独立验证器检查；
原有 checked 指令不会因结果截断而偷偷消失。随后执行守卫
n <= floor(U64_MAX / 255)，用归纳证明允许的 reduction，并在守卫外保留完整 checked 回退。
两个 workload 各有 20 个标量、12 个归纳义务，共 64 个 UNSAT；没有把测量长度当成证明假设。

Rust 对照同时包括普通 release 和显式低字节算术版本，都使用 O3、fat LTO、单 codegen unit 与 panic abort。
每轮保留 144 个行为/资源控制、56 个大输入拒绝探针、360 个计时请求和 7,560 个批次样本。
验收阈值是 median <= 1.10 倍对照且 batch p95 <= 1.20；它是预登记容忍门槛，不等于“每项更快”。

| 对照 | 首轮通过 / 总数 | 完成版通过 / 总数 | 完成版独立留出 | 完成版 HIA/对照 median 比值范围 |
| --- | --- | --- | --- | --- |
| 原 checked HIA | 30/30 | 30/30 | 16/16 | 0.3543–1.0891 |
| Rust release | 25/30 | 26/30 | 16/16 | 0.6380–1.2284 |
| 更强 byte Rust release | 16/30 | 21/30 | 12/16 | 0.9914–1.2510 |
| 两个 Rust 对照合计 | 41/60 | 47/60 | 28/32 | 整体门槛失败 |

比值越低越快。首轮在独立留出上相对原 checked HIA 的 median 加速为约 1.11–2.23 倍；
相对强 byte Rust 则仍慢约 3.36%–29.14%。完成版只有一个回归项（linear n=64）略快于强 byte Rust；16 个留出项全部慢约 1.71%–25.10%。

两轮程序性能实现相同，完成版只扩充组合阶段和 Agent 实验协议；
不同运行的通过数差异不能宣称为新的优化收益。全部长度、尾延迟和失败均保留。
表中的“独立留出”是协议标记的 holdout 长度/负载，在资格计时前已经冻结；
没有另外证明开发过程从未观察这些数据，不能当作经独立审计的开发前盲测，也不代表广泛真实应用。
下一轮需要登记新的留出集合、分析合法向量化/小输入开销，再做代码改进和消融；
不能反复调整本轮留出数据直到“过线”。

构建/证明/链接、装载、首次调用、warmup、采样和清理也有完整 wall 账本。
生命周期摊销表是实测中位数的模型推算，不是每个 horizon 都独立执行过的重放。
共享库文件大小不等于实际映射内存；人工工程成本、能耗和未测成本不按零填写。

## 5. NDU：实现完整成本账本，保留净收益失败

本轮使用固定原生 stream NDU，候选空间明确限定为基线加至多两个变体、至多四步 horizon。
调度模型包含本次/未来 invoke 与 skip、候选准备及证明、实际通信、驻留/复用/退役、
失效和预算。纯 skip 路径不启动 NDU；原生装载、卸载、重载和执行都实际发生。
96 个有限穷举模型对照与原生拒绝/恢复控制用于检查实现是否符合相同模型。

| 场景 | 首轮 NDU/最佳控制 service median | 完成版 NDU/最佳控制 service median | 完成版胜全部控制 |
| --- | --- | --- | --- |
| tiny | 1.090676 | 1.059984 | 否 |
| amortized | 1.329188 | 1.305119 | 否 |
| invalidate-recover | 1.439614 | 1.411348 | 否 |

两轮均保留 9 次实际原生调用与 3 个不启动 NDU 的纯 skip episode。
完成版的保守完整 solo 分摊为 fixed 5.057261 秒、exact DP 5.094874 秒、
lightweight 5.069929 秒、native NDU 24.034514 秒；NDU 包含其实际构建开销。
这三次探索性重复的负结果不外推成“所有负载必定无收益”，也不证明应用级收益。

相同确定性模型、相同信息和相同目标下，精确 DP 已给出该模型的最优决策值。
NDU 若得到相同决策但多付通信、搜索与校验成本，并不会自动产生净收益。
未来要争取的应是更大状态空间中、相同时间预算下更高质量的可行解，
或真实非平稳负载上的经校准收益；都需重新登记实验，包含强固定和廉价控制，不能靠更弱对照赢得结论。

原生 bridge 的完整构建成本及 qualification 进程的剩余开销另在外层补齐。
保守的 solo-policy 成本是按预定规则分摊实际观察的账本，明确不是四个独立 solo 重放。

## 6. C/C++ 迁移和 ABI 的实际进展

新 profile 从新鲜 Clang AST 识别闭合 std::unique_ptr<unsigned char[]> 资源流程：
reset(source.release())、self reset(release)、reset()/nullptr、容量/下标守卫、
获取资源后的 throw-int 路径以及正确作用域析构顺序。
生成目标是独立的 Hepta/Core/原生对象，不链接原 C++ 对象。

原版本和作者编写的 API 维护变体各有 1,245 个场景；各 1,066 次成功分配/释放配对、
642 次分配拒绝，live=0。缺失 drop 在发布前被拒绝；错误析构顺序即使通过资源安全检查，
也会被独立行为 oracle 拒绝。另有七类新鲜 Clang 非法源拒绝控制。
标准库声明依赖被完整捕获、核对并列为可信输入，没有被宣称已经全部翻译或证明。
人工工程时间未知，不能把几十秒机器资格时间称为 C++ 迁移全部成本。

真实上游升级复验使用 GSL 3.1.0 的 0f6dbc9e2915ef5c16830f3fa3565738de2a9230
和 4.0.0 的 a3534567187d2edc428efd3f13466ff75fe5805c：
3.1 非 const 左值 finally 工厂拒绝，4.0 接受；const 左值两版本均可迁移。
六对原始/迁移目标，各 416 行，共 4,992 个正观察、14,976 次标量 C ABI 调用。
这是真实版本升级的限定实例，也是已有 translator 在本组合上的复验；
不是整个 GSL、通用 C++ 异常 ABI 或任意 callback 的迁移。

[Ring-Buffer/musl 双架构 CI](https://github.com/TrillionniumFoundation/Hepta/actions/runs/41257229870)
在实际 x86_64 与 AArch64 Linux runner 上重验固定上游源码。
4 个 TU、12 个翻译函数体中 11 个来自上游，1 个 checksum 和集成客户端为作者编写。
每个架构 48 个功能输入/144 次原生调用，以及 16 个资源/分配故障注入控制场景、32 次资源调用（包含 refuse_at=0 正常或未触发拒绝的控制，并非每个场景都发生实际分配失败）。
两架构生成相同 Core SHA-256：57b01a1a318a7e668d2780c010f977f9c7dbbb233f093a0b1efd93a3e779be89。
范围限定 Linux little-endian LP64 标量 ABI；runner 执行证据不等于物理硬件远程认证。

## 7. Agent 三模型试验

冻结源码和工具身份检查通过，三种预登记模型均实际请求。整个模型 campaign 的外层执行时间为 954.674 秒。
共 12 个任务单元、16 次模型请求；5 个成功、4 个公开校验失败、3 个超时未完成。
超时的 token usage 未知，不能当成零用量或确定错误答案。

| 模型 | 完整模块输出 | 结构化编辑 | 每成功任务已观测分摊时间的下界 |
| --- | --- | --- | --- |
| Qwen2.5-Coder 1.5B Q4_K_M | 0/2；含 1 个超时 | 0/2 | 无成功任务，不定义 |
| Qwen2.5-Coder 7B Q4_K_M | 0/2；2 个超时 | 1/2 | structured ≥ 454.094 秒 |
| Codex 请求 gpt-6.1-sol | 2/2 | 2/2 | full ≥ 14.038 秒；structured ≥ 9.875 秒 |

时间是协议指定的每臂独立使用分摊口径，包含对应的已观测下载、原生 controls、可用性探测和生命周期分摊；
不是把各臂时间相加后声称 campaign 实际经过那么久，也不是美元成本。
公开派生账本补入了 campaign 外层减内层的 228,519,181 ns，按六个登记槽均分。
controls 的另一个未测开销仍保持未知，所以上表只能是该口径下的已观测下界。

五个成功单元共保存 80 条正常原生结果和 25 条隐藏拒绝结果。
重新解码检查确认正常值均符合 oracle，分配/释放为对应 1/1 或 2/2，存活资源与记账错误均为 0；
拒绝是预期 SIGILL/SIGABRT，而非把任意非零退出当作正确拒绝。

API 模型两臂的实际用量揭示了不能忽略的差异：

| API 任务指标，两题合计 | full | structured |
| --- | --- | --- |
| input tokens | 30,853 | 35,817 |
| output tokens | 1,538 | 223 |
| input + output | 32,391 | 36,040 |
| cached input，属于 input 子集 | 11,648 | 23,296 |

结构化回答的输出 token 减少 85.50%，但总报告 token 增加 11.27%。
公开任务信息只有回答格式字段不同，实际 API input 却每题多 2,482 tokens，无法仅由那 50 个字符解释；
CLI 额外上下文/计量来源没有被独立识别，缓存也不同。
因此不能把全部耗时差归因于结构化编辑，更不能宣称 tokens、时间和货币成本同时改善。
[完整公开摘要](agent-bd450/PUBLIC-SUMMARY.json) 同时保留成功、失败、超时和这些计量限制。

任务严格称为“来源明确的仓库模块上的登记缺陷注入”。对历史路径的查询未找到可用的真实维护前后对，
不能把这两个任务改称真实历史维护。两种本地模型属于同一 Qwen 家族；
API 额外系统上下文、缓存和预算执行方式不与本地模型假装等价。
完整模块与结构化编辑得到相同初始模块、公共契约、位置、公共用例和编辑 schema，差别仅为回答表示。
这是 HIA 内部两种编辑接口的比较，没有设置 Rust/C++/TypeScript 语言开发臂。
公开验证最多允许一次反馈重试；hidden 评价为终局，从不反馈给模型。
工具控制不算模型成功，基础设施故障不当作模型答错，失败不移出分母。

已观测账本列出请求、重试、验证、hidden 检查、启动、重启、哈希、关闭、共享准备、
下载和可用性探测。每成功任务成本要求完整 usage 与身份校验成立。
token 总量按 input+output，reasoning 是 output 的细分，cached 是 input 的细分，均不重复相加。
不同 provider 的 token 不合并为金钱；训练、人工维护与货币价格保持未知。
还有一个明确的计量缺口：冻结 controls 当时通过独立 CLI 直接执行，只有内部 wall，
没有可复核的外层进程回执，因而其 Python 启动与最终记录收尾开销未知。
本次不事后补造时间、不重跑替换原 controls；各臂的已观测成本及每成功任务成本仅能作为有缺项的下界，
不能标为完整端到端成本闭合。下一轮必须在登记前将 controls 外层回执纳入必需身份与成本输入。
公开包保留完整候选、结果、使用量与原件哈希，排除本机配置、状态库、凭据和内部思考文本。

## 8. 并发、外部借用和恢复的边界

新 host-region profile 使用实际 Linux memfd seals、mprotect 和固定大小映射。
对象有代际身份和租约；共享只读和排他写互斥，未借用状态不可访问。
实际 C 原子计数观察到至少两个并发 reader；writer、unmap、代码退役冲突被拒绝。
只读页写入的独立子进程实际以 SIGSEGV 结束，而不是仅检查一条声明。

超时、异常或不确定状态保留映射、代码和租约并隔离；只有 worker 已 join 且外部租约归还才可恢复、清零和推进代际。
不确定进程启动或 fd 关闭造成不可回收的拒绝债务，避免冒险释放后重用。
18 项拒绝控制和 9 项 host-region 回归均已执行。

这些性质依赖明确的同步、有界、不逃逸 C 合约。它们不证明任意恶意 C、任意裸指针、
非一致缓存设备、MMIO、DMA、进程崩溃后持久恢复或一般并发 Core 的内存模型。
设备权限当前保持拒绝，后续必须按实际设备、IOMMU/驱动与故障模型单独建立 profile。
