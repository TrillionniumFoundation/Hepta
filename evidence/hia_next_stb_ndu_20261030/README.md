## What is actually proved or observed

The original pinned source is `nothings/stb` commit
`003501f6d7a8668ce8b6d875e34dd97ad0d5d5b5`; the complete header hash is
`46358dedcc0f49324a602f796b13f24e00fa0e512046354ee69511997401af6c`.
The source was captured through the existing whole-component migration route.
The separate bounded call-aware SMT profile compares the original Core
caller/callee closure with the proposed flat Core, including first-trap codes
and ordering. The default call-free TV profile remains unchanged.

The baseline and guard-8, guard-10 and combined-guard candidates occupy
8/13, 17/28, 17/28 and 26/43 blocks/operations respectively, within the existing
32-block/512-operation bound. Four distinct exported native bodies were
prepared and checked. Every actual request has independent inputs, a full
repeated-call count, raw native events and a final checksum. The bound runtime
source creates and consumes a distinct nontransferable in-memory token for
each prepared trace. That token is not serialized: `trace_sha256` is a content
digest and can repeat for equal plans. The offline audit validates content
bindings and all distinct delivery records; it cannot independently prove
in-memory token freshness from those records. The reference cache stores pure
expected values only; it does not store native results or execution authority. The fixed arm receives the complete
combined guard and generic fallback, like every other policy.

The original C undefined cases (zero denominator and `INT_MIN/-1`) are not
promoted to defined source-C equivalence. The application workload uses positive
denominators 8, 10 and 13. The evidence does not prove general C/frontend
refinement, machine-code refinement, a verified system loader, absolute memory
safety of arbitrary foreign code, or production demand. Authority remains
`DENY_ALL` and safety-certificate flags remain false.

The immutable archive contains 3,242 regular files and 71,351,310 payload bytes:

- Archive: `hia-stb-ndu-20261030.tar.xz`, 5,382,792 bytes.
- Archive SHA-256: `e406e8826a7a98aab96232054757a14857b71020c9f5c5b154d170d2c74e7fa2`.
- Manifest SHA-256: `a3e7ea32a6ff607071f662a39f96bf0b9ba9c56ae3b30e1fd5b833945c8f5a00`.

`verify_evidence.py` uses only the Python standard library. It checks the two
external hashes before parsing, using one no-follow bounded regular-file read
per archive and manifest and the same bytes for hashing and parsing. It bounds
compressed/expanded/member sizes and XZ memory, rejects unsafe, duplicate,
linked and special members, and hashes every file. It then audits actual native
events, independent mathematical checksums, input domains, trace-content and
local-slot-to-global-image bindings, all policy information rules, NDU wire frames,
32 same-model exhaustive choices, complete cost arithmetic, identity snapshots,
resource releases, failure preservation and all three negative gates. It does
not extract or execute archive contents, run SMT, compile or load a model.

```sh
python verify_evidence.py \
  --archive hia-stb-ndu-20261030.tar.xz \
  --manifest hia-stb-ndu-20261030.manifest.json \
  --output VERIFICATION.json
```
