# Seven-track implementation and qualification, 2026-11-04

This branch combines executable changes and explicitly scoped research evidence. A successful command is not evidence that a performance, economic or general proof target passed. `all_seven_research_targets_closed` remains false until the independent acceptance conditions are actually satisfied.

## Fixed composition

`tools/qualify_hia_composition.py` v3 starts from clean committed source and hashes every materialized active file against its actual Git blob. It fixes Python, Z3 4.15.4, the locked Lean 4.19 binary, Clang 20, Rust 1.95.0, system native tools, both bridge protocols and the Linux x86_64 target. All output directories are new and outside the source worktree. It checks source, tools and frozen products before and after every phase and retains original command streams and outer wall costs.

The supplied-candidate `zero-abstain-v1` bridge and the additional `raw-model-v1` bridge share upstream NDU commit `8e52e1187f47f6d4edc8d942fc7cb7eca4bc447d`; they have separate source adapters, executables and receipts. The latter sends the complete bounded model to native Rust and validates returned witnesses without a Python continuation search. An old binary, a different adapter inventory, a historical compiler or altered build streams cannot join this composition.

The raw builder may read a complete local Git object mirror to avoid a partial-clone lazy-fetch stall. The unchanged upstream pin and extracted source bytes determine identity; the mirror path does not substitute a different source revision. Both native targets must start absent. Prior dependency acquisition and failed preparation attempts are retained separately; this is not a fully cold machine claim.

The composition includes Core and negative controls, ownership/borrow/lifecycle proofs, selected sequential all-input validation, native continuation/recovery, reduction and the new guarded-layout performance campaign, full-cost application controllers, native raw-model correctness and service costs, both C++ ownership profiles, real GSL release upgrades, SQLite/GSL resource profiles, host-region failure/recovery, and Agent tooling controls. The complete model study is an additional registered command from the same frozen source.

## Agent experiment scope and accounting

The new factorial protocol crosses compact HIA/Rust with full-file/exact-patch responses. All four arms receive the same problem, files, allowed-language information, public examples, generic JSON decoder and feedback schedule. Both interfaces must materialize the same reference source. Hidden evaluation happens once after the first public pass and terminates the cell. No hidden result enters feedback.

The four two-file tasks are the existing authored arithmetic maintenance fixtures. Two exact model files provide 32 cells with fixed ordering, attempts, token/context/deadline/thread budgets and no same-cell rerun. This is an executable descriptive pilot, not evidence of real external repository maintenance or stable population-level gain. Model acquisition, human labor and energy are unknown where no original measurement exists.

Partial cells retain their requests, known token usage and arm-specific time even on evaluator or artifact failures. Unknown token quantities remain null. Cleanup errors and missing cells must produce an incomplete result. The complete runtime library inventory is bound across preparation, execution and model sessions. All common observed preparation/runtime costs are charged once to each descriptive standalone arm; those allocated totals are not independently executed standalone campaigns.
