# Independent method review of the real-node Agent study

## Decision and attribution

The prospective V8 registration at `33c46cdef12c60faf0c1dbef02ea20caa3ad7d56`
(tree `4fd330b60ddfa1ba2ef49d534d33dc056f9b9f98`) has no outstanding blocking
method defect identified in this review. The reviewed source can proceed to its
**fresh three-task Rust-node qualification**. The reference controls do not
satisfy that qualification, and this review does not authorize bypassing it or
assert a qualification/main result.

This is a review of the actual registered finite task/tool experiment. It is
not a proof of language safety or general Agent productivity. The full and node
arms differ in presentation, editable granularity, and tool overhead; their
contrasts estimate those complete tool bundles. A four-task, one-model,
deterministic descriptive study does not establish a population effect or
long-term maintenance advantage.

The study owner ran the producer controls. The independent reviewer read the
implementation and checked retained evidence using only Python's standard
library, Git, and file hashing. The reviewer ran **zero tests, tokenizers,
compilers, VMs, native candidates, or model requests** during this final audit.
Recorded tokenization and execution observations remain producer results.

## Findings resolved before generation

1. **Disclose the enforced HIA full topology.** The first draft enforced the
   original function entry, effects, and block identities for full-file answers,
   but only the node catalogue told the model about that restriction. The common
   HIA prompt now explicitly states this boundary for both interfaces. The old
   `max 16 blocks` finite ceiling is not an invitation to change this task's
   existing block identities.
2. **Bind the runtime across stages, not only within each process.** The first
   frozen registration, `5bba97e859da71a06686fc97970ef53ab0cb6678`, compared the
   server/tokenizer executable identities between stages, while each engine
   separately recorded its local shared-library baseline. Replacing a companion
   library between capacity and qualification could therefore establish a new
   baseline without invalidating eligibility. `33c46cd` adds the server and
   tokenizer directories' sorted `.so*`/`.dll` companion identities to the same
   strict cross-stage tool set. A meaningful negative control first accepts a
   complete capacity record, changes only `libllama.so`, confirms the main
   executable is unchanged, and requires rejection. The actual capacity receipt
   binds 38 companion path identities; these are not a complete system-library
   or process-state attestation.

Earlier development review also led to complete common language rules,
explicit Rust `changes.text` and parameter roles, disclosure of failed-transaction
rollback, use of the exact pre-generation query, the new files/edits decoder
without an unscored `check` field, and the same finite parser and
`compiled && native_built` execution boundary for full answers. These changes
are part of the new V8 source; old V4/V5/V6 results were not rescored.

## What the implementation actually enforces

| Boundary | Reviewed implementation behavior |
| --- | --- |
| Equal generation allocation | All four arms use the same pinned 7B GGUF, context 8192, output limit 1536, maximum three submissions, greedy temperature 0/seed 0, four threads, no prompt cache, and 900-second request deadline. The engine receives the protocol context and output limit. |
| Real tools | Node answers bind the query captured before inference. HIA invokes the previously reviewed production batch/patch adapter; Rust uses finite parsed expression/type spans. Full Rust also runs the finite parser. Full HIA preserves original entry/effects/block identities. |
| No automatic answer correction | The model's returned text is retained. The node adapter applies only the submitted fields/fragments; it does not infer missing edits, merge failed answers, or add casts/grouping. Parentheses in offline human reference construction are confined to the control-only module. |
| Atomic rejection | Admission, compilation, or public failure leaves the original project unchanged. Every repair must resubmit its complete intended edit set against that same captured original query. The existing V7 transaction, parser-depth, and failed-build execution fixes remain unchanged. |
| Public feedback | The feedback path receives only the public execution. It pairs public arguments/expected/observed values and resource/VM flags with actual admission/compiler diagnostics. It does not import reference construction. |
| Hidden evaluation | Hidden execution runs only after public acceptance and immediately terminates that cell, including a hidden failure. No hidden observation can become another request for that cell. |
| Unselected nodes | Queries and catalogues derive from the actual original sources and policy. The decoder contains no golden node IDs, repair operations, or answer values. Prompt controls mutate every hidden/reference field and require all 19 prompts to remain identical. |
| Fresh qualification | Main requires same-source V8 qualification for the three listed Rust-node tasks, all correct with terminal hidden evaluation and complete usage, matching model/tools/capacity/protocol/prompt bindings. A V6 eligible flag is rejected. |
| Cost accounting | Failed requests remain in the arm totals. Partial SSE retains exact input usage and observed output lower bounds while unknown residual output remains unknown. Tool validation, history preparation, cell/run time, startup/shutdown, qualification, and controls remain separately inspectable. |

These are implementation and evidence-review observations, not an independent
formal proof of every possible execution of the experiment harness. Identity
checks cover the declared file sets and the owned runtime; they do not establish
physical machine identity, user `dot` execution, or comprehensive OS isolation.

### Exact limitation of the capacity result

The additive allocation is **not a tokenizer theorem for arbitrary generated
text**. Every actual complete server-rendered request is tokenized again before
generation. A complete previous answer over 1664 tokens, public feedback that
cannot fit after diagnostic-only clipping, or an actual request exceeding the
context ends that cell as a recorded budget failure. Previous code is not
truncated, public cases/resource flags are not removed, and prior cost is not
discarded. The raw diagnostic remains retained separately while its displayed
prefix may be shortened under the common rule.

Consequently three submissions is a maximum, not a guarantee that every possible
model output obtains two further repairs. This is an explicit registered budget
condition, not a reason to silently skip failed cells or claim all conceivable
histories fit. The checked reference and public-no-op histories do fit.
