## Scope and files

Place `hia-paired-native-controls.yml` at `.github/workflows/hia-paired-native-controls.yml` in the entry checkout, and `measure_hia_native_controls.py` at `tools/measure_hia_native_controls.py`. The workflow separately checks out the frozen HIA source at its exact commit. It uses the existing source APIs and native builder; it never edits or monkeypatches that source.

The committed protocol and schema destinations are `docs/HIA_PAIRED_NATIVE_CONTROLS.md` and `schemas/hia-paired-native-control.schema.json`. A push can trigger this workflow only on `codex/hia-sixgap-entry-main-20261108-a897df9a` when one of these four files changes; manual dispatch remains available. Immediately after the entry checkout, the workflow requires `releases/hia-current.json` to select the pinned HIA repository, commit and tree, and retains the original lock plus its hash. The actual source checkout must match both commit and tree. A future entry lock selecting another source therefore cannot silently run this pinned comparison.

The existing `run_control()` CLI fixes order to Ordinary then NDU. The underlying `run_cell()` API already accepts the arm independently. The entry harness uses that API with the same explicit authored proposal provider, allowing four preregistered pairs in **AB / BA / BA / AB** order (A=strong Ordinary, B=actual native NDU). Each cell gets a fresh local worker directory. Every pair uses the same first generated calibration task, ABI, baseline, mathematical oracle, objective, three proposal opportunities and budget. No task is regenerated or substituted after failure.

The provider is Python authored control logic, not a model: one deliberately malformed entry block followed by the same two private-feasibility assemblies. It invokes no provider executable or model API. These original source methods then perform discovery, complete Core checking, actual proofs, emission, native observations, strict size admission, selection, adoption, all-256-input consumer execution and rollback. This is a synthetic teacher-derived mechanism comparison, never an unfamiliar-Agent or real-repository task claim. The exposed control-only task/teacher must not later be relabelled as blind or heldout data.

## Fixed bounds

| Item | Bound |
|---|---:|
| Scheduled paired repeats | 4 |
| Total cells | 8 |
| Wall allowance per cell | 30 seconds, identical for both arms |
| Sum of original cell allowances | 240 seconds |
| Scripted proposal opportunities per cell | 3 |
| Native observation timeout inherited from source | At most 10 seconds, further capped by remaining cell time |
| Native child memory bound inherited from source | 512 MiB |
| NDU ranking timeout inherited from source | At most 1 second, further capped by remaining cell time |
| Real model / provider invocations | 0 |
| Complete workflow timeout including dependencies/build | 20 minutes |

`model_tokens:32768` is retained as the common admission ceiling required by the unchanged source interface. It is not a call to a model, a charge or a reported usage count; every authored provider receipt explicitly has `model_invocations:0` and `provider_usage:null`. A zero token ceiling would structurally stop the source's proposal admission even for these authored controls, so it must not be used to falsely create an empty benchmark.

The existing API does not impose a 180-second minimum. The remaining-cost forecast is the actual candidate probe duration plus a 2 ms transition estimate and 10 ms uncertainty when calibration is empty. There is no fixed forecast term above 30 seconds. This makes 30 seconds a meaningful bounded envelope rather than a structural rejection. It does not promise a slow or contended host will finish. Budget exhaustion is retained as failure, with no allowance increase or retry. Source guards can observe an operation overrun; the allowance is not advertised as hard preemption.

## Choice and tie interpretation

Actual pool cost rows are derived from each arm's own measured probes. The opportunities and rule are matched; the observed cost rows across separate cells are not asserted identical. The external audit re-evaluates every returned original pool with the strong Ordinary function at the exact recorded allowance and checks choice agreement. This audit is read-only, is separately timed, and never replaces an original arm outcome.

The two authored feasibility programs are identical, but their observed probe wall costs will normally differ. Therefore this task comparison may not trigger a numerical tie. The summary records actual native raw recommendation, native disposition/frontier, admitted callback observations, caller selection source and `caller_tie_policy_applied`. It reports a tie count and explicitly says when no tie was exercised. It never edits/rounds observed costs to manufacture one. The actual-native integration CI's independent 100/50/50 probe covers the exact tie repair; that probe is separate from task-cost measurements.

## Cost accounting and failures

Each source ledger retains every event and failure. The entry audit checks event hashes, contiguous offsets, the original budget, actual native wire binding, program consumer observations and adoption/use/rollback. The wrapper clock includes per-cell worker setup, source `run_cell()` work, final receipt production and worker cleanup. The source ledger time is nested within that wrapper clock and is not added to it again. External audit cost is separately reported.

A workflow-level monotonic interval begins before checkouts and ends after final verification. It therefore includes source acquisition, dependency setup, Rust/native build, task generation, scheduled cells, evidence handling and step gaps within that interval. Nested build and cell times are never summed into it a second time. The original native build receipt/logs and actual native executable are retained for independent hashing. Queue time and final artifact upload are outside the observed interval and remain null; CI billing remains null.

All four pairs remain in the report. Each arm's completion count accompanies its costs. Raw paired wall differences can be shown even for incomplete pairs, labelled raw; a completed ledger difference is null unless both cells completed and their original cost evidence is known. There is no best-repeat selection. Missing aggregate cost remains null, with any known subset labelled separately.

Normal settled task failures do not earn retries; later registered cells can still run. Unsettled cleanup, unexpected orchestration exceptions, identity drift or an original-evidence audit failure stops later cells. The unstarted cells remain in the planned denominator and have null timing fields, rather than being turned into free completed work.
