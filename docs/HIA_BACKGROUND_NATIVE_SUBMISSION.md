# Native background submission

This component owns the complete private native implementation of BackgroundOptimizer.submit. It requires a constructed native coordinator closure and returns an independently owned public Future. Constructor, execution, worker interruption, public coordinator methods and final installation have separate integration gates; this report does not qualify the whole BackgroundOptimizer.

## Preserved ordering and ownership

The owner takes an actual monotonic clock before acquiring the same nonrecursive queue condition used by the worker. Under that condition it checks closed state and outstanding capacity, performs the original typed structural gate, freezes the actual caller values with sorted compact JSON, checks the objective, captures the actual runtime snapshot, binds the current tracked source, and checks the incumbent observation. It then creates a real public Future, retains a separate coordinator reference, creates an external-Future Job, assigns the next complete integer job number, and transfers the Job into the FIFO. The second actual clock records enqueued_ns and submit_work_ns before releasing the condition.

The frozen candidates, observations and objective remain bounded by the original 8 MiB, 262144-node and 64-depth contract. The HIA admission workspace is sized from the actual node count. Generation, epoch and job numbers use immutable full decimal values and preserve their original integer domain; converting an input integer to JSON still obeys the separately captured int_max_str_digits policy. A 100001-digit job number does not acquire a JSON conversion limit merely because another stage renders input integers.

The Job's slot 0 holds an independent immutable source payload. Each occupied coordinator slot retains its own metadata and public Future reference. The caller's Future reference survives the coordinator's factory lease, accepted Job and runtime being released. Cancellation does not release capacity before the worker observes the Job.

An accepted Job remains accepted if a later fixed dependency fails while recording bookkeeping. Its queue and Future ownership remain intact. Final whole-worker handling must account and settle that Job; it cannot infer that enqueue did not occur.

## Private native entry

The complete entry is six-argument hia_background_submission(s, sN, o, oN, w, wN). Its output extent is at least 524288 bytes; the captured coordinator context is at least 8192 bytes. These are control/storage extents, not an additional public value limit. The actual image is generated by the HIA packer and native shared linker, with the readable mechanical bridge recorded in the qualification JSON.

The request is exactly 128 bytes, magic HIABSQ01. Operation 0 submits three actual mutable value capabilities. Operation 1 performs cleanup-only retry and has no value inputs.

| Offset | Field |
| --- | --- |
| 8 | Operation: 0 submit, 1 retry retained cleanup |
| 16 | Zero |
| 24 / 32 / 40 | Candidates value capability |
| 48 / 56 / 64 | Observations value capability |
| 72 / 80 / 88 | Objective value capability |
| 96–127 | Zero |

Operation 1 requires all request words after the operation to be zero. Callers hold the three actual value references across the complete native call. No public typed flags, asserted hashes or verified booleans are accepted.

The persistent closure is HIABSSC1. The enclosing native coordinator owns every dependency, FD-derived source, context, capability and template throughout its lifetime.

The freezer template captures the integer-to-string conversion policy at its original offset 80. The standard tested context uses 4300; unlimited conversion is a separately captured policy. Submit cannot override it.

## Replies and failure ownership

A zero native return produces HIABSRP1. The business status is at 8, accepted flag at 16, queue slot at 72, inline error length at 80, retained-cleanup flag at 88 and detail at 96.

| Status | Meaning and owned return |
| --- | --- |
| 0 | Successful submit: factory identity at 24–40 and independently owned caller Future at 48–64 |
| 1 | Original structured error JSON at byte 128, length at 80 |
| 2 | Original mapped runtime error: owned provider reply at 24–40; complete bytes length at 48 and borrowed address at 56 |
| 3 | Actual public Future exception: owned value capability at 24–40, actual kind at 48, actual Exception/BaseException status at 56 and original scalar at 64 |
| 5 | Actual allocation failure |
| 6 | Private lifecycle violation |
| 7 | Unmapped dependency/internal failure |
| 8 | Actual syscall failure |
| 9 | Owned cleanup remains quarantined |

For status 2, release the returned provider reply using HIAMVBQ1 operation 5 with its capability at request 40/48/56 and zero runtime capability. The borrowed error bytes remain valid only while this owned reply remains live.

For status 3, kind 100–107 is the actual builtin error fallback and kind 200 carries the actual owned exception value. MemoryError may have kind 103 and an all-zero value capability when allocating the exception itself failed. The scalar field is preserved separately and is not substituted for kind. No zero capability is dereferenced.

The runtime provider distinguishes mapped errors, actual allocation failure and unmapped dependency failure. Submission preserves that distinction. Runtime post-publication errors and actual committed state belong to the later execution/accounting chain.

Short or malformed private views and envelopes return 4294967293 without publishing a partial public reply. The mechanical entry may initialize its private phase word. Each invocation may use fresh poisoned output; persistent references belong to the captured closure.

## Cleanup-only retry

The owner retains its allocation pointers, owned references, freezer continuation, typed structure's full 96 MiB output, exact threshold request and captured 128-byte structure context when releasing a dependency reference fails. New submissions are blocked while this continuation is retained.

HIABTC02 operation 2 resumes the actual structure cleanup. Each explicit submission retry performs one cleanup pass. A repeated dependency failure returns to quarantine; it does not loop internally until success. Successful releases are cleared and are never repeated. Unknown continuation returns and unexpected function identities remain quarantined without being interpreted as a valid typed cleanup state.

Retry does not re-run structural checks, freeze inputs, capture a snapshot, create a Future, consume a job number or enqueue a Job. An accepted Job and its metadata remain unchanged. Cleanup of the current invocation may succeed while its saved original error is still returned; the quarantine flag states whether ownership is fully released. An empty retry is a successful no-op.

## Actual qualification

The final fixed image is 348944 bytes with SHA256 836a2e2c95a1a1fbb0e0d4bc186f35f7961a7ad0b9ec4fef1cc01c5624bb1507. It uses the qualified public Future v5 and typed-structure cleanup v5.

All final suites ran on that same image:

- 23 original behavior comparisons, including exact exception classes and text, closed/capacity order, invalid keys, cycles, depth, unsupported numeric/byte values, Unicode, the default 4300-digit conversion policy, the queued-node boundary, and actual accepted 139000- and 262130-node payloads.
- Six control groups and 22 submit calls: nine actual owner allocation failures, three actual dependency allocation failures, 39 private envelope/view/PID/lock controls, and nine real threads competing for exactly eight outstanding slots.
- Four ownership groups and five submit calls: real kernel ENOMEM in public Future creation and retention, accepted-job quarantine without effect replay, and the complete 100001-digit job counter.
- One retained typed cleanup group and five calls, using fresh output buffers and real failed reference releases. Only failed references were retried, and the final value context had no leaked references.
- 29 actual native packer controls, including exact generated object bytes, original per-policy 4 MiB boundary, workspace/output boundaries and atomic malformed-frame refusals.
- Two independently captured native policy compiles with byte-identical output.

The readably generated HIA has 91 functions, 887 blocks and 5306 operations within the existing compilation profile. Earlier failure evidence is retained, including a wrong Future fallback-field consumer, a retry observer that expected another pass after all releases had succeeded, and the adapter's repeated-cleanup loop fixed before final qualification. The latter changed product source; the observer correction alone was not treated as evidence of product closure.

The qualification JSON records exact source, image, construction and report hashes. No whole BackgroundOptimizer, final release or production activation claim follows from this component.
