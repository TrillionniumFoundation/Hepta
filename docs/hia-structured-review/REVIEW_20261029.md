## Conclusion and exact scope

No blocking issue was found in the examined final finite editing profile at
`677a15928c1dd3b236c7bee8cf4b3e6041177f6c`, tree
`a4c78f0c6430b9ff0cec2025289c13de639de1e2`, after four concrete boundary
defects found during review were corrected. This review covers the four-file

The implementation remains in
`experiments/hia_agent_structured_v7_20261029/{editing,rust_syntax,session}.py`.
HIA applies the existing production whole-Core verification APIs. Rust first
creates a syntax proposal, then must pass the unchanged finite source admission,

observations. Only after success and receipt retention does the in-memory project
revision advance. Candidate files retained for compilation and audit are not a

## Defects found and closure

| Boundary | Failure found | Fix and evidence |
| --- | --- | --- |
| Concurrent source revisions | In pre-`e5b0766` development, two same-base requests could both validate and the later commit could overwrite the earlier result. Query/validation/commit had no shared lock. | `e5b0766` serializes `files`, `revision`, `query`, and the complete `apply` transaction with an `RLock`. An event-barrier mock compiler test checks that only the first request compiles, while the second refuses the stale revision. Receipt-write failure also leaves the source unchanged. |
| Parser depth | In frozen `e5b0766`, `else if` recursively called `prefix()` without increasing the expression-depth counter. The stated depth-64 bound could be bypassed before later source admission. | `a22d6fe` brackets that recursion with the same depth budget and adds bottom-up AST-depth checking for iterative postfix/left-associated construction. Pure parser controls admit depth 64 and reject 65 for else-if and postfix examples. |
| Native execution before admission failure | In frozen `e5b0766`, `native_built=True` alone triggered execution. The existing builder sets that flag before checking compiler identity; identity drift can produce `native_built=True` together with `infrastructure_failure`. The transaction would execute before refusing commit. | `a22d6fe` requires both `status == compiled` and `native_built` before any native call. A mock of the actual inconsistent-build state asserts `execute` is not called and the revision is unchanged. It does not tamper with a real compiler installation. |
| Commit after a caught metadata failure | In frozen `a22d6fe`, `admitted_files` was set before computing the candidate revision and receipt fields. A caught exception at that later step left the flag set, so a transaction recorded as rejected could still update the source. | `677a159` prepares the revision and receipt fields before setting the flag. Every caught exception clears it and resets acceptance/revision fields; commit additionally requires `accepted is True`. A post-execution candidate-digest fault control verifies the failure receipt and complete original source stay consistent. |

## Reviewed authority boundaries

**Complete query and current source.** Both response envelopes bind the actual
complete project revision and complete query digest. The trusted host supplies
the editable symbol/function scope and the preserve/migrate policy. The adapter
reconstructs the query from the current captured source and compares the entire
catalogue; a model cannot authorize another node by editing its query, fields,
scope or hash. All eligible nodes are derived from source, without selecting
correct nodes or using reference answers. Unknown, duplicate, readonly and
overlapping Rust selections refuse. ASCII source makes stored positions actual
UTF-8 byte positions; CRLF bytes are preserved and Unicode is explicitly refused.

**HIA editing.** Ordinary edits of supported fields on output-bearing operations
call production `prepare_batch` and `apply_batch`. Other instruction and
terminator changes use production `apply_program_patch`. For signature,
block-parameter, insertion and deletion actions, the adapter rebuilds affected
function containers from the original snapshot and exactly the selected changes.
It records that rebuilding and submits the result to the explicit production v2
patch API. It does not automatically change entry parameters, calls, SSA uses or
return types to make an incomplete edit valid. The model supplies no whole
function definition, and the whole module is reverified once the proposed
transaction is assembled. The examined session uses verified primitive v6 Core;
this review does not qualify every other schema accepted by generic helpers.

**Rust syntax and signatures.** Expression/type fragments must be completely
consumed by the bounded finite parser. The replacement bytes are used verbatim;
the host inserts no casts, parentheses, replacement bodies or answer code. The
complete candidate is reparsed, and every unselected expression/type span,
shape and operator anchor must remain. A fragment that changes an enclosing
operator's precedence is refused and requires explicit grouping. Comments,
strings, attributes, macro definitions, dollar metavariables, closures and
general Rust declarations are outside the profile; only the disclosed `vec!`
form is parsed. The existing v6 primitive-parameter `into` gate still applies.
Signature types are readonly under `preserve`, policy is bound into the query,
and the actual parsed candidate signature is checked again. `migrate` permits
explicit type edits; it does not prove external ABI compatibility.

**Validation and feedback.** Failed source admission, compilation, public
semantics, resource observations, artifact identity, or final receipt retention
cannot advance the session revision. Successful native execution is required
before commit. Hidden observations occur only in the external engineering
control runner after acceptance, with separate records, and are never session
repair feedback. Existing v4/v5/v6 source files were compared with the prior
`f695384324d2de784f727d349bd67891f7f45bd3` tree and are unchanged. No prior
experiment was rescored.

## Independent evidence checks

The independent audit used standard-library JSON, hashing and Git reads. It did
not import or invoke the editor, VM, test suite, native compiler, native image,
or model. The retained `review_source.py` records this read-only procedure.

It checked all **158 final source bindings** against exact Git blobs, the
producer's retained source snapshot and the current frozen checkout. It checked
the same Git/snapshot relationship for both earlier runs. It recomputed both
query digests, checked serialized response identities, and reconstructed the
actual written candidate's complete four-file revision from its files. Accepted
revisions match those files. HIA editor-Core and native-Core hashes match their
respective representations. The actual seven compiled native artifacts in each
of the three runs match the producer's image hashes. Compiler binaries themselves were not
freshly rehashed by the reviewer; the producer records stable compiler/tool
identities and the compiler remains part of the trusted toolchain.

The final producer's **51/51 tests, zero skips** include 21 new structured-editor
tests and 30 existing profile/transport controls. Their raw log digest is
`9fe273eecb0a7aa63a0722454e5e38696608c9815f1925bcb0310e91f7dfcf14`.
Mocks of concurrency, receipt failure, candidate-digest failure and failed
compiler identity are explicitly unit controls, not native execution.

The final **9/9 engineering controls** consist of **five accepted transactions
and four intended refusals**. Seven cases have public native observations; the
five accepted cases have separate terminal hidden observations. The stale
revision control performs no build, and the moved-owner failure is rejected by
actual rustc before native execution. None is a model-produced answer or an
Agent-success count. All three runs retain zero model requests and
zero main-experiment cells.

Full per-file bindings, query/response/transaction hashes, actual artifact hashes
and case classifications are in
`experiments/hia_next_safety/structured_review_20261029/REVIEW.json`. Original

`-02` and `-03`, with their exact source commits recorded. No source or result was
changed during independent capture.

## Limits that remain

The HIA editing base must already pass Core verification; this adapter does not
repair arbitrary malformed or ownership-invalid HIA source. Rust accepts only
the disclosed syntax, not general Rust or Unicode. The session and compiler
controls establish this tool boundary and the observed examples; they do not
prove hidden functional correctness for all inputs, backend refinement, general
resource release under every host failure, or long-term production maintenance.

A future Agent comparison still requires an explicit task-eligibility policy
and preregistered equal model, context, generation, tool-call and repair budgets.
These no-model engineering controls provide no productivity or language
superiority result. The environment is shared cloud scratch, not verified user
dot or a physical platform attestation.
