# Isolated structured failure and versioned policy

Stage B after CLI closure audit #634 (86917cac99ac55a3ce89a8904e094904545defff). This is a new explicit `experiments.policy_failures.owner.Owner`, composed from `package_copy.Owner` and its context/operations. No production imports, command adapter, CLI selection, default change, native execution, publication, overlay or sandbox claim.

## Policy

`Policy(version='loader-experimental-v1', limits={...})` accepts an exact dictionary of overrides. Unknown keys, unsupported versions, bools, non-integers and nonpositive values refuse during construction; the existing parser-depth ceiling remains 96. Values remain experimental defaults, not calibrated production recommendations. `limits` and `units` are immutable copied mappings with exactly the same 33 keys as the complete inherited Package Limits dataclass. Each field has an explicit unit in the policy. Per-file role bytes, cumulative returned bytes, read invocations, graph/path/inventory admissions, absolute depths, token/parse admissions, AST constructors, grammar appends, unfolded copies, transforms, authority maps, shallow fields and projected Package deepcopy calls are distinct.

The reader derives `per_file=max(source, manifest, lock, sidecar, header)`, inherits total_bytes and reads, and uses the existing fixed `chunk_bytes=65536` OS read request cap. All four reader settings are snapshotted as exact integers too. Replacing equal-valued context/reader Limits or mutating their dataclass storage refuses before reads. Policy version/value/unit drift and replacement checkpoint/reader observer bindings refuse; checks surround callbacks. Foreign substituted values are type-rejected without invoking their equality or iteration protocols. This is finite ordinary-process integrity checking, not hostile reflection, code mutation, tracing or concurrency isolation.

## Failure contract

`context.failure` is initially None and then one immutable `Failure`: category, phase, dimension, limit, admitted, attempted, observed_bytes and observed_reads. Origin sites supply metadata explicitly. There is no string matching/parsing classifier. Existing experimental `Context.reject` accepts and ignores optional metadata, retaining its original Rejected type and string. Existing owner behavior remains unchanged. Only the new profile raises its structured Rejected subclass with `.failure`; later terminal rejections refer to the same record. No exception, traceback, input bytes or filesystem path is retained in the record.

Count failures report already admitted count and proposed cumulative count. Depth failures report `admitted=None` and absolute attempted depth, never pretend depth is a cumulative counter. Reader stat-size refusals before reading report projected file bytes, not bytes read. Growth refusals report progress admitted before the rejected chunk and proposed bytes including the overflow sentinel. Aggregate-vs-role ties deterministically attribute to total_bytes. Actual OS-returned bytes (including sentinel) and read invocation count are separately snapshotted. Reads increment before open; an exhausted next read does not increment or open. These are admission measures, not allocation/CPU bounds.

Categories distinguish budget, unsupported_runtime, schema (including cold/partial Path), replacement_hook, thread, reentrancy, cancelled, interrupted, memory, recursion, io, diagnostic, policy_drift and unexpected. Only explicit `Cancelled` is cooperative cancellation. KeyboardInterrupt is interrupted; SystemExit and arbitrary callback errors are unexpected. Checkpoint OSError/TimeoutError is unexpected rather than filesystem I/O. MemoryError and RecursionError never become quota exhaustion.

The first originating refusal wins even when a callback swallows it or cleanup raises a different exception. Cleanup still releases the reader lock. Public exceptions/diagnostics remain original where the legacy boundary produces them; an I/O failure may remain an original HeptaError or unchanged=False while the new owner is terminal with the earlier io record. New owner operation boundaries record otherwise unclassified exceptions without replacing them.

## Coverage boundary

All inherited composed quota rejection origins have explicit dimensions. Role limits flow through the effective reader cap, retaining the original stricter role across later read/digest requests; cumulative counters and Package preflight remain on one context. Unsupported runtime is rejected at new-owner construction before callbacks or path conversion. Later Package schema/hook checks retain their original ordering.

I/O source provenance covers Reader open/fstat/read/close and the composed operations' path checks, lexical read bindings and lazy inventory iteration. It is not blanket instrumentation of arbitrary production internals or user/runtime hooks. The record of an otherwise escaping diagnostic identifies the boundary, not an invented deeper origin. Direct calls to private helpers outside an Owner operation are not a comprehensive exception-observation API. First-origin tracking does not authenticate public AST mutation, refresh Hepta.lock on unchanged, create an atomic filesystem snapshot or account for frontend/native work.

## Validation

Tests cover all policy fields, generic/specialized quota thresholds, sticky terminal state, policy drift, swallowed reentrancy, actual read counts/bytes, stat/overflow/tie attribution, multi-chunk growth, first failure surviving close failure, I/O before swallowed revalidation, lazy inventory, runtime pre-I/O, hook/schema/thread distinctions and explicit exception categories. New-profile parity covers all 80 examples (68 graphs, 12 unchanged diagnostics), source bytes/AST/reports and same-ledger revalidation; real locked package tests preserve stale-lock diagnostics and late-lock/inventory semantics.

`compare_legacy.py --baseline BASE --candidate CANDIDATE` independently compares 813 prior-profile default/low-limit valid/malformed/missing-input outcomes, including exception/diagnostic/counter/reader/terminal observations. Hosted workflow runs Python 3.11 and 3.12, checks exact source against #634, binds Rust 1.90.0 and GCC for inherited consumer checks, and runs the existing direct parser/normal-loader differentials. Native tools here validate inherited behavior only; they are not activated by this profile. Passing these controls does not claim complete adversarial coverage or unblock stages C/D automatically.
