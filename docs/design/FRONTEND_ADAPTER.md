# Isolated owner-preserving frontend check

Stage C, based on Stage B #635 at `a300184277d931c596ca592412557d6f36482492`, tree `071a01f97446e57795bdb0b50b3b58efa4b3a343`. All inherited files remain frozen. This adds only `experiments/frontend_adapter`, this design and its workflow. No production import, CLI selection/default, native operation, artifact publication or overlay support is activated. Stage D remains separately reviewed work.

## API and allowed configuration

`FrontendRequest(policy=Policy(), config={'locked': False}, checkpoint=callback)` constructs a one-shot request on its owning thread. The actual omitted policy default creates a fresh Policy, not a shared default object. `request.check(entry, source_overrides=None)` returns the ordinary `pipeline.Analysis`. `request.cancel()` sets this request's cooperative cancellation event and is the only cross-thread operation supported.

Configuration is validated before owner construction or input I/O. Only an exact dictionary with optional `locked` of exact bool type is accepted. Unknown keys are rejected, even with a None/False value. In particular native, backend, compiler, target, crate, optimization, output, command, build, run, emit, header, patch, import-C and source override options are unsupported. Invalid configuration raises TypeError/ValueError. Every non-None `source_overrides`, including `{}`, produces a structured schema refusal before entry conversion or reading. The dictionary is copied into an immutable mapping; later caller dictionary edits have no effect. Request config identity/value and policy identity are pinned around callbacks, alongside the inherited complete Policy snapshot checks.

## Owner, ledger and lifecycle

One structured Policy Owner is created before the entry argument is supplied. The adapter passes the raw entry object/spelling directly to `Owner.load`, without Path construction, normalization, resolution or reloading. It retains that owner's exact handle and ordinary public graph throughout source decoding, real `pipeline.analyze(source, str(project.entry), loaded_project=handle.project, native=False)`, and final `handle.unchanged()`. Owner, context, operations/context and reader identities are pinned. A replacement is terminal; no replacement ledger is operated. Binding drift records original reader observations, not counters from the replacement. No `analyze_project`, public `load_project`, or public `graph.unchanged` fallback is used. There are no runtime monkeypatches or global contexts.

The lifecycle is new → running → finished. Success, ordinary diagnostic result and exception all finish the request. A second check after success produces structured `lifecycle` failure without more I/O. A first originating failure remains the identical immutable Failure on later checks. Reentrancy, even if swallowed by a callback or analyzer, poisons the request and prevents return of a partial successful result. Wrong-thread check fails before path conversion or I/O; a worker must construct its own request on its own thread. Owner/context/handle remain visible for experimental auditing, not as an adversarial in-process security boundary.

Original escaping exceptions retain their types and identities. The adapter records otherwise unclassified escaping exceptions using the inherited categories. Returned checker diagnostics are ordinary pipeline outcomes, not a claim about the chronological first exception: they do not close admission before final validation and do not create an artificial Failure at completion. If final owned revalidation returns False, append the exact legacy `E_MODULE_RACE` diagnostic and set rejected/ok=False. If that False swallowed an I/O exception, preserve the original io Failure and return the legacy race report rather than turn it into a new thrown terminal exception. Other terminal failures never become returned success. Successful and ordinary diagnostic outcomes can therefore have failure=None even though their lifecycle is finished.

## Cancellation and final observation

Checkpoints surround loading and synchronous analysis and occur within inherited loader operations. The request checks its event both before and after the caller callback. Cancellation before load uses no reads; cancellation while analyze runs is observed after that call returns. The synchronous checker, emission, compiler-source hashing, source decoding and all other frontend work are unmetered by this profile. There is no command-wide CPU/memory bound, cancellation-latency bound or preemption claim.

After final handle revalidation the adapter performs a no-callback finish guard: binding/policy drift, terminal failure and cancellation event are checked without executing another caller callback. This avoids adding a known post-validation arbitrary callback window. The owned revalidator itself contains cooperative checkpoints and reads are not atomic filesystem snapshotting. Arbitrary callback mutation, hostile threads, tracing, private-reflection/code replacement and filesystem changes after observations are not fenced by this experiment. The final result checks the inherited observed source/package snapshot, not immutable files or a publication authorization. A cancel arriving after the final event observation or returned completion is not retroactive. Late cancel does not alter the prior result or other independent requests.

## Reports, locks and limits

The real pipeline performs checking and pure source emission/hash computation. Existing source/compiler/interface/generated-source hashes, diagnostics, project report and `Analysis.project` semantics remain unchanged for the admitted class. Successful status is `frontend_only`, never native-qualified. No compiler or subprocess is invoked by the adapter, and it has no output-path/artifact-writing option. Pure `emit_rust` and declaration validation with `emit_header` are retained parts of frontend checking, not publication.

Initial locked=True uses the existing admitted lock verification. Final unchanged does not freshly authenticate `Hepta.lock`; a lock-only late edit may still pass. Source changes, alias retargeting and package inventory changes retain legacy race semantics. Public maps cannot replace private snapshot authority; mutable public AST is not authenticated. Final reads, bytes and other loader costs consume the same cumulative ledger with no retry or fresh owner. Policy values remain experimental, not calibrated production defaults.
