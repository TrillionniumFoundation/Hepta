# Store artifact/profile delivery custody

The Store artifact/profile adapter uses the shared `DeliveryRecord` mechanism
for its actual native calls and foreign-effect observations. HIA still owns
the original eight methods, their eight argument continuations, and the same
138 ports. This change does not alter the HIA graph, generated source, protocol,
literal provider calls, retained method bodies, input domain, or original limits.

Source declarations describe implementation. They do not confer native, cold,
installed-worker, or whole-project qualification. Actual run reports must bind
the final source, compiler, images and unchanged original tests.

## Confirmation and refusal

The adapter reserves shared custody and its existing frame custody before its
first native handoff. A safe failure before that handoff can retire the shared
reservation. An actual initialization handoff whose receipt is lost retains
the frame even when no foreign effect has started.

For each native call, packet preparation precedes `enter_native()`. The actual
entry is followed by all existing canary, state, nonce, sequence, phase and
extent checks. Receipt construction and a final sticky-loss check precede
`confirmed()`. Only phases 4 and 5 are terminal; phase 7 continues after an
original suppressed exception.

Every foreign port runs in a shared activation. Returning or raising records
an observation that still needs the original native ACK. A child loss that an
explicit callable swallows or replaces remains sticky: neither event 2 nor
event 3 may confirm it. The original active-exception handler still drives
`__exit__`, close and unlink, preserving `sys.exception()`, bare reraising,
replacement context and suppression behavior.

An ambient activation covers implicit object release between ports without
inventing an ACK obligation. It follows actual same-process, same-thread
activity. A previously prepared frame does not adopt an expired construction
scope; copied contexts and forked processes do not transfer creator authority.
The original Store guard rejects a foreign creator before entering a shared
scope, preserving its owner-specific exception class.

Ordinary foreign exceptions remain ordinary when no delivery was lost. A
fully confirmed child followed by a foreign error is not a lost child receipt.
After an actual loss, only the original six request-rejection families are
normalized to the Store unknown class. Foreign `MemoryError`, other
`RuntimeError` objects and process-control exceptions preserve their identity.
The separate classifier inside the actual native-call boundary is unchanged.

## Independent controls and retained gates

`StoreNativeDeliverySourceTests` has three source controls. They bind the
published c019 originals, preserve 89 original files and 21 adapter definitions,
retain the complete 50/130/128/152 inventories in their original scopes, and
bind the separately frozen shared-delivery dependencies. The only permitted
old-test adjustment remains one exact helper-registry count literal; all other
bytes must match their frozen source.

`StoreNativeDeliveryNativeTests` has eight methods. Its disposable children
cover 72 Store/peer frame loss combinations in both directions; actual literal
child calls and active-exception cleanup; safe pre-entry versus real init
receipt loss; confirmed-child and genuine foreign-error controls; observation
storage `MemoryError`; actual later ancestry, implicit release, thread and
fork boundaries; both request journals; and installed workers.

The installed controls build a fresh wheel and use the actual worker with a
fixed Store/context/native-journal bundle. A real Store artifact INSERT invokes
the admitted context arithmetic image, whose actual result is then lost. The
controls distinguish swallowing, domain-error replacement, normal completion,
and a process exit after the real peer entry. They retain request rows,
artifact bytes, costs, replay results, natural exit codes and exact package
hashes. Startup entries and request entries are recorded separately. The child
forbids authoring/test imports and the retained Store and request bodies. An
appended-LF packaged-source change must refuse before native execution.

These new controls do not replace the original Store Source3/Native8, its 463
original traces, 41 dynamic-limit cases, 160 literal cases in both modes, six
full-buffer VM cases, original exception/worker controls, or the complete 130
caller gate. The original lifecycle 50, separate 128 and D0-D3 component 152
inventories retain their own selectors and prerequisites. A joint-cold-only
original fixture cannot be relabeled as development.

Choose exactly one nonempty input:

  cold report.
- `HEPTA_HIA_STORE_NATIVE_DELIVERY_DEVELOPMENT_COMPILER` for an explicit

`HEPTA_HIA_STORE_NATIVE_DELIVERY_EVIDENCE` names a new evidence directory. An

component command is:

```sh
python -B tools/run_hia_unittest_gate.py tests.test_hia_store_native_delivery
```

Custody is written as `hepta.hia.store-native-delivery-custody.v1`; child
observations use `hepta.hia.store-native-delivery-child.v1`. Source, compiler,
cold reports and all built bytes are checked before and after. Unknown owners
stay alive until their disposable process exits; no control clears a registry
to manufacture cleanup or success.

## Remaining boundaries

The native artifact provider's subprocess handoff, durable effects and return
receipt remain D5. A known exit code or `PublicationRejected` exception is not
proof that no effect happened. The D4 fixture provider remains distinct from
that real subprocess protocol.

The worker's later independent `service.close()` is not automatically linked
to an already exited request scope. Retaining an unknown frame is not proof
that another explicit call cannot close its database. D4 adds no global
resource lock or cross-call resource association.

An opaque provider can continue inside its own invocation after swallowing a
child error. The shared guard stops the next ACK/port and an ordinary terminal;
it cannot prove that arbitrary internal provider actions did not occur. The
original literal SQL and method-binding expressions remain unchanged.

Those three boundaries, other unintegrated native providers, and whole-stack
delivery qualification remain explicitly open.
