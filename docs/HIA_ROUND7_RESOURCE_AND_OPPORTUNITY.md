APIs retain their own versions. A caller-owned root remains live while a callee

## Prospective opportunity protocol

The exact protocol was published before native performance observations in
[registration commit `18be73e4`](https://github.com/TrillionniumFoundation/Hepta/blob/18be73e4bb42063d3f78c506cd2ec6c37226b47d/experiments/hia_guarded_opportunity/protocol_v1.json).
Its byte SHA-256 is
`1b4d1818d7fa9aff079bf7b27220d9f4df2bc0668a52b827e8a0adbd1b8cebbf`.
The implementation verifies this identity before running it.

The separate profile is `calculate(u32, u32) -> u32`, computing checked quotient
and remainder followed by wrapping addition. An executable equality guard
specializes the denominator to 8 or 10, with the complete generic fallback.
It does not widen the existing `full_lifecycle(usize, u32) -> u64` prepared
session. The same existing proof engines must prove every candidate before
native compilation, including first specified traps. The native driver and
library execute from internally checked sealed images in bounded child calls.

The fixed synthetic horizon is 100,000,000 calls per module, with two distinct
90-percent hot-denominator distributions, seven training seeds and seven
independent validation seeds. The three candidates each receive the complete
registered sample inventory. An actual function-code hash, excluding ELF
metadata, distinguishes useful candidates. Timing samples are retained without
trimming or retries. The full measured generation, proofs, compilation,
qualification, sampling and release cost is charged before assessing savings.
Fresh-child startup/loading/guard/cleanup are part of the prospective batch
comparison, not a free future reuse assumption.

At least two module-specific candidates must have positive conservative
observed savings in both phases after those costs, within the declared study
budget, before a separate one-slot controller comparison is informative. This
slot limits selected specializations; the qualification actually builds the
whole common candidate bank. It is not a claim to have compiled one candidate
online. The declared demand is a research scenario, not a real application
trace. The observed minimum/maximum envelope is not a statistical confidence
bound. A failed proof is a qualification failure, not an economic negative.

The development record retains a 5-second proof timeout for guard10. The
existing solver later proved that exact query UNSAT in 5.587 seconds under a
larger diagnostic ceiling. This closed batch profile uses the same 10-second
per-query ceiling for all candidates and charges actual time within the fixed
60-second study acceptance budget. No common proof grammar or admission rule
was relaxed. Budget checks occur between individually bounded operations;
this is not a hard real-time global preemption guarantee.

The historical constant-fold NDU cohort produced identical machine code and
six `stop` choices. Its costs, the older prepared-reuse negative results, and
the adaptive/owned-state negative forecasts are not overwritten. This
increment cannot declare a new NDU benefit merely because a different native
candidate exists. See [the native opportunity contract](HIA_GUARDED_U32_OPPORTUNITY.md).

CI profile. The other full qualification profile is retained. Native host
workflows keep their existing seven C/ABI and seven C++ library-reuse profiles.
The two new application qualifiers execute from a fresh exact-source worktree
and retain outputs outside that inventory. Both verify all tracked raw bytes
and executable modes against their expected commit before and after execution. Failed
stages and old observations retain their own source and protocol identities.

This source document describes implementation and acceptance rules; it does
not predeclare results of not-yet-completed CI or timing campaigns. Local
focused cohorts, full discovery, canonical selectors, Rust crate tests, native
call counts and independent audit cases have different, overlapping
denominators and must not be added together.

## Remaining research goals

Whole-language preservation/progress, source/native refinement, arbitrary
C/C++ migration, automatic foreign pointer contract inference, concurrency and
async unwind, universal performance superiority over Rust, profitable general
hot replacement and global instruction optimality remain unproved. NDU keeps
proposal/advisory authority only. Resource legality, behavior preservation,
native identity, measured cost and publication are separate decisions.
