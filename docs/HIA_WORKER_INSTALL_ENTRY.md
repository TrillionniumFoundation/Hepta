# Native Worker installation entry

`hia-worker-install` is the installed HIA command that captures a source tree,
compiler, cold report, Store package, and optional runtime configuration, then
calls the native Worker installation owner. It uses the same reviewed syscall
adapter and authoring renderer as `hia-release-build`; the release entry's
generated bytes remain unchanged by the renderer parameters.

```text
hia-worker-install --output PATH --compiler PATH --cold-report PATH \
  --package PATH --package-sha256 HEX [--source ROOT] \
  [--timeout-seconds SECONDS] [--artifact-root PATH ...] \
  [--runtime-config PATH]
```

`--readonly-artifact-root` is an alias for `--artifact-root`. Their occurrences
share one ordered list. The command accepts at most 32 roots, including relative
paths and an empty path. Before framing them it applies the lexical behavior of
POSIX `Path`: an empty path becomes `.`, repeated separators and single-dot
components collapse, `..` remains, and exactly two leading slashes remain two.
The Worker owner resolves the resulting effective roots against the filesystem
and performs the directory and final binding checks. This lexical conversion
does not authorize a root or substitute for those checks.

The source defaults to the current directory. The timeout defaults to 3,600
seconds and accepts 1 through 604,800 seconds. The output name must be absent
under an existing admitted parent. Package SHA256 is exactly 64 lowercase hex
characters. A package is a nonempty regular file of at most 512 MiB. Configuration
capture has no fixed file-size ceiling: both package and configuration bytes are
hashed and copied in 64 KiB chunks, with file observations checked before and
after capture. Configuration input follows symlinks as the previous configuration
reader did. It is then handed to the owner as an immutable descriptor; the CLI
does not parse or reinterpret JSON.

## Native build and binding

The command is a two-object product containing `worker_install_entry.hepta` and
`sha256_stream.hepta`. Its packer is `worker_install_entry_packer.hepta`, using
`HIAENPK1`. The admitted source alias is `hia-worker-install.hepta`.

`worker_install_entry_bind.hepta` is built through the native source KIT and
accepts `build` with `HIAENBD1`, four raw 32-byte SHA256 pins, and the unbound ELF.
The pins identify the neighboring physical files in this order:

1. `hia-worker-install-owner`
2. `hia-subprocess`
3. `hia-source-build`
4. `hia-source-capture`

The binding record is `HIAWEMT1`. The installed entry opens and verifies these
capabilities before starting the owner. Unbound or mismatched entries fail
closed. The Store owner builds and binds the entry after publishing the owner
and other three capabilities, so an unbound command is never a final Store
member.

## Sealed owner request

The owner is executed with `argc == 1`. Its standard input is a sealed memfd
with all four standard seals (`F_GET_SEALS == 15`). All integers below are
unsigned little-endian 64-bit values. The complete frame is at most 2 MiB.

| Offset | Content |
| --- | --- |
| 0 | `HIAWIN01` |
| 8 | Parent PID |
| 16 | Monotonic deadline in nanoseconds |
| 24 | Source directory descriptor |
| 32 | Stage directory descriptor |
| 40 | Work directory descriptor |
| 48 | Subprocess runner descriptor |
| 56 | Source-builder descriptor |
| 64 | Source-capture descriptor |
| 72 | Compiler descriptor |
| 80 | Cold-report descriptor |
| 88 | Output parent directory descriptor |
| 96 | Output directory descriptor |
| 104 | Output-name byte count |
| 112 | Source-inventory byte count |
| 120 | Ordinary-member count; the public entry sends zero for the exact plan |
| 128 | Five raw SHA256 pins: runner, builder, capture, compiler, cold report |
| 288 | Output name, then exact `HIASPI01` inventory |

The inventory is followed by a 64-byte options header: `HIAWOP01`, package
descriptor, root-frame byte count, configuration-present flag, and raw package
SHA256. The root frame is a count followed by repeated `(length, UTF-8 bytes)`
records. Each normalized path has 1 through 4,095 bytes. Order and duplicates
are preserved.

When the configuration-present flag is one, the roots are followed by a 48-byte
record: `HIAWCF01`, configuration descriptor, and the SHA256 observed during
capture. When it is zero, this record is absent. There are 11 distinct input
capabilities without configuration and 12 with it. They include five directory
capabilities; executable/data capabilities, package, and optional configuration
are sealed. Unrelated inherited descriptors are not passed to the owner.

## Lifetime and failure behavior

The HIA policy owns opening, hashing, capture, descriptor inheritance, child
creation, waiting, and output cleanup decisions. The mechanical assembly only
carries process arguments and performs the requested syscalls. The child has a
parent-death signal and is reaped on the tested failure paths. A failed entry
removes only its own still-empty output directory with matching identity. A
replacement directory or a directory containing published data remains intact.

The owner is responsible for full cold admission, same-source Store
reconstruction, package equality and installation, Worker construction, native
controller installation, configuration binding, and final publication. A
successful CLI component check alone is not evidence that those stages passed.

## Reproduction and component qualification

Run `python3 -B -m tools.generate_hia_worker_install_entry --check` to verify the
checked-in HIA sources, and run the corresponding release-entry generator with
`--check` to verify that the shared renderer still reproduces the release entry.
These authoring tools are outside the installed runtime path.

`tools/qualify_hia_worker_install_entry.py` accepts explicit paths for the
unbound entry, binder, runner, builder, capture tool, and compiler. It builds an
external native fixture owner and exercises the real bound command with an
empty `PATH`; it does not replace the final complete-owner acceptance gate.

The 60-case component qualification includes argument order and defaults,
sealed execution, descriptor isolation, all 32 maximum-length roots, Unicode,
duplicates, aliases, relative/empty/POSIX-normalized roots, configuration through
a symlink, and configuration larger than 64 MiB. Refusal and lifetime cases
cover wrong capability/package pins, malformed options, unsafe input types,
existing/replaced/nonempty output, owner rejection and signals, and parent death
with the owned child reaped. Request bytes, seal values, file identities, and
inherited descriptor sets are inspected independently by the fixture.
