# Agent emission coordinator

This explicit owner moves the control flow of `HIAAgentService._hia_emit`,
`_compile`, and the shared signature policy into one retained HIA image.
Selection uses `HEPTA_HIA_SERVICE_EMISSION_MANIFEST`. The default path and the
three original reference bodies remain available and byte/AST guarded.

## State and effects

The image accepts the existing six-argument byte ABI. A 64-byte request names
one 128-byte retained state, its random instance identity, monotonic sequence,
mode, event, observation, and the actual CPython local-layout profile. Version
2 uses the previously reserved final request word for profiles 312, 313, and
314; a different profile on a later request is refused. A successful response is 144 bytes: a fixed
16-byte header followed by every byte of that state. The bridge checks the
complete response, actual retained buffer, exact integer fields, identity,
process, thread, and the precise issued receipt object before a foreign effect.

The three public modes are emission, compilation, and signatures. Four internal
modes implement a context-manager body and the three original generator
expressions. HIA chooses each lookup, call, condition, next operation, yield,
cancellation, cleanup, and completion. A foreign effect is preclaimed before
entry and acknowledged only after its real return. An interrupted claim,
effect, or acknowledgement remains an unknown operation, with strong state
custody and no retry grant. A known exception has a separately consumed native
delivery permission.

The compiler path retains the order of actual machine emission, temporary
directory entry, output path construction, deadline observation, real linker
call, file read, directory exit, exact build metadata checks, and object
publication. The outer path then computes signatures, publishes the native
artifact, and publishes the build receipt. A failure after object publication
does not roll back or invent removal of that original effect.

## Interpreter mechanisms and retained dependencies

Python performs fixed foreign object operations and retains their real identity.
The literal `with` mechanism is preserved: actual special-method binding,
`__enter__`, the original exception triple, `__exit__`, its truth observation,
and suppression use the running interpreter. Its body drives a separate HIA
mode; it contains no foreign emission policy. HIA also preserves the late
`UnboundLocalError` when an exit method suppresses failure before an original
local was assigned.

Each original generator expression has a real Python generator whose only
loop is native `drive → take → yield`. HIA owns iteration and the boolean
policy. This preserves actual interpreter PEP479 conversion and traceback
custody of original iterator/target locals. Generator comparison results are
transferred at yield, so the two distinct truth observations in `and` followed
by `any` remain observable. Error traceback locals are not discarded as if
they were ordinary expression temporaries.

The public facades transfer arguments through fixed normal-call operand pops,
and the native entry transfers each named parameter into its retained state
before driving the image. Neither a forwarding tuple nor an extra parameter
local retains a caller object through the original function's return.

HIA version 2 owns a separate terminal retirement continuation. It accepts
event 7 only after the exact return or original-error permission has been
consumed. Each original named-local slot is issued, preclaimed, and then
acknowledged separately. The HIA table uses the original `co_varnames`, cells,
and free variables: ascending for the reviewed CPython 3.12/3.13 layout and
descending for 3.14. Original inlined-comprehension slots and generator cells
are included. The ordinary context-manager body shares the parent's local
scope and cannot acquire an independent retirement permit.

Normal return retires while the actual result is still held. A confirmed error
keeps the named locals on the real traceback; the state finalizer enters the
same retained HIA continuation when that traceback releases it. Closing the
service blocks new business operations but does not revoke that already-held
retirement capability. An interrupted claim or acknowledgement retains the
state and remaining locals without a replay grant. No GC call or rewriting of
the original exception chain is used. Other interpreter families and minor
versions are refused by this explicit owner before image use; the default
Python route remains available.

An exception can be handed to another thread and its final traceback reference
can disappear there. Only the already-consumed terminal retirement capability
is acquired on that physical releasing thread; the original PID remains bound.
Business continuations keep their original creator-thread check. The retained
state registers an exclusive retirement lease before calling its image, so two
holders of the same exception do not create two retirement operations. The
frozen first version-2 bridge incorrectly reused its business-thread check here;
the original two failing observations remain separate from this correction.

The existing verifier, machine emitter, linker, file and artifact providers
remain dependencies. Clock access and foreign numeric/operator protocols are
hosted physical operations. The shared HIA-produced exception-delivery shim
uses the actual CPython exception ABI. This component is not a replacement
for those providers, an independent compiler proof, or a claim that the whole
stack is native HIA.

## Image and proof custody

A new service performs fresh manifest, HIA source, and image admission, then
retains the admitted immutable mapping and exact manifest/source bytes. Later
environment or pathname changes cannot switch that service's executable.
The existing held-checker capability carries this actual image to both proof
production and consumption. It is not an ambient Core-checker selector, and a
serialized proof cannot manufacture this capability. The explicit worker
bundle must separately admit this helper; no ambient fallback is added.

The strict builder requires the complete matching current-source cold report,
the original 180-second qualification plus 3-second cleanup limits, exact
compile receipt types/status/encoding, and readback of source, image, receipt,
manifest, and report. The mutually exclusive development entry accepts an
explicit retained compiler and records only component development. It does
not confer current-source cold authority.

## Controls and qualification boundary

Source controls retain the original function fixture and independently regenerate
the HIA module. Adapter controls use explicitly named transport doubles.
Native controls execute the selected image, compare full output/state bytes
against the independent Core VM, and preserve actual original/native object,
exception, and callback observations. Real linker/filesystem/store controls
are separate from the controlled-provider observations. Installed-wheel
controls must include all five existing discovery/native/source-build/
compiler-build/publication resource groups.

The source-owned `tools/qualify_hia_service_emission.py` gate accepts either
`--cold-report` or an explicitly named `--development-compiler`, together with
a new exclusive `--evidence` directory. It loads the original four Agent test
modules in their retained 30 + 5 + 12 + 1 order, checks their exact file hashes
and all 48 IDs, and poisons the two retained service methods and the original
signature function only in the test process. Child processes inherit the
explicit selector. Every public and internal mode must have actual mapped
machine returns; helper calls alone cannot satisfy the gate. All original
per-test budgets and the 1800-second group supervisor remain unchanged.

The ordinary request tests distinguish the exact original three-function
reference chain from the selected path. They exercise real object and shared
library publication, lost native acknowledgement after SQLite publication,
reentrant independent calls, held proof identity through selector changes and
service restart, and wheel execution without authoring imports. A known late
signature exception is a controlled injected error; the preceding object
publication and its retained SQLite row are actual effects. Neither a copied
diagnostic receipt nor resetting a Python fence grants another effect.

The first actual development image exposed generator-local lifetime and PEP479
differences. A later actual input exposed the two-observation truth boundary of
`any`. Those original reports remain separate from corrected revisions. No
development result is transferred to a later source tree. Current-source cold,
whole-suite qualification, default activation, live deployment, and deletion
of retained owners remain false until separately established.

The frozen version-1 Python 3.14.4 run completed the original 48 Agent calls,
but its component group failed two methods and the additional 12 generator
and 16 native named-local observations differed. Those original failures are
retained. Version 2 has independent permanent lifetime tests, including the
byte-identical original observation definitions, unknown retirement handoffs,
the full Core-VM/native frame comparison, and service-close-before-traceback
release. A private protocol run with a numeric profile is not qualification
on that other interpreter. Actual runtime observations and original Agent
calls must run on the exact new source and interpreter independently.
