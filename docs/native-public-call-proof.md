# Native public direct-call proof checkpoint

The native parent now accepts original raw program bytes through the shared normalizer and returns freshly bound native call-totality and call-equivalence results. The qualified interface here is HIAPPC01 with an ASCII function selector or absent selector. Typed value transport and the single final facade remain open.

## Actual construction and authority

The actual parent is 10412003 bytes, SHA-256 73cc8f3507f34ad0c0471870922d02dbdc193a0b797f8340f73c657e6631fa9a. The native HIA packer produced bytes equal to independent mechanical layout. The normalizer, shared process, JSON decoder, whole-image hash and cancellation adapter are the same qualified components used by the primitive public parent.

Both child images retain the original 8 MiB executable bound. The public envelope retains the 16 MiB bound, the shared 608 MiB workspace and 64 MiB capture/output bounds. The call child retains 16 functions, 32 blocks, 512 operations, 32 expansions, 32 inputs, 16 returns and a strict 1–10000 ms proof budget. HIA policy owns admission, deadlines, descriptor custody, child lifecycle and receipts; the fixed adapter only transports calls and bytes.

The parent captures actual child bytes into anonymous mode-0500 sealed images, rehashes them, and uses the qualified process role. Every completed child is reaped and every capture stream sealed before interpretation. Whole-image identity and source inventory are rebound to the public parent at receipt construction and checked through closure.

## Original behavior retained

Raw before and after inputs undergo original normalization and complete diagnostics. Only after both sides normalize does the call profile reject structured/composite input, which is outside the original direct-call profile. This differs from primitive scalar proof, where the existing normalized composite domain remains accepted.

An empty raw after byte string in mode 2 now reaches normalization and returns the original program diagnostic. It does not widen the normalized call-child ABI: a successful canonical Core is still nonempty. Invalid solver budgets precede program normalization. Original refusal ordering remains intact for schema, selection, closure limits, resources, signature identity and expansion limits.

Normalization retains raw input hashes, original canonical input hashes and actual primitive Core hashes as distinct values. Call receipt producer binding checks the fresh child validator, checker and implementation identity; output rebinding updates all three to the parent. A late decided result becomes unknown without positive claims or a counterexample while keeping its already-computed call-closure metadata.

Invalid totality inputs retain the original validation_error. Invalid equivalence inputs retain the original HIAProgramRejected message and error type. Explicitly tagged large diagnostics use spans from the same qualified native JSON decoder and preserve complete strings, including escaping and UTF-8.

## Remaining release work

This checkpoint is not the whole public typed API or final release. The final owner will combine primitive, direct-call and bounded proofs with shared normalization and lifecycle components. Typed selectors/timeouts, bounded workflow, multiversion coordination, final production loop, cleanup and a new complete clean-tree gate still need closure. No canonical activation or legacy deletion is authorized by this component report itself.
