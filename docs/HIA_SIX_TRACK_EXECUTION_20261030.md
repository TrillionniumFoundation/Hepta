## 2. 实现为何改变

### 2.1 一个 Rust 执行机器，明确的有界契约

原来的 v2 在深度 33 就会按策略拒绝，而生产 Python API 的相应程序能完成。这是覆盖范围差异，不是已证明的旧版内存安全漏洞。本次保持一个 `Machine`/`ByteMemory`，将语言调用改为显式帧，同时保留 v1/v2 原来的边界。

单独启用的 v3 接受根帧计入的 1–256 层、最多 10,000,000 ticks、最多 1 GiB **逻辑**活跃负载预算。返回借用重新绑定、链式资源销毁计步、预算停止和陷阱的账本前缀保持可比。停止时没有实际发生的清理不会被虚构成完成。

测试实际覆盖了 1–256 深度、512 KiB 宿主线程栈、16 MiB 加 1 字节的成功申请/释放，以及超出 1 GiB 策略时的申请前拒绝。**没有测试成功分配 1 GiB，也没有把逻辑预算当作 RSS 限制。** Rust 的失败注入索引仍有 u64 传输界限；标量参数与 Core 规范化也保留各自限制。

生产准入仍由 Python 执行。独立 Rust 交叉检查的范围、拒绝和未证明项见 [v3 契约](HIA_RUST_BOUND_BUDGET_V3.md)。支持矩阵保留原有 25 项能力及 146 个检查，增加 12 个检查成为 158 项，没有删减旧分母。

### 2.2 可验证候选和执行身份

`prepare_guarded_narrowed` 从不可变 baseline 开始，沿现有 guarded 与 narrowing 两阶段路径重新独立验证，再构建并封存原生图像。实际正例暴露了 narrowing 证明生产者漏填 `policy_sha256`：修复的是生产者，消费端没有放宽。

对 NDU 排名桥接器，真实反例证明了“检查路径、执行路径、最后再检查路径”无法抵御替换后还原的 ABA。新实现保留准入时的实际字节，写入带 write/grow/shrink/seal 封印的 memfd，读回并检查后才执行该描述符。收据和二进制读取使用 nonblocking/no-follow 后检查常规文件，避免 FIFO 无写者阻塞。输出在运行期间受界限约束，进程组清理在 leader 回收前完成。

这保护的是受信任本地桥接器的可执行字节身份。动态加载器、共享库、宿主与编译后端仍在信任范围内；它不是任意恶意原生代码沙箱，也不是远程证明。见 [桥接契约](HIA_NDU_BRIDGES.md) 与 [候选协议](../experiments/hia_ndu_narrowed_candidates/README.md)。

### 2.3 captured C 的后测试循环

新 lowering 只产生一次循环体，以首次进入标志和短路条件保留 do-while 的执行顺序；延迟初始化分析把存活的循环体后状态带到条件与后继。早返回、局部作用域和嵌套循环被实际比较。`break`、`continue`、`goto`、修改状态的条件等不支持项继续拒绝。

8 个函数各 48 个输入，分别比较 C11、C++20、HIA VM 与直接 LLVM；测试禁止使用 Rust 后端作隐式替代。C++ 臂是把 C 兼容参考源按 C++20 编译，**不是通用 C++ 翻译成功**。真实 Ring-Buffer/musl 派生项目还包含 12 个维护用例和实际零长度队列调用。见 [迁移支持范围](HIA_C_PROJECT_DO_WHILE.md)。

## 4. 实际旧代码组合应用：正确运行，但性能门禁未过

既有队列/校验应用重新执行了捕获、迁移、构建、功能差分、资源与维护流程。记录包含 11 个原始上游函数体、1 个自行编写的迁移校验辅助体和集成客户端；原上游字节、Clang 捕获输入、调用契约、AST、Core、LLVM、所有命令和输出都保留。它是有限组件组合应用，未宣称移植了整个大型遗留项目。

实际完成 96 个输入 × 11 条原生路径 = **1,056 次功能比较**，96 行资源观测，12 个维护用例，以及 11 臂 × 2 种 CRC × 7 组 = **154 个性能样本**，没有删除样本。训练输入与固定种子的留出输入分开；原构建及 516 条实际命令可从归档重放。

迁移阶段实测 **8.654354078 秒**，生成后的迁移函数体手工修改记录为 0。但调用契约与测试设计含人工工作，`human_effort_measured=false`；因此不能说“零人工成本”或宣称节省多少人时。

性能候选在测量前固定为 `hia_native_irpgo`，强基线是每种 CRC 中 8 个非 HIA 参考臂里最快的中位时间：

| 留出工作负载 | 预选 HIA IRPGO 中位耗时 | 最快参考（Rust PGO） | HIA/参考 | 验收 |
| --- | ---: | ---: | ---: | --- |
| CRC Castagnoli | 38.288691 ms | 35.354140 ms | 1.083004 | 慢 8.30%，未通过 |
| CRC IEEE | 40.210499 ms | 33.787206 ms | 1.190110 | 慢 19.01%，未通过 |

HIA 的 RSS 中位值比率分别为 0.9058 和 0.8916，但运行时间/RSS 联合门禁仍失败。HIA LTO 等其他臂的原始结果也保留，没有事后换掉预选候选来制造成功。整个资格运行约 51.580 秒，嵌套阶段不能重复相加。

适用范围是 LP64 标量 ABI、受约束记录视图的内部标量化、调用方声明的长度/别名/资源契约和有限输入域。它没有证明任意外部指针布局 ABI、任意 C++ 模板/异常/继承/生命周期、源语言全等价或任意 C 未定义行为的安全自动修复。[应用结果](../evidence/hia_six_track_20261030/LEGACY_APPLICATION_SUMMARY.json)；[独立 64 项核算](../evidence/hia_six_track_20261030/legacy-irpgo-arithmetic-audit.json)。

## 5. 优化净收益与另行登记的复用实验

短周期的独立候选机会控制为真实执行，不是成本模型预测：`byte_sum` baseline 的交付部分为 1.385654382 秒，guarded 为 1.193196153 秒，但完整成本由 1.770014778 升到 2.243499559 秒。guarded+narrowed 的完整成本为 2.551046270 秒。`packet_xor` 两个候选也没有净收益。机器码实际不同和执行片段更快，都没有代替完整成本门槛。

观察到这个差别后，另行固定 [复用实验协议](../experiments/hia_candidate_amortization/PROTOCOL_20261030.json)，在采样之前发布登记提交 [`c0c77cd3`](https://github.com/TrillionniumFoundation/Hepta/commit/c0c77cd382d16953c66e1e8eba206ff11f4da45d)。选择 byte_sum、延长复用期是根据已看到的结果作出的适应性后续实验；新的留出种子也不能把它变成独立、无偏的确认。

三臂各三个循环 Latin 组，固定 256 次交付、每次 65,535 次原生调用，保持现有资源限额。每个 episode 从新的 baseline 验证、编译、封存开始，候选再付额外独立验证与构建费用；检查、证据写入、释放均计入。32 次超出 guard 的交付必须实际走回退。每个候选只有在三个成对完整成本差全部为正时才过关；不删除慢样本，也不在看到结果后再调复用期。

实际完成 **9/9 admitted episodes、2,304 次交付**，所有源码/工具身份不变，资源释放门槛通过。完整独立策略成本如下：

| 版本 | 三组 episode 加共同费用 | 相对 baseline 的观察 |
| --- | ---: | --- |
| baseline | 116.318498615 s | 参考 |
| guarded | 110.491521082 s | 完整成本低 5.0095%，三个配对均为正，候选门槛通过 |
| guarded+narrowed | 113.718536369 s | 总和较低，但第二组变慢，候选门槛失败 |

各组 baseline 减候选的**完整**成本差（正数表示候选节省）：

| 候选 | 第 1 组 | 第 2 组 | 第 3 组 | 预注册候选裁定 |
| --- | ---: | ---: | ---: | --- |
| guarded | +1.762770288 s | +1.124141941 s | +2.940065304 s | 通过 |
| guarded+narrowed | +1.135773314 s | **−0.829901946 s** | +2.294090878 s | 未通过 |

因此，**存在一个通过这次有限复用成本门槛的 guarded 候选**，但要求两个候选都通过的 `observed_complete_cost_gate=false`。narrowed 的总和更低没有覆盖失败配对。这是适应性选择后的微内核观察，尚无统计优越性、无偏确认或真实遗留应用胜利。NDU 没有参与此次后续决策，不能据此改写 NDU 增量结论。

本次新研究计时 **339.344308616 秒**，与前序已记录费用合计 **538.688226815 秒**；最后分析/编码、归档、外层 Python 启动/import、工具取得和未记录人工作业按协议不计入该测量。

## 6. NDU：规划一致，增量价值没有通过

这次使用原始 NDU 源码 pin `c4a1bbed3a39beba43a6abf1a18b6f75c5725c21`，保留实际构建与源身份；排名传输回归另有其原始 source pin。没有把自写模拟器说成 NDU。

各臂获得相同的初始真实交错校准 bank、已登记剩余输入的信息开放范围、复用规则与预算。每个 episode 内，两个模块共享一个候选构建 credit；各臂只使用自身已经完成的实际观测。固定臂一次提交有限 suffix 计划；反馈贪心只按当前 epoch 的完整费用决策；DP 每步重算剩余轨迹；NDU 评估相同分配。可用信息相同，各算法按协议决定如何使用它。

成功的宿主运行完成 16/16 episodes、256 次策略交付、36 次校准，以及另记费用的 6 个机会控制。32 个 NDU 决策与同模型精确 DP 一致，独立枚举复核 regret 为 0。所有策略都使用 0 个候选构建 credit——在该短周期和成本模型下，准备费用不能回本。

| 策略 | 完整归属成本（共同准备每策略计一次） |
| --- | ---: |
| 固定策略 | 25.891747162 s |
| 反馈贪心 | 25.518711929 s |
| 完整 DP | 25.521788425 s |
| 原生 NDU，已有构建 | 26.183594546 s |

NDU 热成本比 DP 高约 **2.59%**，没有通过比三个控制都低的门槛。空 target 构建允许已有依赖缓存，不是整机完全冷启动。

首轮受环境 `/proc/<pid>/exe` 权限限制而失败的运行与费用保留：没有把 NDU 提前失败的低耗时计作收益。之后经正常宿主权限审批，在相同实现和协议下重跑完整四臂；两个运行身份各自保存。全部成功运行的会话/图像释放完成，源码、工具与原始 NDU 字节身份稳定。[结果摘要](../evidence/hia_six_track_20261030/NDU_SUMMARY.json)；[完整 NDU 原始记录](../evidence/hia_six_track_20261030/ndu-receipts.tar.gz)；[独立枚举及成本核算](../evidence/hia_six_track_20261030/NDU_ARITHMETIC_AUDIT.json)。

本结果支持 NDU 在此有限候选图上的决策一致性，不支持 NDU 比完整 DP 更聪明、更快，也不支持为任意程序规划“每条指令的全局最优”。新的候选复用收益即便存在，也不能自动归功于没有参与该后续实验的 NDU。
