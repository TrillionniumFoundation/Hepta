# Service artifact control in HIA

This candidate assigns the complete `HIAAgentService._hia_artifact` control
graph to `examples/hia_bootstrap/service_artifact.hepta`. Selection is explicit
through `HEPTA_HIA_SERVICE_ARTIFACT_MANIFEST`. An empty or invalid selection
fails before a provider call; a selected invocation never falls back to the
retained Python handler.

The original 749-byte method remains in the class source and in an independent
fixture. A post-class public dispatcher selects the actual route. Old AST
checks of the class method pin the retained original; they do not prove which
implementation the public attribute invokes. New checks also verify the actual
public binding and poison the retained alias when selected.

## Complete owner boundary

The image issues profile checking, source extraction, UTF-8 versus path choice,
capture, expected-digest lookup, null short circuit, digest comparison,
conditional rejection, Store publication, result construction and normal local
release. A replacement rejecting provider that returns proceeds to publication,
as the original does. Provider exceptions receive a separate confirmed error
continuation; native delivery loss is never synthesized as a provider refusal.

Python supplies opaque object operations and the original provider expressions.
The literal `service.store.put(data, 'input')` does not extract or retain a
temporary receiver. A detached callable may release its temporary Store before
invocation. Global-provider lookup preserves the original `str(len(data))`
ordering, including a previously bound outer callable when a nested provider
mutates the global namespace.

`capture_path` remains the hosted provider in `hia_agent_store.py`. SQLite,
filesystem, hashing providers, worker startup and other handlers are separate
responsibilities. This owner does not establish an entirely native CLI,
worker, Store or project.

## Pending resource custody

The new foreign activation opts into pending resource observations. Actual
downstream native records and explicit resource scopes can supply already
obtained resources. Service getters, paths, equality and object layouts are
not used to infer them. Reservation alone is not evidence that an effect ran.

A native handoff records a pre-reserved occurrence after preparation and its
final causal check. A resource scope records its pre-reserved return fact
before identity queries or cleanup can fail. A normal mismatching execution
does not become a current native ancestor. Failure to observe return identity
retains the explicit resource outcome without inventing a native child.

The exact activation and receipt are checked before native confirmation.
Healthy references retire after the matching ACK and before another provider
port. Confirmed custody retirement is mechanically recoverable if bookkeeping
raises. It repeats no provider, SQL operation or native ACK; a confirmed ACK
cannot become loss solely because later bookkeeping fails. Actual unconfirmed
resources remain held, and their later retirement is denied. Fault controls
must establish the actual qualification scope before a release claims these
implementation boundaries as verified.

## Independent evidence boundaries

The immutable original oracle has 146 finite cases, observed twice in fresh
CPython 3.12.14 and twice in fresh CPython 3.13.5. Those runs repeat within each
runtime. Five cases differ in ten `AttributeError.name` / `obj` leaves across
runtimes; no normalization is permitted. Temporary receiver, callable, result
and explicit exception-GC traces remain part of the full comparison.

The oracle's loader retains its two private `Original` classes for the lifetime
of the observer. Previously it kept only their method code objects, leaving
two unrelated class cycles for a later collection. The exact parent and
successor both reproduced a 14-versus-0 count on CPython 3.14.4; a separate
object diagnostic identified all fourteen objects as those two loader graphs.
The correction retains only these fixed fixture classes. It adds no collection
call, changes no GC setting and retains no object created by an observed case.

The original freeze, method bytes, 146 cases and historical runtime outputs
remain immutable. Successor source admission pins the complete corrected
oracle bytes and reconstructs the exact old oracle before checking its original
size and hash. Altered or partial successor bytes refuse. Every observed GC
count, exception attribute, finalizer trace and original/VM/Native difference
remains part of the actual comparison; none is normalized.

The packaged observer freezes same-runtime original observations before image
mapping. That finite frame comparison alone does not qualify public selection,
actual Store resources or the installed worker. The separate ordinary caller
inventory preserves all nine original modules and 112 ordered methods. Other
original provider/administrator gates, inputs and deadlines remain separate.

The prototype is not a matching-source cold qualification, an all-input
equivalence proof, or permission to remove the retained original or providers.
