# Explicit HIA cold transport candidate

This component moves the parent lifecycle of the flat and linked native observer's selected `execute` calls into a HIA policy. A C dispatcher performs one named primitive at a time. A separately admitted CPython bridge retains real canonical binary stream owners, original pending exception objects and an actual `subprocess.Popen` object. **It is not whole-native, not qualified, and does not replace either default execute function.**

The HIA source is authored by `tools/generate_hia_cold_native_transport.py`. Root must actually run that generator, validate the unchanged compiler profile, compile its complete output with a matching current compiler and compile the mechanical C sources. No generated HIA bytes, binary, performance measurement, source test or native test exists merely because this source package exists.

## Owned effects and terminal behavior

The 128-byte request, 64-byte reply and 256-byte state use R3-specific magic and exact nonce/sequence binding. Before any effect, C validates the entire returned state against the prior state, the actual last receipt and this request. Every action/argument/amount/auxiliary has a defined projection; the host does not accept an action merely because its XOR is correct.

The 18 raw actions are retained. Seven explicit hosted capabilities add owner initialization, stdio wrapping, the actual Popen audit event, operand conversion, context entry, exception handoff and stdin flushing. HIA selects these actions and every cleanup edge. None calls the old whole `run`, `Popen.__init__`, `communicate`, `wait` or `__exit__` implementation.

Ordinary exceptions follow kill, stream close, wait. Timeout follows kill, wait, stream close. A real nonblocking wait observation precedes a signal; ECHILD is unknown custody, not a fabricated reap. EINTR is an observed transient receipt and is kept out of the terminal cleanup error field. KeyboardInterrupt has a distinct bounded grace path. The original post-constructor deadline begins after the successful exec-error handshake and context entry; that handshake proves EOF on the exec error channel, not execution of main.

A successful normal terminal requires actual descriptor retirement and a genuinely reaped child. A real exception handoff records any remaining FD mask and PID explicitly. The Session is GC-tracked and retains a real Popen owner; its ordinary stdlib finalizer is still a hosted capability. This state is not reported as zero resources or successful normal completion.

### Atomic handoff

The checkpoint version could assign a raw descriptor to Session before a later stream check failed. The final successor removes that partial-adoption path.

Validation first keeps proposed raw integers on the C stack. It checks existing raw custody, every actual surviving stream's fileno and the child owner. Failure assigns none of the new raw integers. On success the old handled-exception state is restored while Session still strongly owns the current pending/caller exception. The commit then performs only nine integer copies and the handoff flag; there is no allocation, Python callback, decref, FD operation or failure branch after that commit boundary.

The additional eight C controls use real descriptors and actual canonical _io streams. They include a raw descriptor followed by a closed stream whose fileno raises ValueError, then genuine retirement and reuse of that integer for a different resource. Disposing the rejected Session must leave the new resource live. These controls are additional tests; they are not substitutes for the original 44 methods or the broader 36 protocol/native controls.

## Canonical Python bridge boundary

The loader admits an explicit CPython 3.14 runtime and its exact subprocess source. It checks actual builtin _io/open aliases and BufferedReader/BufferedWriter descriptors. The C profile rechecks captured open/class aliases and PID/thread before a public call. Extra `closed` and `fileno` queries are justified only within this declared canonical owner profile.

This is not a claim of arbitrary provider, metaclass, reflection, monkeypatch, trace/profile, GC or traceback equivalence. In particular, source-byte identity is not a proof that arbitrary pre-admission code rebinding never happened. Exact public Python stack shape, every OOM cutpoint, every asynchronous signal location, noncanonical arguments, independent competing waiters, and retry behavior after unusual constructor close errors remain open. The original tests, raw exception fields and all-input gates decide observed equivalence; none is normalized.

The extension's sealed code descriptor has an explicit module-lifetime owner containing only code bytes. It is not an invocation keepalive. A forked initializer cannot publish its parent epoch; a selected forked authority refuses rather than silently loading or falling back. Live invocation objects remain in the visible Session/Popen reference graph.

### Timeout exception fields

The IO timeout path calls `TimeoutExpired` with exactly the original two positional arguments and supplies partial output through the original keyword fields. The WAIT timeout path retains its actual remaining wait value in `args[1]`, keeps `stdout` and `stderr` as `None`, and restores only the public `timeout` field to the requested value. Its remaining time comes from the already observed start and first WAIT-entry clock facts, with the original floating-point operation order. No extra clock action or time-budget change is introduced. Independent runs keep their own actual clock values and full exception objects; raw tracebacks, locals and GC differences remain open observations.

## Explicit selection

Default imports retain the complete old execute body. An external development test may select a source-bound build with both:

* `HEPTA_HIA_COLD_NATIVE_TRANSPORT_MANIFEST=<actual manifest>`
* `HEPTA_HIA_COLD_NATIVE_TRANSPORT_ALLOW_DEVELOPMENT=1`

An absent selector retains the old function. A present invalid selector refuses. The selected functions have real new Python code identity and the same literal call signatures; they do not masquerade as the old function and do not retain it in the selected closure.

The builder is `tools/build_hia_cold_native_transport.py`. It requires an explicit compiler SHA and actual Python shared library, preserves the existing native compiler invocation, and records all actual C commands, full outputs, inputs, runtime/header identities and custody. A build result is explicitly BUILT_NOT_QUALIFIED_EXPLICIT_DEVELOPMENT.

## Actual fresh-source cold entry

An external manifest cannot be smuggled through the original clean cold environment. The explicit command is:

```text
python -B tools/replay_hia_selfhost_cold.py --output <new-report.json> --native-transport
```

The default command is unchanged. The new flag still exports only current source, preserves the original 17 independent references, B0 and B1/B2/B3 plus M1/M2/M3, and keeps the original 38 phases and 180-second owner plus 3-second cleanup limit. After the actual fresh B3 and observer builds, this export creates its own policy/extension from its own source. Each selected phase request includes the actual manifest, policy and extension hashes. Its actual command carries the explicit flag, and its report has genuine selected call/entry statistics. No inherited transport image or compiler cache is accepted.

The fresh source path adds real compiler/header/shared-library dependencies and additional build/admission I/O. It does not imply those operations disappeared, or that the 180-second gate will pass. No speedup has been measured.

The complete current cold DATA reader must independently consume all original references, phases, native binaries, loose files and archives with the exact producer/source successor admitted. The new regression reader is not a replacement for that reader.

## Original gates and evidence

`tools/qualify_hia_cold_native_transport.py --scope regression` runs two complete fresh original 44-method lanes before selecting a candidate, freezes both original reports, then runs the same complete 44 methods and the eight additional real-FD handoff controls. No original method, input, assertion, skip rule or internal timeout is changed. Existing original native tests decide their own detailed byte/exception/resource observations. Gate process logs and reports remain raw; this runner does not pretend it rescued temporary artifacts that the unchanged original tests deliberately delete.

`--scope cold` runs the explicit fresh-source command above with the original 240-second outer limit, including source export, and the unchanged internal 180+3 owner. A producer success still requires the full independent cold reader.

`tools/read_hia_cold_native_transport.py` independently binds all regression reports, command/result/stream bytes, current source pins, complete old IDs, original-before-selected order and the real eight-control output. It imports no product or producer helper.

The original 36 native/protocol control definitions are retained exactly. `tools/qualify_hia_cold_native_transport_controls.py` executes all 75 public and 32 actual policy subcases, runs two original public lanes before the selected lane, and keeps every full observation and raw difference. `tools/read_hia_cold_native_transport_controls.py` independently checks all 38 complete owned command records, exact source and build inputs, actual C-loaded policy and target bytes, and complete before/terminal file consumption. Its control-assertion result does not claim raw public equivalence or whole-cold qualification. The original CT36, original 44 methods and eight handoff controls remain distinct gates.

`tools/qualify_hia_cold_native_transport_references.py` executes the original 18 reference-ownership controls. `tools/qualify_hia_cold_native_transport_fds.py` executes the original 18 FD-ownership controls. Their inputs and limits are unchanged. Reference source admission accepts only complete, explicitly pinned source bundles and verifies the full reversible lineage; it rejects mixed source versions. All of these gates still require actual execution and full readback on the current source.
