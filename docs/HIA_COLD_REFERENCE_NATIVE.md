# Complete reference VM constructed by independent HIA tools

The complete reference VM can now be constructed from its HIA source by the
independent HIA assembly frontend, HIA projector, original v1 seed, the explicit
VM backend profile, and a closed HIA linker. The target selfhost compiler is not
part of this construction. The original v1, unsigned division, bulk, word and
owned backends retain their original source and identities.

This checkpoint closes the previous development construction dependency on the
Python general machine emitter and GNU object linking for this VM. Integration
of the native construction plan into the public default build remains separate;
the development build driver is an external mechanical caller, not the final
public build command. A successful component qualification is not a successful
complete release or a completed 180-second cold campaign.

## Construction and interfaces

seed_vm_backend.hepta is constructed by the original independent v1 seed from
actual native frontend and projector output. It accepts an existing projected
wire with the explicit HIAVMR01 magic and word 56 equal to 3 or 7. All original
wire and capacity limits remain: input and object output at most 1 MiB,
2,048 registers, 64 bounce values, 128 functions, and 16,384 commands. It admits
the borrowed operations used by the complete reference VM and the separately
qualified unsigned division and remainder emitter. Signed division and owned
allocation or chain operations are outside this construction profile. The VM
it constructs still implements the full original language and resource domain.

Mode 3 exports the six-word SysV planner ABI for three borrowed views. Mode 7
exports the original private runner ABI: RDI points to fourteen argument words
representing seven views, and RSI points to exactly one result word. The
backend's internal two-word value slots are adapted through a private temporary;
the public result store writes only one word. A real original/new canary test
checks both adjacent words and the exact complete result.

cold_reference_kernel_linker.hepta accepts HIAVLK01, mode Q, object length Q,
then the exact seven-section relocatable object. It checks the complete ELF
header, section table and layout, padding, ten symbols, strings, public wrapper,
all relocation sites and types, and the canonical final abort/UD2 sequence.
Only actual abort, memcpy and memset relocations are accepted. Every admission
check precedes the first output write. The fixed primitive adapter is retained
as tools/hia_cold_reference_primitives.S; its generated bytes are embedded in
the HIA linker, so native builds do not execute an assembler. Its abort path
preserves SIGABRT, rather than substituting another trap.

Both f0 and f3 are independently projected and compiled. Their linked flat
images are concatenated; the original source-owned owned_reference_cli_packer
receives HIAOPK01, total length Q, runner offset Q, and the complete flat bytes.
The unchanged complete VM source produces the ordinary 10-million-step
admission image. cold_export_reference_vm.hepta produces the existing private
30-million-step admission image used by the linked-reference tests; each
request still passes its original actual step, depth, heap, and failure budget.

## Executed qualification

- 309 fresh original Core VM versus newly constructed complete HIA VM calls,
  including scalar, dense, reordered, allocator and compiler-word cases.
- 965 original generic-family packets plus four mixed-view packets, each
  executed now on both the original independent VM and the new image. Return
  code and the complete stdout and stderr bytes agree, including actual steps,
  resource ledgers, view snapshots and traps.
- 39 owned, 69 chain and seven allocator packets, again executed on both current
  images and compared in full.
- 12 original linked observer policy and packer cases under the original
  30,000,000-step, 128-frame and 4 MiB heap profile, with exact step counts.
- 1,288 closed backend, object-linker, no-partial-output, and ABI controls.
  These include every public-wrapper byte, section and symbol metadata, strings,
  relocation fields, unsigned-only division, borrowed-only resources, full
  original bounds, and exact one-word runner results.
- Four actual native-link results agree byte for byte with external GNU linker
  comparison objects. These host tools are used only as qualification oracles.
- A second construction uses freshly executed native assembly and projection
  of both complete sources and reproduces both VM images byte for byte.

The initial guard suite found a real boundary: extending the text section by
one zero padding byte remained structurally self-consistent. The linker now
checks the canonical terminal call-abort/UD2 sequence and its exact final
relocation. The failed receipt is preserved. Valid kernel and final VM bytes
are unchanged after this fix.

Exact source, initial-root, product and report identities are recorded in
HIA_COLD_REFERENCE_NATIVE_QUALIFICATION.json. The two final VM images are
708,381 bytes; their SHA-256 values are
1f164447c5407662ccf2b4829189adab51d2cd7bcfa023785902e9607c94af69
and
86bb8987049bc6a5b6b18deddbcaecfd41f56198fd5bda1559e7ccc1610f5d42.
The increased machine-code size has a measured cost: the 965 generic VM calls
take about 5.02 seconds on the new image versus 2.63 seconds on the previous
independent general-backend image. This isolated timing excludes frontend,
projection, archival and the complete cold campaign and does not establish
compliance with the overall 180-second limit.
