# Optional HIA CLI discovery route

This opt-in bundle links five real HIA images: the retained argument controller,
retained formatter, discovery JSON constructor, discovery expression controller,
and genuine parser-error object graph. The ordinary CLI default is unchanged.
It does not close all fifteen actions or remove Python from the process.

The expression controller orders the original output and provider evaluation.
Standard, definition-bound providers can use the JSON image. Changed providers
or metadata take the actual foreign callable and preserve real dictionaries.
The JSON image constructs and sorts the catalog and computes its canonical SHA;
it does not store nine completed responses. The parser graph creates fresh
objects and preserves the actual shared class/function identities, aliases,
container cycles and ArgumentError action. CPython supplies mechanical object
operations and establishes the real handled-exception context.

## Explicit installation

The three additional `.hepta` resources belong to the native bridge resource
group. A wheel contains the runtime, data and resources; runtime loading does
not import authoring tools. The bundle manifest schema is
`hepta.hia.cli-discovery-bundle.v3`, with five relative component manifests and
their SHA-256 values. Each component is bound to its actual source and compiler.
The original two-image bundle and the earlier four-image development bundle
remain separately identified.

Build from real current-source cold authority:

```sh
python tools/build_hia_cli_discovery_bundle.py --output NEW_DIRECTORY --compiler B3_IMAGE --cold-report COLD_REPORT
python tools/qualify_hia_cli_discovery_bundle.py --cold-report COLD_REPORT --evidence NEW_EVIDENCE_DIRECTORY
```

Development requires the separate `--development` builder option. Its manifest
is accepted by the new tests only through the explicit development variable.
It cannot prepare a matching-cold fixture or enter the production qualifier.
Compilation retains the original 20-second child and 1 MiB buffers; each
qualification group retains the 180+3 process owner. Independent Core VM frame
comparisons retain 10,000,000 steps, 8 MiB heap and call depth 128.

The strict qualifier re-reads the actual current B1/B2/B3 images and current
source closure. It then binds every compile request, child stdout/stderr,
receipt, full 1 MiB output, produced image and manifest. Original CLI test files
are unchanged. Their old production fixture builder is explicitly bound, only
inside this qualification child, to the new five-image producer. Both complete
builds and the original invalid-cold rejection are recorded. This is a fixture
provider change, not a claim that the old two-image builder produced five images.

## Observed and open boundaries

Local CPython 3.12 development observations include all original 43 CLI tests,
21 successful/foreign comparisons, parser exception graphs and real lost-ACK
controls. Their exact source revisions and retained failures are in the
external development evidence. A subsequent packaged test run must qualify its
own current bytes. Actual CPython 3.14 and matching-current-source cold results
are not inferred from these development observations.

The parser graph is generated for the exact admitted interpreter profile.
Arbitrary parser replacement, concurrent mutation, exotic module dictionaries,
locale/TTY process presentation, and the remaining semantic action providers
are not claimed closed by this component. Physical argv/env/fd2 and a direct
ELF process entry are separate profiles. No default switch or whole-native
delivery status is granted by this optional bundle.
