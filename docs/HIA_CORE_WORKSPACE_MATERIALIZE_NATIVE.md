# Native primitive Core workspace materialization

This **explicit candidate**, not the default workspace loader, accepts
`hepta.hia.core-workspace.v1` JSON. HIA performs strict JSON decoding, the existing
module-graph policy, capture-avoiding function-name allocation, call-target
rewriting and Core assembly rendering. Original public names and declaration
order are retained. Unused private function bodies are not discarded.

The resulting assembly is representation, **not semantic admission**. The
standalone `hia-workspace-elf` filter always runs the existing native HIA compiler
and emits only an x86-64 ELF relocatable object after successful type, effects,
SSA and resource/borrow checking. Invalid SSA and dropping an owner with a live
loan are refused by that compiler. ELF linking is a separate mandatory step for
executable projects. Neither flat-output nor executable-output profiles can
bypass this filter's ELF-object check.

## Build and invocation

From a clean, matching checkout, complete the original/modified cold replay:

```sh
python -B -m tools.build_hia_core_workspace_cli \
  --compiler /absolute/current-cold/B3.image.bin \
  --cold-report /absolute/current-cold.json --output /absolute/new-output
/absolute/new-output/hia-workspace-elf < workspace.json > workspace.o
```

An incomplete or different-source completed cold report is refused before the
output directory is created. The hosted builder validates the actual compiler,
source contract and application images; it is trusted build custody, **not a
native-only installation or bootstrap claim**. At runtime the copied executable
uses Linux x86-64 syscalls, without an interpreter, another executable, filesystem
payload reads or a PATH dependency.

Exit statuses: 0 success; 2 JSON/policy/representation/semantic refusal; 3 byte or
arena capacity; 4 I/O failure; 64 unexpected arguments. EINTR is retried. A real
partial write followed by EAGAIN returns 4 and can expose an output prefix:
stdout is not transactional publication. Check exit status before publishing.

## Exact supported boundary

Only primitive `hepta.hia.program.v8` Core bodies are supported here. Older
feature schemas and nominal types are refused, not silently upgraded or erased.
The inherited JSON/fact profile is 8 MiB input/facts, 1,048,576 decoded nodes,
depth 128, 1,024 modules/functions/exports, 4,096 imports and 16,384 calls. The
materializer uses an 88 MiB private arena and 16 MiB + 8,192 bytes scratch, and
renders at most 1 MiB assembly. These private buffers may change on refusal.

The mandatory compiler retains its existing, narrower profile: 128 functions,
256 blocks per function and 1,536 total blocks, plus its existing source,
output, workspace, instruction and relocation bounds. A valid graph can still
exceed that compiler profile and be refused. No limit or cold deadline is raised.

The new application's trusted in-process HIA packer has a separate **2 MiB
bundle** input/output profile to embed the materializer and compiler, each at
most 1 MiB. This does not extend the compiler's 1 MiB ABI buffers or the existing
qualification-child profile. The existing single-program JSON CLI packer's
default generated bytes remain unchanged.

## Evidence and remaining work

Tests require independent VM bytes and refusal canaries before building a new
seed, fresh B0/B1/B2 and applications, original/modified real projects, original
public-name/capture avoidance, native semantic refusals, source-bound manifests,
short-buffer guards, private concurrent calls, copied empty-PATH/syscall tracing,
injected read/write EINTR, real partial writes and 128/129-function boundaries.
Fresh source CI, exact-source cold, installation/lifecycle and complete regression
are separate acceptance gates; development tests do not substitute for them.

`NativeCoreWorkspaceMaterializer.render(bytes)` is a hosted adapter around a
locally trusted image. The default hosted `link_workspace` path is unchanged.
General Core/nominal materialization, hosted authoring/build custody, runtime and
library coverage, Agent persistence and native-only installation remain OPEN.
This component is not whole-stack closure or production activation.
