# Native query payload owner

This integration candidate implements the complete payload produced by `prepare_edit` in HIA. The ordinary callers share its explicitly selected route, including an installed worker's pinned helper bundle. An unselected caller retains the reference construction. This candidate has no matching-source cold qualification or complete-regression result; the separate development observations below do not supply either.

## Authority and ordering

The existing `verify_program` remains the first authority for the complete original Core or structured/Core pair. The host captures its immutable canonical and structured bytes, exact selector type/length/codepoints and the original fields container type. HIA then validates fields, validates all three selector types, locates the function, block and SSA output, encodes and validates the original graph packet, performs the original SSA and FIFO CFG closure, and applies the original 256-operation and 64-block display limits. HIA constructs all signatures, dependency and consumer entries, downstream records, affected parameter names and visible callee signatures.

The complete selected operation is encoded as bounded canonical ASCII JSON and hashed in HIA before the context is constructed. HIA hashes the actual canonical/structured bytes and emits the complete v2 or v3 query under the separate original 1 MiB, 262144-node and depth-128 JSON gates. The result header is published only after success. The host only checks framing and decodes the returned object; it supplies no graph, query dictionary, selector decision or digest.

## Flat protocol and storage

The entry has the existing `(readbuf, mutbuf, mutbuf) -> u32` native ABI. The input begins with a 128-byte header and six 544-byte selector records, followed by the original canonical bytes and optional original structured bytes. The canonical span starts at byte 3392. The ABI details are in [HIA_AGENT_QUERY_ABI.json](HIA_AGENT_QUERY_ABI.json).

The original 56-byte decoded Core arena is immutable after decoding. HIA copies only required subtrees into a separate 64-byte query arena. Core tags 0 through 6 remain distinct; tag 7 is reserved for HIA-generated unsigned indexes. Canonical Core keys already have decoded-key order, so the selected operation's first serialization must preserve its entire private child/next structure before that subtree is attached to the context. The selected-native development control checks the complete private operation links and the original decoded arena before and after serialization. That observation is distinct from qualifying the later registered source tree.

Physical construction storage is distinct from the original semantic query limit. A static disjoint-copy bound uses `4*N+4096` private nodes, where N is the original admitted canonical node count. The full workspace bound is `456*min(canonical_bytes,262144)+canonical_bytes+268560`, at most 128194832 bytes. The output buffer also serves the unchanged decoder's key-table scratch and is 4 MiB; the published query remains limited to 1 MiB. These bounds require real generated/native boundary controls before a complete-domain equivalence claim.

## Build and qualification

The builder requires the shared strict matching cold admission before it creates an output directory. Its source, generator, builder and adapter must all occur in that admitted source map. It rereads the original compiler, cold bytes, complete source map and produced image before publishing the unchanged five-field manifest. The source-only generator checks the actual lowered CFG against the original 128-function, 256-block-per-function, 1536-total-block, 2048-value-per-function, 16-logical-argument, 8192-operation and 1 MiB source limits. Actual image and relocation bounds still require the unchanged native compiler.

## Product integration and remaining owners

The four ordinary consumers are CLI `edit-query`, the service's dependencies inspection, `prepare_batch`, and `apply_edit` reconstruction. They share `prepare_edit`: the original whole-program verification runs first, then an explicitly selected `NativeAgentQuery` owns the complete query payload. The manifest is admitted through its exact source/schema/factory tuple; an installed worker can select it through the existing pinned helper bundle without a per-call environment selector. A selected refusal does not fall back to the reference construction.

The unselected route still calls `_reference_prepare_edit`. No source-checkout or unselected installed caller is described as native here. The production reference construction can be retired only after those callers are actually provisioned with this same owner. General Core verification, candidate revalidation and publication, display validation and whole-batch policy remain separate active owners.

The original 84 exact IDs are retained in the external development validation plan. New observations must compare complete graph, operation and query bytes, preserve refusal order and original budgets, poison the former query construction owner during actual native calls, and exercise real installed ordinary callers with strict resource/factory custody. Development results and matching-source qualification remain separately labelled.
