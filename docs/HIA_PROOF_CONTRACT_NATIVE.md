# HIA proof-contract owner: new recovery revision

This is a new, explicitly selected development candidate. It does not change
the default path, remove any retained implementation, or establish current
source cold qualification or whole-stack native closure.

## Policy boundary

The selected HIA image owns all eight original functions in
hepta/hia_proof_contract.py: _item, _require, _safe_core_method, proof_subject,
_method, proof_result, assumptions_document, and proof_contract_description.
It also owns their eight lazy frames, conditions, ordered obligations,
dictionary construction, exception handler decisions, and retirement
permissions. The fixed foreign layer exposes individual CPython object,
import, CALL, dictionary-update, formatting and exception-delivery mechanisms.
It never calls the retained eight policy bodies and never evaluates an AST at
runtime.

Independent solver/checker engines, source identity, deepcopy/hash operations,
SQLite, compilation, and publication retain their existing implementation and
identity boundaries. CPython 3.12, 3.13, and 3.14 physical ABI mechanisms remain
hosted dependencies; they are not described as HIA-native interpreter semantics.
A runtime ABI guard refusal is a real failure, not a reason to run old policy.

## Selection and actual held authority

HEPTA_HIA_PROOF_CONTRACT_MANIFEST is explicit. The loader freshly reads and
rechecks the complete manifest, HIA source and image on every admission.
The cache shares only immutable mapped image bytes. An active worker bundle
remains authoritative and cannot be bypassed by ambient selection.

A service captures either an actual owner or captured absence at construction.
Profiles, proof production, verification consumption, and replay execute in that
same scope. A later environment change cannot select new code for an old service.
A direct unscoped public call admits once and propagates that capability to
nested calls. proof_result adds its actual capability if the caller did not
already supply that exact object. Invalid tuples and duplicates retain the
original checker's rejection path. A digest supplied by evidence cannot become
an executable capability. A conflicting owner cannot impersonate the actual
producer. Service close prevents new business; failure evidence is not replayed.

The Core dependency inventory remains its original pure-Core closure of 46
files. Seven separately named runtime/coordinator mechanisms are still freshly
hashed by every checker. Their non-Core providers are explicit and retain their
own cold/installation/source identities. No ambient backend selector was added
to the verifier inventory.

    python -B -m tools.build_hia_proof_contract --compiler B3.image.bin \
      --cold-report cold.json --output new-proof-build

      --cold-report cold.json --evidence new-proof-callers

## Remaining limits

This revision is not default activation, deletion authority, an all-input
equivalence proof, or full native stack closure. The original failures, authored
but unexecuted drafts, retained compiler provenance, source snapshots, and every
new run remain distinct. A later integrated source tree must regenerate its own
complete contract, cold chain, installed artifacts and full acceptance gates.
