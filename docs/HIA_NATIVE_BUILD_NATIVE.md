# Explicit HIA native-build coordinator

This development owner covers the complete top-level coordination bodies in
`hia_program_native`: `_implementation_hash`, `validate_block_layout_plan`,
`emit_program_machine`, `_inspect_object`, `_read_artifact`, `_run_logged`,
`_host`, `compile_program_machine`, and `build_program_machine`. The original
rejection helper, `remaining` and `recheck` closures, comprehensions, and
generators are included in the HIA control table. The unselected public route
retains the Python reference implementation and the original signatures.

`HEPTA_HIA_NATIVE_BUILD_MANIFEST` selects the owner explicitly. Each public
entry captures either its admitted immutable owner or explicit absence. An
already held outer scope is authoritative, including after an environment
change, nested call, or exception. The captured owner participates in checker
identity and the implementation fingerprint. The generated HIA asset is
`examples/hia_bootstrap/native_build.hiaasm`.

The HIA image chooses policy branches, effect claims, response acceptance,
exception handlers, and object retirement. Fixed Python ports perform original
object operations, actual import opcodes, actual context-manager protocols,
and the declared OS/Path/hash operations. A with-body is a separate HIA frame
sharing the original local cells; no Python policy body is used as a callback.
The context-manager result travels in an ordinary zero-ACK CALL envelope and
HIA inspects it. Suppression by `__exit__` cannot confirm an uncertain native
transition. Such a frame remains strongly retained and cannot replay an effect.
Successful retirement uses the actual confirmed return, rather than the
caller's ambient handled-exception state.

Verification, lowerer/emitter/Code/ELF/Plan/Byte ABI owners, subprocess capture,
linker and ELF inspection, filesystem publication, and CPython object protocols
remain separately declared dependencies. Selecting this coordinator alone
does not make an unselected dependency native. The runtime does not import an
authoring module or call any retained coordinator body. The authoring compiler
reads fixed source and CPython lexical metadata offline; it does not execute
those business functions at runtime.

`tools/build_hia_native_build.py` production `build` accepts only a complete,
matching current-source cold report. It verifies the compiler receipt in
memory and from disk, keeps complete source custody, publishes exclusively,
and checks readback. `build_development` is an explicit separate entry using a
retained compiler. Neither route activates the selector. Development evidence
does not inherit the retained compiler's old source qualification.

The controls preserve original source fixtures, all existing compiler limits,
ordinary caller tests, original deadlines, and the distinction between an
original business exception and an unconfirmed transition. Tests select either
`HEPTA_HIA_NATIVE_BUILD_COLD_REPORT` or
`HEPTA_HIA_NATIVE_BUILD_DEVELOPMENT_COMPILER`, with optional persistent output
under `HEPTA_HIA_NATIVE_BUILD_EVIDENCE`. Both inputs together refuse.

`tools/qualify_hia_native_build.py` is the separate ordinary-caller gate. It
keeps the exact 51 machine, 50 Core, and 13 additional Agent buffer/lease test
methods, for 114 distinct ordered methods. Their original eleven module bytes
are pinned before image admission. Every coordinator reference body is poisoned
during the test process; actual HIA frame returns and all nine native entry modes
must be observed. Original downstream subowners are declared separately and are
not silently included in this coordinator qualification. Current cold and an
explicit development manifest are mutually exclusive. The original caller
deadlines and subprocess limits are unchanged; an external 1,800-second
supervisor bounds a complete caller run.

The first local CPython 3.12 component checkpoint ran all 22 then-defined
controls, including 170 complete VM/native frames and a real installed wheel.
That checkpoint is independent of the additional caller-source controls and
does not establish CPython 3.14 compatibility or the 114-caller conjunction.

The current implementation is under development. Current-source cold, complete
installed/caller qualification, all-input equivalence, default activation,
whole-product HIA closure, live deployment, and reference deletion are false.
Earlier development failures are retained independently; later controls do not
relabel their original results.
