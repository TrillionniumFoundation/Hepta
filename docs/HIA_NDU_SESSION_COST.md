# NDU 会话：密封产物身份与完整已测成本

本轮改进移除了每次请求前后对同一个密封 ELF 的完整重复读取与 SHA-256 计算。
初次准入仍读取真实文件、复制到 Linux memfd、验证实际密封描述符字节与原文件完全一致，
并计算 SHA-256 与构建清单匹配。每次原生请求前后继续检查同一 inode、大小、四种 seals
及 `/proc/<pid>/exe` 的实际进程映像身份。原生 Rust NDU 每次仍重新运行原有 evaluator。

## 身份保持的条件

`F_SEAL_WRITE`、`F_SEAL_GROW`、`F_SEAL_SHRINK` 与 `F_SEAL_SEAL` 在已经持有的描述符上
共同约束内容、大小和密封集合。只有在这个描述符仍指向同一个 inode 且完整 seals 仍在时，
初次字节验证才能继续复用。以下条件继续拒绝：

- 同一 fd 数字被重用或替换为另一个 inode，即使文件内容与大小相同；
- 任一所需 seal 缺失，描述符关闭，或实际进程已经退出；
- 子进程执行了另一个映像；
- 公开 manifest 对象中的 binary SHA 或原生 identity 在准入后改变；
- 请求/响应的序号、实际发送字节摘要、目标、snapshot、generation 或原生身份不匹配。

manifest 的两个生效绑定被独立冻结，snapshot 返回原绑定的副本。构造或请求失败会关闭会话；
清理期间的错误保留为诊断，父 fd 在 `finally` 中释放，原始拒绝不会被清理异常替换。
该机制信任 Linux 内核、受控 Python 宿主和已绑定构建输入；它不是对恶意宿主的隔离或远程证明。
所有结果仍为 `authority: DENY_ALL`、`safety_certificate: false`。

## 实际回归与对抗控制

实际执行 21 项，0 失败、0 错误、0 跳过：

| 组 | 数量 | 含义 |
| --- | ---: | --- |
| 既有原生 NDU 会话测试 | 8 | 原始 Rust evaluator、one-shot 对照、256 次请求上限、超时、序号与输入绑定 |
| 新增 Linux ELF 身份控制 | 8 | 真实 memfd/子进程，fd 替换、四种 seals、实际 exec、manifest 漂移和清理异常 |
| 成本准入控制 | 5 | 未知或 warm build 成本、失败/缺失/重复单元、响应不匹配均不准入 |

ELF 身份控制使用明确标注的 C 传输夹具，不计成原生 NDU 算法成功。
初始隔离执行环境缺少所需 fcntl 常量或实际子进程 `/proc` 视图，检查按设计拒绝；使用受支持的
具备真实 Linux 进程视图的执行配置后完成上述验证，没有弱化身份检查。

## 预登记旧/新会话对照

运行工具：`tools/qualify_hia_ndu_session_cost.py`。
历史会话直接从提交 `0e1f5dd9bf0f54c492d96bd5dd1ae52e8c804997` 读取完整原始 Python 源码，
其 SHA-256 为 `0458724d443bf6b581fbf8f7411513867fa0f8841172675d4aedff0cecf57fc8`。
没有在新类中重写或模拟旧算法。两种会话加载同一个本轮实际构建的原生 NDU ELF，
使用相同请求、相同原生源身份和同一 Python 解释器。

首次会话前保存协议、源码绑定、原生身份、请求 corpus 与登记。
五组配对，每个会话 32 次真实请求，组间交替执行先后顺序，共 320 次实际原生回复。

没有按零计入。完整已测成本不等于完整经济成本。

## 对第 3 项总验收的影响

这证明在上述场景中可以降低原生 NDU **传输与身份检查**成本，未重跑或改写编译闭环对照。
上一轮 NDU 完整成本 398.457516886 s，高于强固定策略 348.754475126 s 和轻量 DP
352.591082376 s 的结果原样保留。相同 additive 成本模型与候选空间上的完整 DP 已给出模型内
最优计划；减少传输开销不会自动建立 NDU 对这个对照的算法优势。

`compiler_vs_fixed_or_light_acceptance_changed` 与 `native_ndu_advantage_established`
在本轮结果中均为 `false`。安全授权也未改变。

证据目录：`experiments/hia_ndu_session_eval/round4_20261030/`。
`RESULT.json` 保留每组实际生命周期与分摊成本，`REGISTRATION.json` 和 `PROTOCOL.json`
保留运行前登记。`trial01.tar.xz` 保存原始请求、320 个完整回复、实际原生 ELF、构建清单
和执行源码，共 18 个成员、7,837,198 个原始字节，压缩后 501,864 字节。
`trial01.manifest.json` 记录每个成员的大小和 SHA-256，全部逐字节读回核验。
实际 ELF、源码、请求/回复绑定、成本算术及归档另有 45 项只读审计。
试验后复制 ELF、打包与完整读回用了 1.247210040 s，单独保留为证据归档成本，未追溯修改
运行前登记的会话比较；它也未被计成零或隐藏在完整经济成本主张中。
