# Bounded c2hia / cpp2hia L1 composition

This is **not a second language frontend**. \`hepta.hia_migrate\` composes the
existing Clang C/C++ L1 migrators and the source-qualified HIA scalar Core → LLVM
native builder. The accepted intersection is deliberately **narrower** than
either migrator: finite checked i32/u32 scalar SSA exports. The HIA build still
requires the pinned native Rust reference compiler. Unsupported signatures,
pointer/FFI, classes, captures, effects, or LLVM profiles **reject**; no silent
fallback to C, Rust, AST LLVM, or opaque precompiled objects is offered.

## Usage (complete exact-source Hepta checkout required)

\`\`\`sh
python -m hepta.hia_migrate --language c \
  --source examples/interop/c11_small.c \
  --output-dir /tmp/c2hia-bundle --rustc /path/to/pinned/rustc
python -m hepta.hia_migrate --language cpp \
  --source examples/interop/cpp_noexcept.cc \
  --output-dir /tmp/cpp2hia-bundle --rustc /path/to/pinned/rustc
\`\`\`

These commands are *examples of invocation*, **not** evidence those example
sources pass the current exact scalar profile. For a cross-object target add
\`--target aarch64-unknown-linux-gnu\` if the LLVM builder supports the target.

The resulting new directory contains \`candidate.hepta\`, the HIA-derived
\`candidate.so\` host shared library (or \`candidate.o\` target object), and
\`migration-hia.json\`. The manifest records original source identity,
the generated Hepta bytes, native artifact identity and HIA Core SHA, while
retaining source and backend receipts with their explicit unproved claims.

The current Linux publisher stages and verifies all three files, then uses
`renameat2(RENAME_NOREPLACE)` plus directory fsync to publish the **whole
directory atomically without replacing an existing name**. A failure after
rename returns `recovery_required`; consumers must inspect the published
directory rather than assuming an aborted transaction removed it. This is
a bounded Linux filesystem publication guarantee, not a guarantee against
malicious same-user writers or faulty storage.
The compiler and foreign-contract trust boundaries remain unchanged. The
original C/C++ semantics, undefined behavior conditions, pointer provenance,
C++ mangled ABI, platform/toolchain-specific ABI details and backend
refinement are not certified by successful output.

## 2026-10-26 canonical executable Core convergence

The L1 migration **no longer** publishes through `llvm_ssa_pipeline.build_llvm_ssa_source`
(the separate historical `hepta.hia.scalar-core.v0` carrier). It invokes the
existing `hia_source_bridge.build_checked_hepta_hia_native(profile="scalar")`.
That build requires pinned real Rust validation, exact checked source, canonical
HSIR/SSA and source-derived Resource IR replay, the existing
`core.from_scalar_core` converter and **verified executable
`hepta.hia.program.v1` bytes** consumed by the native HIA LLVM backend.

The new outer receipt checks source/compiler/SSA/resource/Core/LLVM identities,
precise target and artifact kind, native artifact byte hash, and the no-replace
publication receipt. Legacy v0-only receipts explicitly reject; forged or
unproved safety/backend claims cannot be upgraded. Unsupported C/C++ input
still fails closed; general C/C++ source equivalence, ABI parity and whole-
language memory/provenance soundness remain open. This version does not claim
to support newer HIA v2–v6 memory syntax from an L1 scalar migrator.

The mocked local protocol test validates this gate, not actual pinned Rust,
Clang, C/C++ execution, hardware or Agent provider experiments.

## Strict L1 migrator receipt policy (PR #208)

Before entering the pinned Rust/HIA/LLVM build, `hepta.hia_migrate` now calls
`hepta.hia_l1_receipt.validate_migration_receipt` on the **actual stage
candidate source hash**, exact original path/hash and the legacy migrator
return object. The schema must be exactly one of:

| Language | Accepted schema | Admitted scope |
| --- | --- | --- |
| C | `hepta.migrate-c.v0` | `strict_scalar_pilot`, frontend passed |
| C++ | `hepta.migrate-cpp-l1.v0` | `L1`, closed `noexcept` scalar free functions |

The validator has closed, versioned field inventories; extra or missing fields
reject, even if a new field says `false`. Converted declaration identities
must be nonempty and unique; no rejected declarations may be hidden inside
a purported successful L1 receipt. Only native-validation `not_run` is
accepted at this stage because the **separate** pinned native builder is
responsible for native qualification. The C preprocessing identity is required.

Every former proof/safety/ABI claim must retain the exact Python Boolean
`False`, not integer `0`: source equivalence and whole-language soundness
for C; C++ mangled ABI, behavioral equivalence, foreign memory safety and
whole-language memory safety for C++. No valid schema alone authenticates a
migrator; actual source hashes, native verifier and artifact bytes remain
mandatory independent checks.

Standalone CPython 3.13.5 tests for the exact validator bytes passed 4/4
method groups, including rehashed claim promotion, missing fields, wrong
source/output identities and declaration duplication. The full integration
and actual native target path are **not qualified** by these unit tests.
Run with a full pinned source checkout:

```sh
python -m unittest tests.test_hia_l1_receipt tests.test_hia_migrate -v
python -m unittest tests.test_c_migrate tests.test_cpp2hepta_l1 -v
```

`whole_project_blockers_closed=false`. The actual C/C++ L2/L3,
multi-compiler ABI and complete semantic-equivalence gates remain open.
