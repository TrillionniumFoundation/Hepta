## Actual public route

The existing non-data _SlotControlMethod preserves unselected original binding,
instance/subclass override priority, class access and the static _lease_value
route. Its selected result is a C vectorcall descriptor wrapping a real Python
function with the original signature. There is no selected Python dispatcher
above that continuation. All genuine nested public calls get their own real
continuation and actual Session/Frame/DeliveryRecord.

The first statement in each real continuation calls the C start primitive.
Python therefore binds the original positional/keyword/variadic signature
before source/image admission, Frame allocation and HIA INITIALIZE. Extension
loading is earlier, at the selected adapter/callable construction boundary;
this additional boundary is explicit and must be tested. A missing extension
does not fall back to the retained policy.

The continuation uses the actual ledger module dictionary. Dynamic providers
and original global lookup remain dynamic. Each business expression is in the
real method frame. The loop branches only on HIA-issued port numbers. It does
not decide the business branch from a duplicate Python implementation.

## Expression ownership

* The lease expression evaluates self._call first using the genuine complete
  Python call expression. Its C operand primitive then observes release once,
  acknowledges that observation, and returns only the opcode selected by the
  HIA directive. The captured callable and the remaining original arguments
  remain on the real Python value stack.
* The conditional AND is a real Python AND. A false non-bool object remains the
  exact assigned value and gets one original truth test. The RHS is evaluated
  only after HIA has selected and claimed its port.
* Adopt uses a real for loop. A GC-visible C iterator owns the actual iterator;
  its tp_iternext calls the real iterator with no Python __next__ trampoline.
  Python stores row before the corresponding acknowledgement. A pre-reserved
  Session slot holds mechanical iterator custody: on a healthy/confirmable
  loop unwind its extra reference is dropped before the wrapper's real
  iterator reference, preserving the final release cutpoint; known loss keeps
  that custody instead. This extra reference is not claimed to preserve an
  arbitrary getrefcount observation. Python's actual loop exit precedes the
  release acknowledgement.
* Conditional error matching uses a real except AgentRejected as error in the
  same continuation. The original exception alias cleanup and active handled
  exception are not replaced by a passed error value. C saves and restores
  the handled-exception state using supported CPython APIs for mechanical
  cleanup. It never edits an original traceback or exception metadata.
* Statement results originally discarded remain discarded. Returned values
  pass through the return expression; there is no Session result field.

## ACK and completion

INITIALIZE and CLAIM still pass through the original Frame.call. New ForeignCall
preparation occurs after CLAIM, with no observed foreign result until the
literal expression actually starts. A preparation failure is not sent as an
ordinary RAISED acknowledgement. A completed return/error is marked before
new bookkeeping, and the matching activation is acknowledged only by the
complete validated native receipt. Existing sticky child loss prevents an
ordinary foreign-error acknowledgement.

A continuation acknowledges its last actual effect and observes READY_RETURN
or READY_PROPAGATE. It then really returns or propagates. Its normal fast-local
release happens before the C outer caller sends FINALIZE. The actual ambient
ForeignCall and whole OperationSeries remain live through this release and
the final receipt. A real child loss during release prevents terminal success.
The final record is terminal only after the original receipt validation and
one further actual loss check.

Previously handled tracebacks retain their actual method frame/locals normally;
the bridge neither clears them nor simulates their release. A FINALIZE loss
after a normal return preserves the actual mechanical Frame, native workspace,
record and declared resource obligations. It cannot resurrect Python locals
that already released normally, and it does not invent a historical frame.

## Resource and cleanup boundaries

The existing OperationSeries is reused unchanged. Every real _execute SQL
argument handoff has a fresh SqlAttempt. The original self.store lookup is
value-preserving and occurs once, followed by the original .db lookup. The
final parameter guard retains the same parameter value and arms only that
actual SQL handoff. Independent facts remain with the full actual method and
each actual opted-in ancestor until its own FINALIZE.

This is the already declared weak, registered, same-generation Store
retirement association. It does not turn an opaque DB, a dead temporary Store,
or an overridden _execute implementation into a universally retained SQL
resource. Independent foreign parents which did not request resource capture
do not inherit invented responsibility.

The actual Frame remains DeliveryRecord.owner. A Session is attached to it
before the first handoff. A real unknown keeps the owner/session and, when it
still exists at the loss boundary, the actual continuation frame. Normal
records retire; failed records do not replay or silently reuse a workspace.
Same-Frame reentry is refused before it can own outer cleanup. Different
genuine nested public calls remain legal and causally linked.

All C-owned Python references participate in GC traverse/clear. No untracked
container hides cycles. Clear/deallocation performs reference release only,
not SQL, close, rollback, HIA entry or invented acknowledgement. The session
also binds PID, thread, exact actual ContextVar activation and actual
continuation identity. A borrowed frame pointer is never a reusable registry
key and is cleared immediately after the invocation leaves Python.

## Build, install, and supported profile

The extension is hepta._hia_slot_mechanical, compiled separately with the
current interpreter headers. The current static profile is CPython 3.11 through
3.14, GIL-enabled Linux, full version-specific C API. It is not abi3 or a claim
of execution on all those versions. Other profiles remain explicitly
unsupported for this selected bridge. The package's existing unselected
requires-python declaration remains unchanged.

setup.py adds a setuptools build_ext hook and retains the original Agent
resource builder. Ordinary wheel builds produce a platform/CPython-specific
extension and _slot_mechanical_build.json. Explicit source builds can use
tools/build_hia_slot_mechanical.py. No runtime compilation, download, retry or
new wall-time/resource quota is introduced.

The build receipt binds actual compiler argv and executable bytes, interpreter
profile, exact extension bytes and eight runtime/source inputs. The loader
captures the same bytes for parse and hash, verifies all declared sources and
the binary before loading, reads them again after loading, and repeats fresh
complete admission for every public invocation. It does not treat a receipt
as proof that qualification ran. The formal HIA builder continues to require
its original matching-current cold report, or its already explicit separate
development mode. The C receipt is an additional identity, never a cold report.

Root must separately retain actual compiler process-group completion, headers,
toolchain/version identity, wheel RECORD, installed source/binary/manifest
readback and original native-helper bundle identity. The C binary/receipt are
build outputs, not checked-in or silently trusted placeholders.

## Unresolved compatibility and qualification

Public PyObject_Vectorcall arguments are borrowed from the actual caller.
The C outer caller cannot steal or clear that vector. A direct interpreter
Python CALL may transfer stack references differently. The static code does
not prove that receiver/argument destruction is identical at this boundary.

Materializing the actual PyFrameObject, a GC-visible Session/iterator, C-owned
references, additional private globals, and mechanical allocation sites may
change process-wide GC or reference observations. C removes intermediate
Python provider frames but does not prove the old GC16 result or arbitrary
sys.getrefcount/frame-introspection equivalence. Host MemoryError allocation
points are not claimed to be one-for-one with the old implementation.

The selected callable has C descriptor type and forwards real function
signature metadata; it is not types.FunctionType and does not claim arbitrary
function-object reflective mutation/pickling compatibility. The complete
existing public84 domain remains mandatory. Private raw Frame.finish remains
a Python compatibility wrapper; it is not evidence that the canonical public
provider backchain has extra or fewer frames.

No original field, input, failure, deadline, observer, GC call, traceback,
expected label or retained-body poison is removed or normalized. All original
7822, Native6, Source3, public84, handled12, four resource methods, original
Slot Source10/Native5, and separate caller gates remain required. A smaller
frame count or successful build is not qualification.

The CI additions in this package are proposed build preparation, not authorization or permission to deploy.
