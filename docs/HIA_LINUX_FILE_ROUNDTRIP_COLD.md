# Explicit Linux file roundtrip cold and portable qualification

This owner selects `hepta.hia.linux-file-roundtrip.v2` explicitly. It does not
activate a default CLI, enlarge the original worker resource profile, or claim
whole-language/native qualification. The installed static ELF executes without
a Python interpreter or libc. Python remains the author, cold-build supervisor,
test observer before `execve`, independent VM/reference provider, and auditor.

## Source and compiler authority

`tools/build_hia_linux_file_roundtrip_cold.py` admits the actual current-source
cold replay, its complete nested qualification, all three B1/B2/B3 image bytes,
their original receipts, and the current complete source manifest. It adds its
own explicit source closure and the five versioned optional resources. A
development compiler pin, old successful report, or serialized fixture alone
cannot grant this admission. Every public admission repeats fresh checks.

The build uses actual current cold B3 to compile the process profile P1, then P2
and P3. All three compiled images must match. P3 must compile the ordinary
selfhost source back to the exact admitted cold B3 bytes. P3 then compiles the
controller, private representation resident, semantic resident and ELF packer.
The actual HIA packer produces the aggregate ELF; its complete payload extents
and bytes are checked by the existing structural inspector. No resident is
substituted with a saved development image.

Every original compilation keeps its 20-second child bound and 1 MiB output
and workspace. Each actual request, original child stdout/stderr, receipt,
complete output buffer and produced image is retained and read back. The ELF
also must fit the original 1 MiB bound. Nothing in this owner changes the B3
128-function, 1536-block or 8192-operation limits.

`--portable` additionally publishes the real compiled ELF with mode 0500 and
the exact five resource bytes in a separate bundle. The bundle manifest is an
installation record; requalification still requires fresh original cold
admission. The ELF itself needs no bundle-loading Python at execution time.

## Fixed permanent groups

Run the complete qualifier from a matching source checkout:

```text
python -B tools/qualify_hia_linux_file_roundtrip.py --cold-report <actual-cold-report> --evidence <new-directory>
```

The four groups have new permanent unittest identities. The original inputs,
order, return codes, complete stdout/stderr and assertions remain fixed in
`tests/fixtures/hia_linux_file_roundtrip_retained.zlib.json`. Its exact wrapper
and decompressed identities are pinned by the custody owner.

| Group | Methods | Required observations |
| --- | ---: | --- |
| Kernel | 130 | Every original input in order; actual static ELF return, complete stdout/stderr, unchanged input and ELF, timeout and cleanup |
| Pipeline | 7 | Original complete VM input/provider/error behavior; all three buffers under 10 million steps; six actual kernel whole-buffer comparisons |
| Tail faults | 2 | Exact C1 or C2 last-byte injection; unchanged length/full-equality guard; actual native and VM code 72/phase 7, no stdout, three complete buffers |
| Portable | 1 | Actual sdist, default and explicitly selected wheels, install, cold-built bundle, three actual installed ELF executions, resource/ELF drift refusals |

Each group and preparation keep a separate original 180-second process owner
and 3-second cleanup. Every VM has the original 10-million-step limit. Each
direct kernel observer keeps its original 20-second wall/3-second cleanup and
original CPU/address/stack/file/descriptor limits. The extra packaging commands
have a 60-second subprocess bound inside the unchanged 180+3 group owner.

The six full native F/O/W observations are written by the separately compiled
pure HIA postreturn observer. It contains exactly the actual production
controller and resident bytes. Its test-only startup writes the actual BSS
through file descriptors 29, 30 and 31 after the controller returns. Python
opens those output descriptors before `execve`; it does not construct or edit
the observed buffers. The extents are 8,388,609, 1,048,576 and 1,048,576 bytes.
The seventh pipeline row is explicitly VM-only for the original read-error
plus close-error priority case. It is not assigned an invented native result.

The qualifier re-reads every original exec request, stdout/stderr, actual
postreturn file, VM frame, compile observation, start/stop event and cleanup
receipt. It requires exact loaded/started/stopped ID order and all methods.
Skips, expected failures, unexpected successes, subtest failures, partial
reports, changed inputs and boolean substitutes for integer counts all refuse
qualification. Ordinary group failures retain later fixed groups; actual source
drift stops further execution. Failure reports and all files are retained.

## Installation and original worker resources

The default wheel continues to contain the original 210 worker resources:
NATIVE92 and ENTRY19 remain unchanged. This owner adds no HIA asset to those
roles. The independent profile registry supplies the already existing five
roundtrip assets. A selected wheel is built only with:

```text
HEPTA_HIA_BUILD_PROFILES=hepta.hia.linux-file-roundtrip.v2
```

The portable group builds both the ordinary 210-resource wheel and the
explicitly selected 215-resource wheel, using no package index or wheel cache.
It checks every resource and every installed Python source byte. The executable
is copied from the admitted actual cold build, read back, kept 0500 and executed
from the installed bundle. Missing resources, changed source bytes and a
changed ELF last byte are refused before payload execution. These tests are
explicit-profile observations, not permission to use an ambient source tree.

## Qualification boundaries and preserved failures

The original roundtrip pipeline7 succeeded in its own development experiment.
The separately frozen semantic resident R5 suite has six logical VM controls:
five passed and `root-v8-cross-target-loans` exhausted the unchanged 10-million
step budget. That failure remains explicit in every fixture and qualification
report. The pipeline seven and checker six are different fixed groups. A pass
here does not turn the separate failure into a pass and does not claim complete
semantic-resident VM qualification.

The profile uses bounded internal JSON/node/function/attribute domains. An
8 MiB file-read buffer is not a claim that the full 8 MiB external grammar is
accepted. The private representation resident accepts its three exact internal
magics; it is not a compatibility replacement for the two public canonical
entry magics. The original public representation assets remain separate.

At initial authoring of this successor, no new cold positive, Native, portable,
or CPython 3.14 qualification has been executed. The Source class checks fixed
inputs, original code projection, registration, strict refusal and evidence
mechanics only. Historical reports and source packages are retained as
historical evidence, never transferred to the new source generation.
