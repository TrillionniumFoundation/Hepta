# HIA-owned program Emitter candidate

The complete original six-method `_Emitter` policy is compiled to nine `.hepta`
units: one typed literal owner and eight 64-instruction continuation units.
`HEPTA_HIA_CORE_EMITTER_MANIFEST` is explicit opt-in, with a distinct bundle,
unit and ABI schema. Every package source, ABI, manifest and image is bound.
The ordinary emitter captures one selection for the complete operation.
Subclasses and unselected calls retain their original behavior.

The original policy AST is retained independently in the pinned `608` fixture.
The authoring adapter transports the five constructor arguments in one exact
tuple, preserving the four-bound-argument packet limit. Sole keyword mapping
calls, four-value unpacking, relative import lookup and lazy item projection
use explicit generic hosted object-runtime helpers. Lazy projection is not
replaced by eager materialization: partial `list.extend` writes and exception
ordering remain observable. Unsupported grammar fails authoring.

This candidate does **not** replace the Python object runtime, callable and
iterator plumbing, Core verifier, native byte wrapper, ELF writer, image loader,
filesystem, worker persistence, build orchestration or installation handoff.
The generic 18 object packet opcodes and four additional mechanical callable
helpers remain hosted. Core `_Function` lowering is a separate admitted bundle;
tests must distinguish Emitter-only selection from paired selection. Neither
selection enables itself by default or authorizes legacy retirement.

Development compilation may explicitly reuse an older qualified compiler;
that is not matching-source cold acceptance. Exact source regeneration, own
cold replay, all native gates, full regression and independent source/installed
replays remain required before integrating this candidate.


## Development observations (not formal acceptance)

The nine current HIA units were actually compiled with explicit reuse of the
v80 source compiler. The complete Emitter development gate executed all 110
planned tests (9 component, 51 original machine and 50 original Core), zero
anomalies, in 109.44 seconds under the original 180-second owner. All six Emitter
modes had actual admitted native step returns, all source and image identities
were stable, and retained Emitter methods were forbidden for original callers.
The installed wheel ran isolated without site packages, authoring imports or
PATH tools. This does not admit current-source cold identity. A separate paired
Emitter/Function run remains required; its complete source and image pins must
be retained separately from this single-owner observation.


The separate paired development run also executed all 110 tests, zero anomalies,
in 137.14 seconds (137.29-second original process owner, limit 180). Both the
Emitter and independent Function bundles were source/image pinned before and
after. The original machine and Core groups returned actual native Function
steps, while all original Emitter/Function bodies and five scoped helper bodies
were forbidden. This remains explicit development-only compiler/bundle reuse,
not current-source cold acceptance or default whole-stack activation.
