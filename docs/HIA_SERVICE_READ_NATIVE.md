## HIA policy and foreign expressions

The one-mode protocol uses an 80-byte request, 96-byte receipt and 128-byte
state. Each actual foreign operation requires a newly issued claim followed
by a matching receipt with sequence, nonce, phase, state checksum and buffer
guard checks. HIA owns the following complete control flow:

| Section | Native decision or continuation | Explicit foreign boundary |
|---|---|---|
| Initial artifact | Read before cursor/limit; retain original unpack order | Original dynamic `store.get`, mapping and unpack protocols |
| Cursor | Presence, missing row, id then SHA short circuits, reject and offset | Original SQL/fetchone chain; opaque comparisons and truth |
| Page | Original limit and slice order | Dynamic `int`, `get`, arithmetic and slicing |
| Encoding | Whole-data decode first; first trim loop; base64 fallback | Original decode and base64 operations |
| Budget | Repeated test; shrink; format-specific decode/trim; repeat | Three original wire calls and opaque numeric protocols |
| Cursor publication | End comparison; digest; INSERT only on the native branch | Original digest expression, SQL tuple and dynamic execute |
| Return | Construct result, retire original locals in original order, return | Original aliases and object destruction |
| Errors | Inner/outer matcher order, first/later trim distinction, propagate or resume | Actual interpreter exception matching and active exception state |

The fixed linear expression helpers preserve ordinary method binding,
callable capture and temporary lifetimes. They contain no pagination loop,
cursor-admission policy, encoding-choice branch or fallback to the retained
body. The complete wire-budget expression preserves first-len capture before
the first wire and second-len/outer-wire capture before the inner wire. Its
temporary operands stay on the original interpreter evaluation stack, so a
failure in the right operand releases the left operand at that cutpoint.
The same rule applies to cursor comparison/truth and the end comparison.
HIA consumes their scalar truth observations and owns all short circuits,
branches and repeated budget decisions. There are 32 fixed foreign ports.
The earlier unexecuted 51-port split became 42 to preserve temporary
expression lifetimes. This static successor replaces its eleven fixed-order
release ports with one actual `release_locals` operation; the existing
`return` acknowledgement remains the distinct native terminal transition.
Neither original inputs nor test bodies have changed. HIA source is now
generated for this port table; no native image has been built, and an earlier
42-port image must not be reused.
Opaque numeric operations remain hosted; this is not a claim that arbitrary
Python numeric protocols or the wire/codec/hash/SQLite implementations were
rewritten in HIA.

The original outer `UnicodeDecodeError` handler covers the whole-data decode
and the first trim loop, including its exception matching and slicing. It
does not cover the later budget trim loop. The image issues separate inner,
outer and later matcher ports. The host executes the interpreter's actual
`except` matching while the original error is active; it does not replace
that protocol with `isinstance` or normalize exception fields. A native
unwind phase leaves the handler before the next decode/budget operation.

Normal return has one explicit native-issued local retirement after result
construction. The complete original local slots, in source order, are
`self, args, ref, data, _, offset, row, limit, chunk, encoding, content,
next_cursor`. The adapter maps the first, second and fifth names to
`service`, `arguments` and `metadata`, and preallocates a builtin dictionary
with all twelve slots. A fixed private frame/dict probe chooses the storage
order for the current interpreter and caches only those fixed names. Later
assignments replace values without moving slots; unbound original locals
have inert `None` placeholders. No user object enters the probe, and no
per-invocation type, finalizer or garbage collection is introduced.

HIA issues `result -> release_locals -> return`; the one release operation
calls the builtin dictionary's `clear`. The interpreter supplies object
destruction mechanics. The result dictionary independently retains its
original artifact/content aliases. Exceptional paths leave the same locals
in their slots until the actual traceback is released. No host `finally`
clears them early, and no exception frame is forcibly cleared.

This storage successor has generated source but is still unexecuted. The full finite gates
must compare normal and exceptional release under the same actual runtime,
including the already frozen metadata/chunk and consumer-release cases.
The service-artifact companion's qualified six-slot repair does not prove
the read owner's twelve-slot behavior. A 3.12 or 3.13 observation does not
establish the order on 3.14; differences must not be normalized away.

## Pending resource and qualification boundaries

The adapter explicitly requests the separately reviewed weak-registered
capture policy from the beginning of each effect. This static composition
includes the exact shared R3 implementation on its reviewed source base.
That is an implementation identity, not runtime qualification. The final
integration source must be frozen before candidate execution. Other owners keep their
existing capture policies. An unregistered opaque receiver is not assigned a
guessed Store or DB relationship.

The direct cursor SELECT/INSERT expressions have an explicit final argument
delivery guard. At each original Store receiver, the new binding also reserves
one registered weak identity/generation fact for that activation and its
actual opted-in ancestors. Both reservation and the final argument query
finish with a live-record check. SELECT and INSERT use separate HIA effect
activations and separate one-use facts; this is not a general multi-SQL or
transaction protocol. The new six-group resource controls have not run, so
the candidate does not yet claim this resource-retirement boundary closed.
They additionally require a same-source service-artifact companion to observe
a real strong ancestor's independent ACK, rather than manufacture a parent
confirmation in test bookkeeping.

The service and shared source changes have one explicit reversible successor
record in the complete eight-file composition. Six existing successor
records remain byte-identical. Admission requires either all original files
or that entire exact successor; partial mixtures fail. The original c019
fixture, its other 86 whole files, other 18 shared pins, and its twenty
original adapter definitions plus the one previously reviewed context
protocol successor remain checked. The older full service SHA is never
silently accepted or dynamically re-pinned.

The existing production limits, original test bodies and catalog remain
unchanged apart from the pre-existing registry's one exact helper-count
assertion: this composition adds read as helper 42, so its decimal
literal changes from 41 to 42. The ordinary-source admission reverses that
single declared literal and requires every other original byte to match.
Composition with other new owners requires the actual registry count, not a
looser assertion or a different original test inventory.
There is no new wall, heap, page, loop, integer or frame-count limit. No old
implementation has been removed. Current-cold qualification, installed-worker
qualification, complete original caller gates, all-input equivalence and
whole-language/self-host closure are false until their actual independent
gates establish their respective narrower claims.
