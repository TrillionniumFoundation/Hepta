# HIA ordinary service requests owner

This explicit component contains the exact original eight request/discovery
method bodies of `HIAAgentService`: `_profiles`, `_examples`, `_error`,
`_hia_describe`, `_hia_artifact`, `_hia_read`, `_hia_inspect`, and
`_hia_candidate`. The frozen original source fixture is an independent test
oracle. The generator emits all eight bodies, the profile context-manager
region and the original inspection generator into one HIA image.

The component does not claim whole-stack self-hosting, a default selection,
current-source cold qualification or production activation. Those statuses
require their own completed evidence. Retained references remain available
while native closure is incomplete.

## Ownership and effects

HIA owns profile construction, request branches, page/cursor decisions, UTF-8
retry and wire-size loops, inspection selection, candidate-source selection,
and the order of storage/provider effects. Python supplies fixed object,
import, exception, context-manager and call representation primitives. It
does not execute these retained Python business bodies for a selected owner.

Storage and SQLite, file capture, codecs, schemas/opcodes, Core verification,
assembly, edit/query, proof contracts and machine emission remain separately
declared providers. This component does not relabel their work as its own
native implementation. Direct machine-return observations and poisoned old
request methods are required by the original-caller qualifier.

`_profiles` enters the actual captured proof-contract scope through a fixed
context-manager primitive. HIA runs the whole body in a child frame sharing
the original named cells. Suppression is accepted only for a confirmed HIA
error terminal; an uncertain foreign outcome cannot become a normal return.

The page loops break only from successful try bodies. Exception destinations
are encoded on each HIA-issued effect; that success edge does not enter an
active exception handler. Unreviewed jumps out of handlers or finally regions
are rejected by the author. The original loops retain complete-artifact
UTF-8 admission, boundary trimming, binary fallback, double JSON wire-size
accounting and exact immutable cursor binding.

Imports use each original grouped `IMPORT_NAME` once and actual individual
`IMPORT_FROM` operations. A module argument moves off the primitive's named
parameter before import, so a retained ImportError does not acquire an extra
module owner. Provider bindings are observed when the original body observes
them. HIA chooses the next operation after the actual one-use acknowledgement.

## Selection and identity

`HEPTA_HIA_SERVICE_REQUESTS_MANIFEST` explicitly selects a source/image-bound
manifest. Service construction captures that immutable executable for its
lifetime, including profile initialization. A nested static `_examples` call
uses the active same owner. An independent static call re-admits its own
selection. Closing a service forbids new frames from that service owner.

Every independent admission rereads the manifest, source and image, rejects
non-regular inputs without blocking on FIFOs, and reads back the same inputs
after mapping. Cached mappings never cache a mutable admission decision.
The exact complete HIA policy-table digest and all physical function layouts
are checked against fixed generated ports. The fixed CPython ports are imported
inside explicit native factory admission; a default import does not execute
their Python 3.12/3.13/3.14 ABI guard.

The owner is registered as a held service mechanism. It is outside the strict
Core import closure, and all external providers remain explicit. Checker
custody binds the actual held mapping, manifest and source bytes.

## Build and qualification

The cold builder requires the complete matching current-source cold report
with the original 180-second work and 3-second cleanup bounds. It binds every
required input before creating output. It checks the compiler's actual receipt,
its published readback and all consumed inputs before publishing a manifest.
Each compiler child retains the original 20-second bound.

The explicit `--development` route accepts a retained compiler and records
development scope only. It cannot provide cold authority.

The caller qualifier preserves all four original Agent modules, all 48 ordered
IDs and their exact source bytes. Its separate namespace and ledger groups
preserve their original nested 35/48 IDs, numerical budgets and 1800-second
group limit. Missing tests, changed order, skips, expected failures, unobserved
native modes and an old-body call all refuse qualification. Every raw failure
and original source/receipt observation is retained.
