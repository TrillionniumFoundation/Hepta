# Native Clang command-log component

This component supplies the production command-log path for the private Clang
Value profile `HIACVPL1`. It executes the existing native Clang producer and
uses the same already bound Value arena. The full public LLVM API remains open:
fresh public record emission and origin checking, late output-Path conversion,
bounded-resource composition, and final whole-release qualification are separate
requirements. No Python callback, prefix write, fabricated syscall result or
second Value arena supplies production behavior.

## Native construction

Nine policy modules are compiled twice with the retained source compiler
`494833999e25ac74ea6ad1de41235c01bfa036951f212604026cb8be686c78af`.
Their source, byte length and flat SHA-256 are bound in the qualification JSON.
The original 128-function, 1536-block and 8192-operation compiler profile is
unchanged. The root Clang build combines the policies with fixed mechanical
calls and native whole capsules, and independently checks the packed bytes.
The component qualification executes that actual shared library through a sealed
memfd. It verifies the mapped complete text against the actual ELF text and
separately verifies every input component pin; fixed relocations are not
mistaken for unchanged input-component bytes.

The input remains 256 bytes followed by Core, ABI and absolute filesystem path.
It preserves the PC1 target, kind, layout and actual compiler-capability fields.
Only the PL1 profile adds the actual borrowed log-list capability at bytes
96, 104 and 112. The native initializer captures the bound Value entry, context,
extent and nonce from the enclosing Clang owner, retains its context token and
the actual list, and checks the plain-list requirement. It does not accept a
request-supplied entry or arena pointer. The old BC1 and PC1 profiles retain their
prior domains.

## Fixed calls and ownership

| Location | Fixed action | Contract |
| --- | --- | --- |
| Inner policies 108, 109, 110 | Log transport, failure formatting, retirement | Actual inner control at bytes 2560–3071 |
| Inner child 16 | Native Q2 log codec | Exact argv filesystem decoding and cwd WTF-8 |
| Inner child 17 | Whole log owner, entry 0 | Append or patch the actual retained row |
| Inner child 18 | Actual early exception factory | Borrow the enclosing owner's real primary exception |
| Inner child 19 | Whole cwd owner, entry 0 | Sealed descriptor, including parent traversal for long cwd |
| Inner child 20 | Bound Value entry | Same actual enclosing arena |
| Inner child 21 | Native string representation | Fixed pure string/bytes formatting |
| Inner child 22 | Actual exception replacement | Clone, establish context, commit, and retire old references |
| Outer policy 113 | Logger initialization and close | Preserves the enclosing error and cleanup state machine |
| Outer child 23 | Whole logger bind, entry 7 | Captures actual outer entry/context/extent/nonce |
| Outer child 24 | Whole logger main, entry 0 | Retires logger references and its context token |

The append occurs before each actual bounded command capture. Completion and
failure update the same retained dictionary even if the caller removed it from
the list. The initializer's strong list reference keeps the sink alive after
the caller drops its original capability. A capture failure first creates the
actual typed primary exception; the log observes that object before later
temporary-directory cleanup can change the final exception.

Each temporary capability, mapping and cwd descriptor stays in an explicit native
ledger until actual consumption or retirement is confirmed. Queue-only resource
pending remains distinct from local mapping pending. No error status is used as
a substitute for a known/consumed fact. A failed map retirement can be retried
through the ordinary native enclosing retirement operation.

The private replacement helper takes a borrowed exception still held by the
logger. It clones that reference, sets the actual exception context, commits the
new enclosing primary slot, and retires the old slot. Its committed flag means
replacement, not export delivery. It chooses three actually free temporary
slots; a live CaptureFailure in slot 61 is preserved.

## Actual behavior qualification

The two frozen seven-group suites execute the same 61-role native product and
the formal Value 115 owner. They retain the original CPython 3.14.4
`_run_logged` dictionary contents and insertion order as the comparison oracle.
Python is confined to test inputs, observations, syscall notifications and the
original oracle.

The normal suite covers three actual Clang captures, invalid sink types,
retained-row identity after removal, caller capability drops during capture,
actual `munmap` EIO with native retry, surrogate filesystem cwd, and a cwd longer
than 4096 bytes. The fault suite covers actual waitid EIO, actual signal-query
EPERM, actual Clang invalid-UTF-8 stderr, and four actual logger mmap ENOMEM
points. The latter verify real MemoryError objects, preserved primary exception
identity in `__context__`, and the live CaptureFailure slot case. Every case
retires its actual references and descriptors before success.

The native Q2 codec separately retains the original 1759 native calls and
60 actual Value JSON-import checks, with 1046 new calls including 975 exact
OSError formatting comparisons. Capacity and malformed-frame checks are kept.

The final fourteen behavior groups and the source-freeze comparison completed.
The launcher then encountered filesystem ENOSPC while saving only its aggregate
report. Both complete behavior reports survived. The qualification JSON records
that persistence failure and its explicit recovery from the original reports,
the captured source bytes, and the original launcher output. The failed empty
aggregate is preserved; no failed launcher is relabelled as a clean exit.

## Remaining public work

This qualification covers the fixed native command-capture exception families
exercised above. It does not establish a general `str` implementation for every
arbitrary user exception, nor a complete public LLVM or Runtime API. Fresh
HIAProgramLLVM record construction, all origin fields, late output-path
conversion, bounded-resource composition, installation and final repository
closure remain explicit higher-level requirements.
