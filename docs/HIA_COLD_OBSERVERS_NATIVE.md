# Native cold observer references and phase plans

The original observer reference gates now run as immutable native plans. The pre-B0 phase imports independent native source admission, projection, packet construction and the complete resource VM. It imports no target or successor compiler. Every expected byte is calculated in this execution.

## Complete native observer windows

The actual native_observer_packer.hepta body is appended to each original reference wrapper. Nine fresh VM executions retain the original 128-byte disjoint windows: eight return 129 scalar values and the last returns 84. They cover all 1,107 ELF bytes. Each call keeps the original one-million-step, 256-frame and 16 MiB heap budgets, validates typed byte returns, and conserves its owner and loan ledger. The assembled output equals the independently constructed native observer byte for byte.

## Linked observer references and reconstruction

The original private linked profile retains thirty million steps, 128 frames and 4 MiB heap. Its pre-B0 plan checks the two complete object-packing inputs and all nine original policy continuations, including exact resource limits, descriptor path, f0 name, return-snapshot custody, elapsed-time framing and committed response. The complete control/workspace observations remain in the lossless journal and reference publication.

The later build phase compiles the actual policy and packer with the current compiler. A fresh independent complete VM executes that actual packer on the actual compiled policy bytes and compares the complete ET_REL output. The separately qualified HIA observer executable linker resolves the closed five libc imports. Actual processes use libc startup, dlopen, f0, return snapshots and normal exit. No host compiler or linker runs in the plan. The system dynamic loader and libc remain explicit mechanical dependencies.

## Phase interfaces

`generate_hia_cold_observer_plan.reference_observers(p, h, cases)` creates a pre-B0 plan. Its imports are assembly, projector, observer, check, utility, reference_packet, vm, reference_packet_30m, vm_30m, linked_packer_root, native_packer_source, linked_policy_source and linked_packer_source. The reusable test harness also admits independent observer_linker and linker roots for the later build phase. The case data is cold_observer_cases.json and contains source wrappers, never expected output values.

The four publications are reference-native-observer.bin, reference-linked-policy.bin, reference-linked-packer-wire.bin and reference-observer-source-pins.bin. `qualify_observer_builds(p,h,compiler,label=...)` rechecks all three current source digests, consumes the native image/reference wire/pins, and publishes native-observer.elf and linked-observer.elf. Both original and modified compiler phases were executed independently.

The packet owner mode 2 now accepts the projected register-bounded parameter domain and bounce-bounded return domain. Modes 0 and 1 keep their original sixteen-parameter restriction. The 32 MiB VM-packet output bound, byte snapshots, original per-call budget fields and legacy packet semantics remain unchanged. The complete VM itself is unchanged. The private 30M profile is separately named and pinned; ordinary callers still pass their original one-million or ten-million limits.

## Strict owned object inspection

cold_owned_elf_inventory.hepta accepts raw ET_REL on standard input. It checks every original inspect_owned_object condition, including all seven section identities and shapes, exact five symbols, both allocator imports, nonexecuting stack, payload order, relocation spacing/type/addend and actual zeroed call sites. Success returns the exact actual .text bytes; refusal returns a nonzero status with empty output. It neither repairs nor re-emits input objects. Independent native construction passed 195 fresh original-inspector comparisons and all seventeen original owned cases through actual source compilation, native linking and dlopen, including real SIGILL and shared writes before termination.

## Exports split publications

The exports author now exposes publish_reference_bundle and qualify_exports_from_bundle. The reference plan publishes the four HIAEXR01 response objects and one word-reference.bin, keeping every phase below the original 64-import bound. The word bundle is HIAEWR01, count 28, the 32-byte current compiler-source SHA256, then twenty-eight records of three u64 lengths and the full source/initial/expected spans. Its static slice layout is derived from the current input helper spans, and every actual emitted length is checked before publication. Each qualification phase validates the header, all lengths, complete extent and current source digest. No reference from another source or a historic golden is silently substituted.
