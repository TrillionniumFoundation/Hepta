# HIA service context owner

`service_context.hepta` owns the current Agent context creation, retained-context
lookup, total-wall budget and remaining-millisecond policy. The independent
reference consists of the exact four bodies from published commit
`b569c210a807af29a3ad816679f2b9437c5c6875`, tree
`84b67370cd899f969a7130605f99bb056904af04`. The current `_consume_attempt`
route is a fixed foreign port: the context owner never substitutes direct SQL
for an installed candidate-budget provider.

## Runtime ownership

The HIA image chooses effect order, short circuits, both workload loops, budget
field iterations, external-cost checks, retained identity/profile checks and
terminal outcomes. A separate entry in that same captured image computes exact
signed addition, subtraction, multiplication by one million, floor division by
one million, comparisons and nonnegative clamping. Operand bytes and workspace
grow with the actual integers; there is no new integer width, decimal digit,
active-context count or parallel-service quota.

The production worker snapshots JSON before validating it. Both fixed
`buffer_size` providers return exact nonnegative integers, so the workload
snapshot sum is HIA integer arithmetic. Arbitrary replacements of private
providers are not an expanded public language profile. Existing direct Python
object/clock operators are retained as explicitly hosted interoperability ports
when an operand is not an exact integer. The actual clock and stored budget
path uses HIA arithmetic. The original strict `elapsed > limit` comparison,
floor division, three-second caller budgets and candidate-consumption route
remain unchanged.

Python still supplies schema validation, profiles, buffer descriptors, object
representation, immutable artifact publication, SQLite, platform/clock
observations and execution-budget effects. This component does not claim that
SQLite or the whole ordinary worker has become native.

## Selection and custody

`HEPTA_HIA_SERVICE_CONTEXT_MANIFEST` selects one source-bound executable image.
An absent selector retains the current body; an empty or invalid selector
refuses without falling back. Every operation rechecks its captured manifest,
packaged source and image. The existing administrator native-helper bundle also
pins this image and restores the previous environment after its scope.

Each frame reserves a growable process custody entry before its first effect.
HIA issues one port, accepts one claim and accepts one acknowledgement. Replayed
claims, mismatched identity, corrupt state and unknown ports refuse. A confirmed
foreign exception is reraised by its real Python handler, keeping the original
exception, cause, context, notes and traceback. This introduces no private
CPython exception ABI or interpreter-minor restriction.

If an effect or acknowledgement is unconfirmed, its frame is permanently
fenced. Its service, actual resources, arguments and observations remain held
until the worker process exits. Further context operations on that service
refuse. The owner does not repeat an effect, silently fall back or claim that an
unknown effect has been undone. Existing explicit caller cleanup is still an
actual caller effect; custody does not invent a new cleanup. A fork rebuilds
only the custody lock, preserving inherited unknown references while refusing
to resume a parent frame.

## Qualification

`tests.test_hia_service_context_native` compares generated source and exact
frozen bodies, every observed foreign failure point, real SQLite partial
effects, wide native integer arithmetic and independent Core-VM transitions.
It exercises four current public routes with all four retained references
poisoned, real installed wheel resources, administrator bundle selection and
source/child-manifest drift refusal. A disposable process verifies an actual
context INSERT followed by lost acknowledgement, without erasing its unknown
custody entry.

The actual public-route control also selects context, Store lifecycle, execution
budget and candidate budget together in one pinned helper bundle. All four
images must receive real native entries while the retained policy bodies are
forbidden. The context still has its original 3,000 ms budget, creates its real
SQLite records, consumes an attempt through the installed candidate provider,
computes remaining time and closes the Store. Matching-cold runs build every
component from that same current report; explicitly selected development runs
retain their own labelled compiler receipts. This checks their actual shared
service and journal boundary without replacing the separate installed-worker
or complete original-caller gates.

`tools/qualify_hia_service_context_callers.py` freezes and runs all 50 original
tests from the four complete current Agent tool/campaign/buffer/lease modules.
It records actual HIA control and integer entries and poisons the four Python
policy bodies. No original source, skip denominator or deadline is changed.

Both build and test entry points accept matching-current-source cold evidence
or explicitly labelled development construction. Development evidence does not
qualify a different cold source tree or whole native installation.
