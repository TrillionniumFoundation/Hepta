# HIA compatibility contract

Generated by `python tools/check_hia_compatibility.py`; check committed tables with `python tools/check_hia_compatibility.py --check`.

The schema registry, opcode catalog, LLVM profile/publication tables and actual wrapper extension rules supply these values. `tests/test_hia_compatibility.py` checks real verification, LLVM text emission, normalization and rejection paths without requiring Clang. Its optional native test also builds v8 objects for every listed target and checks ELF machine, RV64 ABI flags and symbol inventories. Run that gate with `HIA_COMPATIBILITY_REQUIRE_NATIVE=1 CLANG=/path/to/clang python -m unittest tests.test_hia_compatibility` to fail if the actual compiler is unavailable.

This table records admitted interfaces. It is not a verification receipt, a successful native compilation, or target execution evidence. AArch64/RV64 execution requires its own measured qualification receipt; emission support alone does not supply one.

Machine-readable contract: [hia-compatibility.v1.json](hia-compatibility.v1.json).

## Public scalar input and output ABI

The public C-compatible entry accepts the integer and boolean types below and returns at most one scalar. The table gives the LLVM extension attribute for **both the argument and result** of that type. `none` means no LLVM `signext`/`zeroext` attribute; it does not promise that unused hardware register bits have a value.

| HIA type | LLVM value | x86-64 argument / result | AArch64 argument / result | RV64 argument / result |
| --- | --- | --- | --- | --- |
| `bool` | `i1` | `zeroext` / `zeroext` | `none` / `none` | `zeroext` / `zeroext` |
| `i16` | `i16` | `signext` / `signext` | `none` / `none` | `signext` / `signext` |
| `i32` | `i32` | `none` / `none` | `none` / `none` | `signext` / `signext` |
| `i64` | `i64` | `none` / `none` | `none` / `none` | `none` / `none` |
| `i8` | `i8` | `signext` / `signext` | `none` / `none` | `signext` / `signext` |
| `isize` | `i64` | `none` / `none` | `none` / `none` | `none` / `none` |
| `u16` | `i16` | `zeroext` / `zeroext` | `none` / `none` | `zeroext` / `zeroext` |
| `u32` | `i32` | `none` / `none` | `none` / `none` | `signext` / `signext` |
| `u64` | `i64` | `none` / `none` | `none` / `none` | `none` / `none` |
| `u8` | `i8` | `zeroext` / `zeroext` | `none` / `none` | `zeroext` / `zeroext` |
| `usize` | `i64` | `none` / `none` | `none` / `none` | `none` / `none` |

`usize`/`isize` are 64-bit in this closed word model. RV64 `u32` uses `signext`, matching the LP64D convention that extends 32-bit integer values to XLEN with bit 31. AArch64 emits no narrow-argument/result extension attributes.

| Interface shape | Native wrapper behavior |
| --- | --- |
| No result, or one `unit` result | Returns LLVM `void` |
| `unit` argument | No public wrapper |
| Two or more results | No public wrapper |
| Owner, loan, chain, nominal record/enum/task argument or result | No public wrapper |
| `unit` argument or multiple scalar results in an explicit Core `exports` list | Whole native emission rejects with `E_HIA_PROGRAM_ABI` |
| Resource descriptor in an explicit Core `exports` list | Core verification rejects with `E_HIA_TYPE` before emission |
| Unsupported implicit entry | Omitted; at least one and at most 128 representable scalar entries are required |

Private calls may use resource values and multiple results when the independent Core verifier admits them. Host wrappers must retain the exact scalar widths, boolean contract, allocation and trap boundary; generated metadata never permits constructing ownership or loan descriptors.
