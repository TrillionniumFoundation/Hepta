## Closed implementation paths and required evidence

The Rust path composes chain descriptors/nodes, byte payloads, bulk operations,
borrowed arguments and v8 returned loans in one Machine and ledger. Logical
`Owner` and `Chain` identities cannot alias solely because their numeric IDs
match. Call-formal scope witnesses distinguish aliased readonly parameters
without inventing source borrow events. Value, trap, allocation failure,
call/heap/step budget and stopped-destructor observations require full ledger
agreement. See [HIA_RUST_RETURNED_CHAINS_V8.md](HIA_RUST_RETURNED_CHAINS_V8.md).

The C path retains the exact capture source operand, semantic flags and
physical source inventory. It reads original result/parameter types before
signature or record adaptation. Fixed and incomplete array spelling can be
admitted only with a compatible bound original-type receipt and the required
pointer contract. Runtime-sized parameter entry effects and forged/mismatched
types refuse. Strict JSON contracts distinguish absent from empty input and
reject duplicate keys and unsupported Python object hooks. See
[C_ORIGINAL_PARAMETER_TYPES.md](C_ORIGINAL_PARAMETER_TYPES.md).

Native scalar optimization keeps its v1–v7 boundary. A v8 Core that can be
interpreted or directly compiled does not thereby enter a scalar proof or
publication profile. Explicit scalar state, generation/revision checks,
cancellation, old-generation leases and rollback share the existing runtime.
The measurement profile binds actual before/after artifacts and declared
sample, call and cost denominators, with fixed noise and net-benefit rules.
An identical artifact, noisy run or unpaid cost does not establish a gain.
See [HIA_NATIVE_LIFECYCLE_CONVERGENCE_20261028.md](HIA_NATIVE_LIFECYCLE_CONVERGENCE_20261028.md).

The qualification workflow configures Cargo home/target before the first
Rust test, requires the pinned Cargo payload and installs libclang alongside
Clang. Both full-unit entrypoints accept and record an explicit 1–3600 second
budget. Their existing defaults remain 900 seconds for `release_check` and
1800 seconds for the standalone unified qualifier; CI selects 3600. All other
gate deadlines and acceptance rules stay intact, and timeout reports preserve
partial output. A larger time budget is not a successful qualification.

## Same-source acceptance

Use `tools/qualify_hia_integrated.py` with the exact clean `--expected-head`
and all required tool/bridge paths. It runs the Cargo crate and one complete
verbose Python discovery; critical groups are subsets of that discovery.
The original-type reader gate actually loads libclang and checks its reported
version, then records compiler, library, Python and worker bytes in the input
inventories. The full test denominator is separate from every native call,
differential observation, refusal process and independent audit group.

Retain detailed same-source collectors for returned chains, earlier v8
returned loans, resource budgets, AArch64/RV64 execution, original C types,
complete migration components and native lifecycle/measurement controls.
Collectors must preserve failures, raw process streams, actual tool and
artifact identities, declared inputs and an unchanged-source result. A
development run on a dirty merge is useful debugging evidence and remains
unqualified. Remote publication is independently confirmed by its actual
commit/tree and branch; a successful local test does not establish publication.

Pre-publication review also requires retained original Rust CLI/build streams,
complete RingBuffer binaries, transition observations and native command logs,
and original musl boundary-process outputs. The external nine-role replay
wrapper rejects observed source drift permanently, verifies each role's exact
receipt schema and handles its own process group before hashing outputs. Its
process-group cleanup does not claim to sandbox descendants that deliberately
leave that group. These retention and orchestration controls are additional
evidence requirements, not extra language capabilities or performance wins.

## P0–P7 limits that require further implementation or external evidence

This increment closes concrete composition and acceptance-path defects within
the named profiles. It does not mark the entire P0–P7 program complete.
General memory and provenance, arbitrary recursive ADTs, complete partial
initialization, escaping/foreign lifetimes and asynchronous cancellation need
their own semantics, legal compositions and stable counterexamples. Rust
production authority still requires the complete declared switch qualification.

Cross-platform ABI and external callback/lifetime claims need actual target
toolchains and execution. Complete C/C++ library migration needs configuration
and declaration inventories plus replayable native differentials and cost.
Independent held-out Agent/model productivity, representative service
throughput and tail latency, physical device protocols, whole-language
soundness and backend refinement remain separate unmet gates. QEMU, finite
scalar proofs, synthetic measurement controls and this local host cannot
substitute for those results. No absolute safety or general performance
superiority claim follows from this checkpoint.
