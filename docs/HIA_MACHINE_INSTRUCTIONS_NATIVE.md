# HIA machine instruction control

This component moves the decision control of all 41 public Code instruction
methods into the HIA continuation machine. It composes with the six HIA Code
state operations and the 37 HIA instruction byte commands through three explicit
manifest selectors. An unselected Code and existing subclasses keep their
existing behavior until the replacement has completed the integration gates.

## Native control and retained value operations

HIACIN01 admits an 80-byte request, an 8-byte result and a private 2,048-byte
continuation workspace. HIA chooses exact operand/type/range admission, condition
aliases, ASCII external symbols, option truth transitions, virtual call order,
register observations, branch/fixup insertion, relocation dictionary construction,
and byte commands. The bridge executes each requested primitive object operation
once. A malformed acknowledgement or failed effect makes its session terminal.

The caller's actual data, labels, fixups, relocations and option objects remain
visible. Foreign equality/truth, attribute binding, arithmetic, Python objects
and CPython exception construction remain hosted primitive boundaries. In
particular, the exceptional signed-byte pack path preserves the original
struct.error after a changing foreign truth object; it cannot produce admitted
instruction bytes. These remaining primitives are work for the native object,
text and integer runtime, so this component is an intermediate ownership move
and does not qualify an entirely HIA runtime.

The retained Code and NativeEncodedCode class bodies remain available as exact
reference fixtures. Their methods are forbidden during selected ordinary caller
tests. The only retained NativeEncodedCode method used by this component is the
stateless _bytes dispatch to the separately selected HIA byte image.

## Source, installation and selection

The HIA source is generated by tools/generate_hia_machine_instructions.py and
included in the actual installed wheel. The strict builder rejects a missing,
stale or incomplete matching-source cold report before creating its output.
Selected images recheck installed package source identity even when warm.

HEPTA_HIA_MACHINE_INSTRUCTIONS_MANIFEST requires both
HEPTA_HIA_MACHINE_STATE_MANIFEST and HEPTA_HIA_MACHINE_ENCODING_MANIFEST.
A whole backend emission pins all three selected or unselected owners, and its
implementation identity binds all selected source and image bytes.

## Required observations

The dedicated 12 methods cover source/Core roundtrip, all original compiler caps,
exact retained class fixtures, fail-closed cold admission, selector/subclass
behavior, the original 159 instruction observations, all 41/6/37 native entries,
word/displacement/condition/symbol boundaries, error precedence, changing foreign
truth and register maps, method and append binding, actual 64 MiB state, one-shot
failed effects, whole-emission selector pinning, warm source refusal and a real
installed wheel under -I -S -B with an empty PATH and authoring imports forbidden.

tools.qualify_hia_machine_instructions_callers also executes every original
method in the unchanged five-module caller tuple: 51 loaded and 51 executed.
All five failure/skip categories and loader errors must be empty. Source pins,
manifest bytes, images and the immutable development bundle must remain stable.
Matching-source cold selection and explicit development selection are separate
scopes. No development result supplies a matching-source cold or full-discovery
pass, changes the default backend, qualifies all foreign inputs or authorizes
removing the old stack.

The original cold limit remains 180 seconds with two workers and all 38 phases.
The original full discovery and owner limits remain 5,400 and 10,800 seconds.
The original caller timeouts and method denominators are unchanged.
