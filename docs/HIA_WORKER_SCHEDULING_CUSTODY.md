# Explicit five-family worker custody

The optional `hepta.hia.native-helpers.v3` administrator capsule extends a
complete v1 or v2 capsule with one to five fixed in-process scheduling owners:
execution observation, Core Function, Core Emitter, byte wrapper, ELF writer.
It is a hosted custody bridge, **not** a native object runtime, native SQLite
store, default service switch or whole-product closure.

The root SHA256 pins its complete production Python inventory and every selected
outer manifest. Admission captures and rechecks the base helpers/report/wire,
all source and ABI inputs, all unit manifests and images, and each aggregate
container before mapping scheduler code. Unit images retain the original 1 MiB
bound; aggregate containers retain their separate 64 MiB bound. There is no
manifest-supplied class, factory, namespace, child command or dynamic compiler.
The root rejects unknown/duplicate families and only admits the in-process schema.

The five ordinary installed selectors return captured owners only for the fixed
path, family and original module namespace. Sessions verify the actual registered
owner and peer before effects. Old held owners, foreign threads/processes, expired
owners and host `run`/`step`/`handoff` are refused. Native HIA still owns internal
unit selection and handoffs. The eighteen Python object primitives are unchanged
and remain explicitly hosted. Source/resource/runtime file drift is attested at
the original worker identity boundaries; post-effect failures remain uncertain
and must use the original observation/recovery path, not retry as a new success.

Existing v1/v2 capsules remain unchanged and continue to reject all five unregistered
schedulers before mapping or effects. Empty/unselected scopes still reject them.
The v3 scope preserves v2 captured request/report/wire lookup and root identity.
Original worker and outer deadlines, primitive ABI and compiler limits are unchanged.

Create a JSON object mapping fixed family names to already built manifests, then:

```sh
python -B -m tools.build_hia_worker_scheduling_bundle \
  --base-bundle /absolute/worker-v2.json \
  --schedulers-json /absolute/families.json \
  --output /absolute/worker-v3.json
```

Creation is exclusive and does not activate a worker. The printed SHA is supplied
to the existing `--native-helpers-manifest` and `--expected-native-helpers-sha256`
worker flags. Creating a pin is input custody, not a cold or correctness receipt.
Formal tests require the current source's cold compiler. An explicitly selected
older-compiler fixture is development-only and cannot override current cold.
