# Bind finite proofs to the program bytes actually admitted and executed

The original implementation and a terminal-only comparison both produced a
false proved result for two different programs. The retained ABA counterexamples
executed 512 calls for the full 256-input domain, temporarily replaced the left
program before execution, and restored its bytes after each call. Initial and
final hashes were identical despite the false proof.

## Product change

Both Service host proof methods now capture complete canonical and structured
input bytes, create private program objects, and admit those initial inputs.
The ordinary finite route performs the original two full admissions and uses
the resulting immutable metadata with a new VM per original call. Public
execution still performs its complete admission each time. Selected providers
receive new objects made from the same captured initial bytes, retaining their
original public validation route. A detected byte/provider/selector change is
sticky; an unbound observation callback cannot establish a complete proof.

The native ServiceVerification controller uses the same input binding through
an explicit eighth import capsule and new authored HIA ports. The current graph
has 463 ports and 26 modes. The complete source and mechanical graph changes
are retained; original budgets, resource guards, and non-behavior mode semantics
are preserved. The existing runtime batch implementation and all seven of its
original test methods were imported unchanged.

## Source history and failures

The immutable v1-v4 fixtures preserve complete old/current files. The data-only
reader captures actual bytes and modes, refuses partial or unknown versions,
provides an explicit prior view, and rereads actual and projected files at the
end. The original method ASTs and counts remain intact. A later merged service
file needs an explicit new complete relation; changing a pin alone is invalid.

Both actual false-PROVED examples, initial failed preparations, missing prerequisite
attempts, syntax failure before packet execution, and the earlier outer 300 s
timeout remain in the complete archives. That timeout was reconciled to no
remaining owned process before the later separate run. Original 600/1800 s
child limits were preserved. No unknown run was replayed as if it had failed.

The Linux archive contains 3,939 physical files. Both ROG and Mac independently
verified every byte and mode. The Mac archive preserves 3,202 local counterexample,
source and import/history files with full hashes. No original output was deleted.
