# Partition framing parser: equivalent prefix dispatch

This change is based on frozen source `66e0b699e354ce90bf800c14b01a9624d4e3f1ee`.
It addresses repeated regular-expression dispatch in
`tools/core_syntax_partition_sources.py::_parse`; it does not change the proof
protocol or a qualification budget.

## Change and equivalence argument

The five existing regular expressions are compiled once with their original
patterns and default flags. Each non-continuation line is dispatched by an exact
literal prefix: `def ` or `theorem `, `#print axioms `, `import `, `namespace `,
or `end `. Those prefixes are mutually exclusive. Every match of an old pattern
requires its corresponding prefix, so skipping the other patterns cannot remove
a match. The selected compiled pattern still determines whether the entire
command, or the declaration prefix, matches. A malformed line reaches the same
unsupported-command rejection.

The UTF-8 encoding, newline checks, byte splitting, full per-line decode,
two-space continuation handling, declaration bytes, state transitions, error
messages, and final check remain unchanged. Induction on the input lines then
gives the same parser state and return value or first rejection for the same
input under the standard Python regular-expression implementation.

In particular, the declaration pattern retains Python's default Unicode word
boundary behavior. The parser is a restricted framing parser, not a complete
Lean identifier validator. Existing accepted duplicate imports and prints,
empty namespace wrappers, and ASCII declaration-name prefixes before certain
Unicode punctuation remain accepted here; downstream validation is unchanged.

No parsed-result cache, trusted validation cache, input truncation, sampling,
validator removal, generated-source change, or test-budget change is introduced.
The original workflow files and the original 46 / 207 / 705 test inventories are
not edited. The new tests live in their own independent module.

## Evidence and limits

`tests/test_core_syntax_partition_parse_fast.py` contains the frozen original
function body under the name `reference_parse`. Six tests compare returned
tuples and declaration bytes, or the exact exception type and arguments. They
cover imports and namespace transitions, continuation bytes, Unicode boundary
cases, malformed prefixes, newline/control characters, duplicate commands,
print positions, non-string inputs, and 1,024 deterministic source mutations.

An additional external differential audit wraps every `_parse` invocation in one
actual `core_seven_shared_acceptance_plan.prepare()` call. It compares both
implementations without caching or bypassing validators, and alternates which
parser is timed first. It also compares both framing outcomes on all 11 original
and 11 candidate modules, and requires their complete generated bytes to equal
the retained frozen-66e0 proof sources. Modules outside the restricted framing
grammar are recorded as matching rejections, not successful parses.

The evidence packet records actual call counts, input hashes, all 22 source
files, exact outcomes, raw stdout/stderr, tool/source identities, and outer
costs. Summed parser timings on this shared host are descriptive only. This
finite differential evidence is neither a general machine-checked proof of
Python behavior nor a completed Lean proof/replay run, and cannot close the
600-second or 180-second end-to-end gates on its own.

The first actual audit completed successfully: all 545 parser calls on 45 unique
inputs had identical outcomes, and all 22 generated sources matched the frozen
files byte for byte. Direct framing of the complete modules returned for 6 and
rejected for 16, identically in both implementations. The independent 6-test
module passed. Alternating parser-call totals were 7.266668261 seconds for the
old function and 3.651991177 seconds for the dispatch implementation; the audit
outer wall time was 58.430084328 seconds and includes both implementations.
No Lean invocation was made.

An earlier outer preflight stopped before preparation because it requested
`plan.json` instead of the retained `PLAN.json`. That raw setup failure is
preserved separately. Correcting the file path did not change parser source,
test inputs, validator behavior, or a qualification budget.
