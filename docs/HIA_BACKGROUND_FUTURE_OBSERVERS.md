# Native Future array observers

This component implements the internal captured-array operations used by public
wait and as_completed. The public native Iterable/iterator adapter remains a
separate required component. The full Future surface and background controller
are not declared closed by this qualification.

The complete six-word image is generated by the HIA packer from actual HIA
owner and binary64 arithmetic flats. It uses the existing fixed public Future,
kernel, value and timeout entries captured in the same global context.
Allocation is the closed anonymous mmap allocator with exact owned munmap;
no libc or host-language policy dispatcher executes in this image.

## Private input and output

S is HIABFO01, a 128-byte header followed by zero or N rows of 48 bytes.
O is at least 131072 bytes and W is the existing 256-byte global context.
The checked bridge rejects null, overflowing or overlapping nonempty views
before any policy effect. Successful completed calls return zero and a
128-byte HIABFOR1 record.

Header offset 8 selects 0 wait, 1 as_start, 2 next, 3 take_wait_row, 4 close.
For operations 0 and 1, offset 16 is N, offset 24 is the return condition
(0 FIRST_COMPLETED, 1 FIRST_EXCEPTION, 2 ALL_COMPLETED, 3 invalid), and
offsets 32/40/48 carry an actual owned-value timeout capability or all zero
for None. As_start requires condition zero. Each row is actual factory3Q
followed by Futurecap3Q. The rest of the header is zero. These fields are
internal capture results, never public verified/finished flags.

For operations 2 through 4, offsets 16/24/32 are the observer node and its
two random tags. Offset 40 is the row index only for take_wait_row; all other
fields are zero. Lookup walks the live registry before dereferencing an
opaque capability. It rejects a wrong type, busy node, wrong tags, stale
handle or duplicate row transfer.

Reply status is at 8 and kind is at 16. Normal kind1 is a wait result:
observer capability24/32/40, done count48, pending count56 and total64.
Kind2 is an as_completed iterator with the same capability fields.
Kind3 transfers one independent Future reference: factory24/32/40,
Futurecap48/56/64, unique index72, first input ordinal80, done membership96.
Take transfers a row at most once; close releases every untransferred row.
Kind4 is exhausted and consumes the iterator handle. Close returns kind0.
Errors retain the existing native Future status/class pair, detail96 and
total104; an owned typed exception capability, when supplied, is at72/80/88.
Cleanup failures are separately indicated at120. A stale private capability
has no inferred public Python meaning: exact native upstream error identity
is preserved. Ordinary allocation failure is status3/class103.

HIABFO02 is a strictly private as_start variant. Its timeout fields instead
hold a live empty as_start iterator capability. Under the global lock it
verifies that node's context, identity, type, zero cardinality and idle state,
then copies its already computed deadline. No raw deadline or caller truth
flag is accepted. The caller still owns and must close the empty capture.
This supports computing as_completed's deadline before native enumeration.

## Ordering, waiting and lifetime

All inputs are independently retained and deduplicated by actual retained
kernel identity. A dynamically sized vector, open-addressed identity table
and N-entry event queue have no 128-item admission ceiling. The registry and
initial kernel snapshot are synchronized with completion notification by the
global mutex at32. The namespace at W48 owns both active and inactive nodes;
type144 is 0 wait, 1 iterator, with 2 reserved for the lazy public adapter.
The array interface rejects type2. The fixed notify leaf skips inactive
nodes without interpreting their array fields.

The first kernel callback appends each completion at most once. Every
subscriber observes the same actual serialized completion order. A per-node
sticky32 readiness word at248, reset only under the lock after inspecting
the queue, prevents a wrap of the diagnostic W40 sequence from losing a wake.
Waiting uses real futex operations and real monotonic clocks. All references
remain held until transfer or close, and a linked node blocks global destroy.

Wait preserves early-condition and all-done bypass of timeout checks.
FIRST_EXCEPTION queries the actual public exception method and releases its
owned exception value; cancellation is not an exception trigger. The result
membership is frozen when the subscription is detached, even if an originally
pending Future subsequently completes.

As_start is called only at the first public next. It computes the original
binary64 timeout plus monotonic-seconds deadline before capture. Next drains
an entire buffered batch before checking that deadline again, checks expiry
before collecting a new batch, and preserves NaN, infinity, negative zero,
subnormal and arbitrary-integer conversion behavior. Timeout errors consume
the handle and release pending references. The exact pure arithmetic role
was independently checked in 61398 native calls, including direct calls to
the actual original C PyTime_AsSecondsDouble symbol. Integral seconds use
that function's quotient-first shortcut; the earlier float(ns)/1e9 proxy
missed four one-ulp counterexamples and is retained as superseded evidence.
Finite wait deadlines saturate at the original signed PyTime_t maximum,
confirmed against the actual _PyDeadline_Init symbol. Ordinary futex EINTR
is retried; no external typed interruption source is invented.

## Qualification scope

The final captured-array interaction used public Future v5, pinned by its
actual build receipt. The complete original-state/timeout suite made 1534
observer calls and 5536 public Future calls. It includes all256 combinations
of three pending/result/error/cancelled states and four return conditions,
type/sign/NaN/integer timeout behavior, 259 unique Futures from648 actual
references, multiple subscribers, retained original deadline capture and
partial collection failure.

Separate controls cover seven view refusals, six request refusals, forged
and stale handles, type2 cross-interface protection, four simultaneous native
iterators consuming32 completions in identical order, actual kernel ENOMEM
and getrandom EIO with complete reclamation, and native packer atomic refusals.
The companion JSON contains exact pins, reports and retained fixture failures.
Neither these tests nor the notify component prove the still separate native
Iterable adapter or complete public Future/controller surface.
