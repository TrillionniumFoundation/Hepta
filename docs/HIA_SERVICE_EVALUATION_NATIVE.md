# HIA service evaluation, adoption and lease invocation

This explicitly selected owner contains the complete original policy bodies for
`_native`, `_build_inputs`, `_build_receipt`, `_cost_ledger`,
`_hia_evaluate`, `_hia_adopt_native` and `invoke_lease`, plus
`_connection_arguments` and `_value_observation`. The independent retained
fixture preserves those exact bodies. No selected route executes that fixture
or a retained Python business body.

## Selection and custody

`HEPTA_HIA_SERVICE_EVALUATION_MANIFEST` is opt-in. A service captures an actual
immutable HIA mapping and its held checker capability during construction.
Ambient selector changes do not replace an existing service's mapping. A new
service performs fresh source, manifest and executable admission. The helper is
registered as a held service owner, not as a default Core checker selection.

`tools/build_hia_service_evaluation.py` accepts one explicit cold report or
development compiler. Matching cold admission retains the original 180-second
qualification and 3-second cleanup limits. Compilation uses the unchanged
20-second compiler observer. Development receipts confer no current-cold,
default, whole-stack, or source-deletion authority.

## Policy and physical mechanisms

The emitted HIA table owns branching, loops, comprehensions, generators,
named closures and their shared cells, helper dispatch, issued effect claims,
outcome acknowledgements and temporary/named-local retirement. Actual CPython
3.12, 3.13 or 3.14 profile is observed by the fixed bridge; HIA chooses the
reviewed retirement direction. Unknown future profiles are not guessed.

The Evaluation-local literal format adds tag 6 for exactly eight IEEE binary64
bytes. Each emitted literal index is boxed once per immutable image. Positive
and negative zero retain distinct payloads. Existing shared compilers and
their qualified images are unchanged.

CALL uses fixed generated literal keyword shapes and transfers operands to the
interpreter stack at the native claim. Keyword mapping calls have separate
DICT_MERGE, map-retirement and CALL permissions; dictionary displays use
DICT_UPDATE. Named closures and imports use the reviewed Build lexical and
physical import mechanisms. Exception identity, held traceback ownership,
PEP 479 and once-only unknown outcomes retain the shared continuation protocol.

## Preserved evaluation order

The original context's absolute `created_ns` establishes the deadline; neither
new callbacks nor this owner renew it. Reference checks run baseline then
candidate. Native budget claim, individual runs and terminal completion keep
their original order. An unknown execution does not complete or refund a claim.
Measurements publish before the full cost ledger, which publishes before the
evaluation receipt. Cost SQL retains `LIMIT 10001`, length/truncation observation,
then the first 10000 rows. Numeric and buffer observations remain complete.

The nine-body scope does not migrate the internals of Store/SQLite,
wall-clock acquisition, runner subprocesses, journal or ledger providers,
schema validation, proof engines, Emission, or compiler/backend subowners.
Those dependencies remain explicitly selected or retained providers.
Existing `_signature_values` remains the Emission owner's entry.

## Validation

Source controls verify every exact original body, current generated HIA and
fixed bridge bytes, original compiler limits, held checker registration, float
representation, and original deadline/publication order. Adapter controls keep
synthetic compiler/cold receipts separate from actual native execution.

Native controls compare all public entries and helpers with the original
controlled-provider corpus, retain full reports on failure, exercise actual
issued-frame/claim/ACK rejection, retained errors and object lifetimes, and
compare complete HIA output/workspace/canaries with the independent Core VM.

`tools/qualify_hia_service_evaluation.py --caller-group agent` executes all
original Agent 48 IDs. `--caller-group namespace` invokes the unchanged original
namespace wrapper and its ordered 35 tests; `--caller-group ledger` invokes the
unchanged original ledger wrapper and its ordered 48 tests. These are separate
1800-second groups with the original per-test 3-second and 1000-ms limits.
Each group compiles its own new candidate with explicit compiler/cold custody,
records actual HIA modes/mappings, poisons only the seven replaced service
bodies, and preserves every original result. The two helpers remain legitimate
foreign dependencies of other, unmigrated providers; they are separately
poisoned only in the complete selected controlled-provider corpus.
