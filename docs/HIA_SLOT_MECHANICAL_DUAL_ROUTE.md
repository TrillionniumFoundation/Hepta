Status: STATIC ONLY. No product, original oracle, test, compiler, generator, VM,
Native, SQL or GC execution occurred while preparing this layer.

## Version and callable boundaries

The pre-C selected HIA descriptor, all fifteen real-signature bridge templates,
and SlotOperationsFrame.finish remain the legacy v1/direct-env route. Existing
v2/v3/v4 companion behavior is not implicitly upgraded. The retained complete
business functions remain unselected references; the selected legacy route
still calls the HIA owner and its mechanical providers.

Only the explicit, digest-verified v5 branch creates a C callable. A private
version-selection flag is distinct from the live construction/active token:
selected v5 without a token refuses. Old route observation returns None without
moving its original post-argument-binding owner check earlier.

A C callable captures the exact bridge authority object, PID and thread. Its
admission callback and image check repeat actual live owner/pin checks. A later
scope with identical bytes and SHA is a different authority and cannot authorize
that callable. Failure never dispatches to legacy finish. A v1 callable does not
upgrade when later called inside v5: its original lazy/image pin rules determine
success or refusal, and the C counters must remain unchanged.

Raw Frame.finish remains its original HIA implementation. Explicit raw C
run_frame is still a separately authorized diagnostic API and cannot satisfy
the public v5 qualification. Ordinary adapter import performs no C preload.
The same code and explicit route rule apply to source and installed wheel.

## Actual C execution evidence

The C module records four fixed per-mode uint64 arrays: actual public Vectorcall
attempts, explicit raw-Frame C attempts, successful INITIALIZE receipts, and
complete FINALIZE receipts followed by the existing loss check. Counters do not
claim terminal success after later cleanup. Recording does not allocate Python
objects or change a return value. A read-only snapshot has schema, actual PID and
overflow flag. There is no reset API; a fork starts a separate PID epoch.
Saturation makes the independent reader refuse qualification.

Full finite/public launchers capture counters before and after the unchanged
complete observer. Loaded-library identity alone is insufficient. They require
actual public C calls and initialized HIA, with zero raw-Frame shortcuts.
Installed normal and lost-SQL-ACK workers must independently show actual C/HIA
entry; replay/request versus startup counts remain the original observations.
Counters are separate evidence. No original GC, traceback, error, result, case,
budget, or input field was changed or masked.
