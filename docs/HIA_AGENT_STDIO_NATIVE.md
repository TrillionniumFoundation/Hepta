# HIA-native Agent stdio entry

This explicitly built Linux x86-64 entry implements `capabilities`, `verify`,
`compile`, `render-assembly`, `assemble`, `check-assembly` and `catalog` without Python, a host JSON parser,
Rust, LLVM, libc, a dynamic
loader or a second executable at runtime. It is the first native replacement
component of the Agent-only product, **not** its complete editing/persistence,
runtime, package/build or installation/release implementation.

## Build and invoke

```sh
python -B -m tools.build_hia_agent_stdio \
  --compiler /qualified/B3.image.bin --cold-report /completed-cold.json \
  --output /new/private/agent --output-profile flat
/new/private/agent/hia-native capabilities
/new/private/agent/hia-native verify < program.core.json
/new/private/agent/hia-native compile < program.core.json > program.image.bin
/new/private/agent/hia-native render-assembly < program.core.json > program.hepta
/new/private/agent/hia-native assemble < program.hepta > program.image.bin
/new/private/agent/hia-native check-assembly < program.hepta
/new/private/agent/hia-native catalog --schema hepta.hia.program.v8
```

The build/custody driver is still Python. Actual HIA code compiles the command
dispatcher and ELF packer with the admitted native compiler; the packer writes
ELF headers, patches three-image relative calls and copies the exact HIA images
and an immutable opcode catalog table.
The platform adapter is literal-ISA-authored syscall/ABI glue emitted by that
HIA packer. It neither parses a payload nor substitutes a foreign compiler.

The command string is selected by a HIA function, with exact length/byte
matching. `capabilities` returns versioned JSON without reading stdin.
`catalog` also leaves stdin unread. It returns the same JSON bytes as the
hosted catalog for each declared primitive profile (v1–v8), defaulting to the
latest profile. The table is generated at build time from the shared opcode
declarations; at runtime HIA validates the schema arguments, bounds the selected
table entries and emits the reply without reading external files.
`verify` accepts the complete existing native JSON-Core profile and invokes the
real semantic/resource compiler; only after acceptance does HIA emit the JSON
verification response. Compilation occurs in private memory but no generated
machine code is published by `verify`. `compile` publishes generated bytes on
stdout. `render-assembly` publishes the native frontend assembly only after the
mandatory native semantic/resource compiler accepts it. It publishes no machine
code and cannot return an unchecked view of malformed, invalid SSA, leaking or
unsupported programs. The exact original build profile is preserved; this is
not a general Core renderer or a profile upgrade. `assemble` passes the submitted
HIA assembly bytes directly to that same native semantic/resource compiler,
without the JSON representation frontend or a source-language conversion.
`check-assembly` follows the same direct assembly admission and operator-selected
output-profile check, then returns the verification JSON reply instead of any
generated machine-code bytes. It neither bypasses resource checking nor executes
the compiled program. The exact diagnostics of the ordinary hosted
`hia check-assembly` action are outside this bounded native command contract.
Both assembly and the JSON frontend preserve explicit primitive v6/v7/v8
schemas. V6 cannot use chain types or operations, and only v8 can declare
returned loans. The compiler does not relabel old programs as v8.
These are command-specific output contracts, not JSON-lines RPC.

Fixed-profile builds choose `flat`, `elf` (ET_REL objects) or `exec` (the
existing syscall-only program entry). The capabilities record reports 0, 1 or 2
respectively. The sealed release uses one `portable` build (profile 3), which
defaults to flat and accepts one `--output-profile=flat|elf|exec` argument after
a compile, verification or assembly command. For example:

```sh
hia-native assemble --output-profile=elf --input-file exported.hepta > exported.o
```

The portable build accepts `--input-file FILE` for verification, compilation,
rendering and both assembly commands, after any output-profile option. It reads
that ordinary file instead of stdin, with the same byte limits and parser. The
file is opened without following a final symlink; directories, FIFOs and
other special files are refused. Discovery and the fixed-profile builds keep
their original argument contracts.

The same sealed release provides `hia-elf-link`. For an object exporting a
supported no-argument scalar entry, `hia-elf-link entry exported.o > program`
links through HIA without invoking an external linker. Additional ordinary
object files may be passed in link order. The linker still accepts its existing
`HIALNK01` framed stdin input when invoked without arguments. File mode
refuses symlinks, non-regular objects and an oversized aggregate before
producing any bytes; the original bounded ELF profile still applies.

Input module or
export metadata cannot switch that operator-selected profile. For `assemble` and `check-assembly`,
an ordinary module selects flat output, `selfhost_elf` or explicit scalar
exports select ELF, and `selfhost_exec` selects the executable profile. The
caller must provide source matching the selected profile; the adapter never
rewrites its module or exports. After successful semantic compilation, a
private HIA dispatcher phase checks the actual flat/ET_REL/ET_EXEC result against
the build profile before publication. This is an output-selection check, not
a general ELF validator or an admission path for submitted machine code. The existing
no-argument JSON compiler filter is unchanged.

## Limits and failure contract

Input JSON for `verify`, `compile` and `render-assembly` remains bounded to
8 MiB, 1,048,576 nodes and depth 128; there is no
new JSON envelope subtracting from those budgets. The unchanged compiler
source/output/workspace ceilings are 1 MiB. `assemble` and `check-assembly` read at most 1 MiB plus
the one-byte oversize guard, reject excess bytes, and copy the unchanged
input into the existing disjoint compiler source region. Commands never infer
or convert the input language. Capabilities separately report
`assembly_input_bytes_max`. The separate anonymous RW mapping
has the same 88 MiB plus 8192 bytes transport budget as the JSON CLI; code is RX.
The private command mode occupies bytes beyond the input's oversize-read guard,
outside all frontend/compiler output and workspace regions.

A command is required. The adapter scans at most 32 command bytes; the HIA
dispatcher accepts only the seven exact declared words. `catalog` accepts
bounded tokens for the optional `--schema` setting. The portable compiler
checks the explicit options before opening a file or reading stdin.
Exit codes:

| Exit | Category |
| --- | --- |
| 0 | Accepted operation completed |
| 2 | JSON/assembly representation, semantic/resource or output-profile refusal |
| 3 | Wire/node/depth/assembly/native-output capacity |
| 4 | Mapping or descriptor I/O failure |
| 64 | Invalid argument count or unsupported command |

Refusals produce no stdout before successful input/semantic/capacity admission.
The adapter attempts a versioned JSON category on stderr. Descriptor failure
can prevent or truncate that diagnostic; the exit category remains authoritative
when the process exits normally. Actual EINTR is retried for input and both
output streams. A successful partial stdout write followed by I/O failure is
not transactional publication. Kernel signals can terminate the process;
SIGPIPE disposition is inherited. Only the explicitly named input file is
opened. There is no automatic retry of execution or deployment/persistence authority.

## Evidence and remaining scope

Independent Core VM observations precede native builds: exact command/profile
selection and output guards, verification replies, every packer-produced byte
in bounded windows, ELF headers/call relocations/copied payloads and refusal
canaries. Native qualification must use a genuine completed matching cold
receipt, not a shape-only fixture. Original/modified compiler chains, real
generated-program execution, installed copies, profile-switch refusals,
ownership rejection, I/O failure and native syscall traces are separate controls.

The assembly continuation checks exact 1 MiB and plus-one input, command-language
mismatch, missing effects, invalid loans, leaked owners and all cross-profile
refusals. Raw original and modified HIA compiler sources can be assembled to
standalone executables that compile the same source through their own
stdin/stdout entry under an empty `PATH`. The original three images must agree;
the modified first image must differ from the next, the next two must agree,
and the modified fixed point must differ from the original. This is compiler
self-hosting, not complete Agent package/build/install/persistence closure.
Fresh matching-source cold qualification and actual native observations are
required for changed source; these tests inherit no prior-source acceptance.

The hosted `hia` bridge remains during replacement. The high-level language
and old `hepta` CLI entry are removed; no compatibility entry is packaged. Native command presence does not qualify complete Agent editing,
durable recovery, Core modules/build, production runtime/library, clean-machine
native-only installation, final artifact lifecycle or whole-product retirement.
No production/default/release lock or service is changed by this component.
