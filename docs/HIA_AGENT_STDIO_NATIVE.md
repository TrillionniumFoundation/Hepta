# HIA-native Agent stdio entry

This explicitly built Linux x86-64 entry implements `capabilities`, `verify`
and `compile` without Python, a host JSON parser, Rust, LLVM, libc, a dynamic
loader or a second executable at runtime. It is the first native replacement
component of the Agent-only product, **not** its complete editing/persistence,
runtime, package/build or installation/release implementation.

## Build and invoke

```sh
python -B -m tools.build_hia_agent_stdio \
  --compiler /qualified/B3.image.bin --cold-report /completed-cold.json \
  --output /new/private/agent --output-profile flat
/new/private/agent/hia-native capabilities
/new/private/agent/hia-native verify < program.core.json
/new/private/agent/hia-native compile < program.core.json > program.image.bin
```

The build/custody driver is still Python. Actual HIA code compiles the command
dispatcher and ELF packer with the admitted native compiler; the packer writes
ELF headers, patches three-image relative calls and copies the exact HIA images.
The platform adapter is literal-ISA-authored syscall/ABI glue emitted by that
HIA packer. It neither parses a payload nor substitutes a foreign compiler.

The command string is selected by a HIA function, with exact length/byte
matching. `capabilities` returns versioned JSON without reading stdin.
`verify` accepts the complete existing native JSON-Core profile and invokes the
real semantic/resource compiler; only after acceptance does HIA emit the JSON
verification response. Compilation occurs in private memory but no generated
machine code is published by `verify`. `compile` publishes generated bytes on
stdout. These are command-specific output contracts, not JSON-lines RPC.

The output profile is chosen explicitly at build time: `flat`, `elf` (ET_REL
objects) or `exec` (the existing syscall-only program entry). The capabilities
record reports its numeric build profile, 0/1/2 respectively. Input module or
export metadata cannot switch that operator-selected profile. The existing
no-argument JSON compiler filter is unchanged.

## Limits and failure contract

Input JSON remains bounded to 8 MiB, 1,048,576 nodes and depth 128; there is no
new JSON envelope subtracting from those budgets. The unchanged compiler
source/output/workspace ceilings are 1 MiB. The separate anonymous RW mapping
has the same 88 MiB plus 8192 bytes transport budget as the JSON CLI; code is RX.
The private command mode occupies bytes beyond the input's oversize-read guard,
outside all frontend/compiler output and workspace regions.

Exactly one argument is required. The adapter scans at most 32 command bytes;
the HIA dispatcher accepts only the three exact declared words. Exit codes:

| Exit | Category |
| --- | --- |
| 0 | Accepted operation completed |
| 2 | JSON representation or semantic/resource refusal |
| 3 | Wire/node/depth/assembly/native-output capacity |
| 4 | Mapping or descriptor I/O failure |
| 64 | Invalid argument count or unsupported command |

Refusals produce no stdout before successful input/semantic/capacity admission.
The adapter attempts a versioned JSON category on stderr. Descriptor failure
can prevent or truncate that diagnostic; the exit category remains authoritative
when the process exits normally. Actual EINTR is retried for input and both
output streams. A successful partial stdout write followed by I/O failure is
not transactional publication. Kernel signals can terminate the process;
SIGPIPE disposition is inherited. There is no arbitrary filesystem-open path,
automatic retry of execution or deployment/persistence authority.

## Evidence and remaining scope

Independent Core VM observations precede native builds: exact command/profile
selection and output guards, verification replies, every packer-produced byte
in bounded windows, ELF headers/call relocations/copied payloads and refusal
canaries. Native qualification must use a genuine completed matching cold
receipt, not a shape-only fixture. Original/modified compiler chains, real
generated-program execution, installed copies, profile-switch refusals,
ownership rejection, I/O failure and native syscall traces are separate controls.

The hosted `hia` bridge remains during replacement. The high-level language
and old `hepta` CLI entry are removed; no compatibility entry is packaged. Native command presence does not qualify complete Agent editing,
durable recovery, Core modules/build, production runtime/library, clean-machine
native-only installation, final artifact lifecycle or whole-product retirement.
No production/default/release lock or service is changed by this component.
