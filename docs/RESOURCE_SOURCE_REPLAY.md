# Resource graph correspondence with actual source

`python -m hepta.resource_ir GRAPH.json` independently checks the resource
graph's declared types, owners, loans, control flow and external obligations.
Its source and project hashes are assertions supplied by the graph producer.
A different, internally valid graph can carry the same hashes. Data-only
verification therefore continues to report `source_binding_verified=false`.

The additional read-only command connects this verifier to the actual source:

```sh
python -m hepta.resource_source path/to/main.hepta graph.json
python -m hepta.resource_source path/to/package graph.json --locked
```

The graph input is the `resource_ir` member exported by `hepta resource-ir`,
not the export wrapper or a previously successful validation receipt.
The graph must have the exact current resource-lowering format. Legacy
graphs remain valid inputs to the standalone data verifier where supported;
source replay requires regenerating them with the current compiler.

## What is checked

1. Parse bounded JSON with duplicate-key and nonfinite-number rejection.
2. Run the existing independent resource verifier on a frozen JSON copy.
3. Load the actual source/import/package graph using the existing loader.
   Run the actual frontend and a fresh pinned Rust metadata qualification.
   Caller-supplied ASTs, type tables and successful native receipts are not
   inputs to this interface.
4. Use `semantic_ir.lower_checked_program`, the single canonical semantic
   encoder, and the existing `resource_lowering.lower_resource_ir`. No
   alternate checker, source grammar or resource-lowering authority is added.
5. Require exact source/project identities and equality of the full resource
   projection: type definitions, functions, return origins, blocks, owner and
   loan operations, and external obligations.
6. Recheck every loaded source and path binding before accepting the result.

The receipt is `hepta.resource-source-validation.v1`. A successful default
run reports `source_replayed` or `source_replayed_with_external_assumptions`
and `source_binding_verified=true`. It binds the current source inventory,
project identity, canonical semantic digest, independent resource IR digest,
compiler identity and the fresh source-validation report. The receipt's own
digest identifies those bytes; it is not a signature or code-generation
authorization.

An explicit `--frontend-only` run reports `frontend_only_source_replayed` and
`native_reference=not_run`. It cannot inherit a previous native pass. A
missing, wrong or failing Rust compiler rejects the default profile. The
command performs metadata checking; it does not execute the user's program.

`E_RIR_SOURCE_IDENTITY` identifies a stale or forged source/project identity.
`E_RIR_SOURCE_GRAPH` identifies an internally valid graph that differs from
the actual source projection. `E_RIR_SOURCE_STALE` identifies a source or path
change during replay. Ordinary resource failures retain their existing
diagnostics, such as `E_RIR_LEAK` or `E_RIR_LOAN_CONFLICT`.

## Adversarial controls and preserved assumptions

The source-replay tests include graph changes that pass data-only validation:

- Erase balanced allocation/move/drop operations from an otherwise empty body.
- Replace a returned borrow's declared origin and its matching loan with a
  different argument of the same type.
- Remove an external declaration, its call and its obligation together.
- Replace the graph's source identity with another valid-looking digest.

Replay rejects each against the unchanged real source. Tests also change an
import while preserving entry-file bytes, change source during replay, rebind
an import symlink, remove a drop, elevate proof claims, supply ambiguous JSON,
and attempt to override an actual Rust borrow rejection with a valid graph.

Successful foreign calls retain their `assumed_not_verified` resource
obligations, canonical unsafe/FFI boundaries and frontend foreign assumptions.
The full canonical inventory is included even where a source effect has no
separate operation in the lossy resource abstraction. No unproved obligation
is promoted to verified.

## Scope

Exact replay strengthens the connection between a serialized graph and the
currently checked source. It does **not** independently prove the lowering
algorithm. The resource projection still abstracts scalar values, so it does
not establish arithmetic correctness, functional equivalence or termination.
Native binaries are still generated by the existing source backends, not by
this resource graph. Stored-borrow records, raw pointers and concurrent/I/O
profiles outside the resource lowerer's supported subset still reject.

The source rechecks detect mutations across the observation window; they are
not an atomic filesystem snapshot against noncooperating writers. The trust
base still includes the frontend, canonical encoder, resource lowerer, native
compiler and host filesystem. Whole-language soundness, source/backend
refinement and foreign correctness remain explicitly unproved.

## Executed qualification for this implementation

The focused source/graph/CLI suite passed **44/44 tests** with actual Rust
1.90.0, including **14 new source-replay tests** and native metadata checks of
the owned library, owned generic library and returned-view programs.
`tools.validate_resources` additionally built and executed those three
programs and rejected all **11/11** existing adversarial graph mutations.
Each retained graph then passed a fresh source-replay invocation.
These observations qualify this resource-replay increment; they do not close
the repository's whole-language or production-resource blockers.
