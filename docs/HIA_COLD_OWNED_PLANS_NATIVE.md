# Native owned and chain cold plans

The retained original case inventory is 39 owned sources, 69 chain sources, 37 owned refusals, 59 chain refusals and seven allocator sources. Every actual source and original declared fixture assertion is in cold_owned_chain_cases.json. The native plans retain both independent reference arms: the complete resource VM, and an independently constructed native resource backend that performs real libc allocation.

## Phase boundaries

`generate_hia_cold_owned_plan.reference_family(p,h,cases,family=...)` constructs the three pre-B0 plans named owned, chain and allocator. None imports a target compiler. Each source is admitted and projected by the independent HIA roots, then a fresh complete independent HIA VM executes it with the original ten-million-step, 256-frame, 16 MiB heap limits and exact allocation failure index. The shared case gate validates the original return, trap or budget category; no generic nonzero result substitutes for a semantic error. Full output, declared scalar assertions, normal owner/loan conservation and the allocator resource counts are checked.

Each phase publishes one `{family}-reference.bin`. The format starts with HIAOWR01 and a u64 count. Every fixed 216-byte record contains the actual source SHA256 (32 bytes), actual VM report length (u64), exact allocation failure index (u64), return/trap/budget kind (u64), then the complete HIASPR01 report padded to 160 bytes. Padding is transport storage, never a simulated result. All actual process requests, stdout, stderr and ledgers remain in the lossless journal.

`qualify_family(p,h,compiler,cases,refusals,family=...,label=...)` consumes the same-run reference bundle. It validates each current source digest and original profile facts, then regenerates a fresh full Core projection and an independent native ET_REL. The actual target compiler produces its own object. The native strict seven-section inspector retains every original owned ELF condition; the general object has its original export and closed-import inventory checked independently. Both objects are linked by HIA and invoked through actual libc startup/dlopen/exit with the complete original output and return snapshot. Native SIGABRT versus target SIGILL remains distinct. Both original short-output cases in each family retain transactional output checks. Every refusal replays independent general admission/rejection and actual target rejection with unchanged full source and output.

The four qualification phases are original-owned, original-chain, modified-owned and modified-chain. The chain phases call `qualify_allocator(p,h,compiler,allocator_cases,label=...)` after their ordinary and refusal cases. Each phase stays below the existing 64-import and 180-second limits; no budget or original assertion was relaxed.

## Actual allocation observation

Each of the seven allocator cases runs twice per compiler: independent native and target. The HIA witness bundle uses actual libc calloc/malloc/free, the original six selected NULL points, and the 5000-node control. The driver owns an exact 1,048,712-byte auxiliary descriptor as its distinct allocator capability class. It snapshots the entire object after normal or signal termination. The native event gate validates all 16 counters and every recorded event, original failure position and allocator, unique live identities, free identities/sizes, counts and conservation. All 32,768 slots are retained. No simulated cleanup is performed after a trap.

The expected output and return come from the same-run complete VM record. Fixture allocation counts and the selected allocator are original assertions. The direct node route remains malloc and the target node route calloc. The control observes 10,000 allocations and frees, covering both the 5000 payloads and nodes.

## Independent observer construction

The independent linked observer is now built without GNU ld: the independently compiled actual HIA policy, HIA object packer and qualified HIA executable linker generate its complete executable. It is not built by the target or successor. Its pin and independent actual byte/compiler dlopen qualification are included in the provenance report. The system loader and libc remain explicit mechanical host dependencies.

## Evidence

HIA_COLD_OWNED_PLANS_QUALIFICATION.json records the exact source pins, seven phase plans, complete immutable imports, publications, elapsed times, trace hashes and lossless journals. Every descendant exec was a sealed descriptor execution; no Python, host compiler or host linker ran in the replay. Prior component evidence and failed development artifacts remain separate. This closes these retained families and their allocator component boundary; whole-source cold orchestration, final installation/rebuild and old-stack retirement still require their own final gates.
