# C++ contract v5: composed automatic lifetimes

`hepta.cpp-contract.v5` adds a required `pipelines` array to the v4 fields.
Earlier schemas retain their exact field sets and reject a v5 pipeline. The
implementation remains an explicit C++ bridge: it does not translate or certify
the retained foreign library.

Each pipeline declares at most sixteen inputs and thirty-two steps. It may
construct up to eight objects using existing native-checked constructor
contracts, then call selected methods on those objects. A method can materialize
a scalar or trivial POD copy under a fresh name. That copy can become an
argument to a later construction or call of exactly the same type.

```json
{"op":"call","object":"source","method":"at","args":["index"],"result":"copied"}
```

An argument can name an input or an earlier copied value. No object name, raw
address, future result, synthesized span or C++ expression can be substituted.
Inputs preserve the declared type, argument category and call-only retention.
Copied values can feed only value or const-reference scalar/POD parameters.
Reference-returning methods are materialized into explicit value types before
any subsequent owner mutation or destruction. Every input, object and copied
value must participate; shadowing and ambiguous result names reject.

Objects remain ordinary automatic C++ locals inside one generated lambda. On
normal return the scalar/POD result is materialized and completed objects are
destroyed in reverse construction order. Only after the lambda and its
destructors finish does the wrapper publish the result to the caller. C++
exception unwinding cleans up already completed objects; the wrapper returns
status 3 and leaves the output sentinel unchanged. A failed constructor's own
member cleanup follows ordinary C++ semantics. A native test separately
observes constructor failure, later method failure, reverse destructor order,
reference-copy-before-mutation, and output publication after all destructors.

No registry lookup, lock, shared-owner copy or heap allocation is generated by
the pipeline itself. The ordinary handle entry points are still generated and
counted separately; their costs do not become pipeline costs. Foreign objects
and methods may allocate, use stack, block or terminate. Their call-only
nonretention, alias discipline, effects and correctness remain external
obligations. A `noexcept` destructor violation, longjmp, process termination,
nontermination or foreign undefined behavior is not repaired by this wrapper.

## Real library execution and upgrade

`examples/cpp/composed/contract.json` and one unchanged Hepta caller implement
two actual library sequences:

1. Construct `std::vector<int64_t>`, append and copy an element, construct
   `std::deque<int64_t>` using that copied value, and copy its selected element.
2. Parse a real nlohmann/json document, replace an array element and copy the
   sum; use that value in a separately constructed second document; feed its
   copied sum to a vector and return a copied element.

The existing authored `Document` adapter remains separately counted C++. Its
upstream implementation is the exact, unmodified nlohmann/json **3.11.3** and
**3.12.0** single-header releases already pinned with their MIT licenses in
`tests/fixtures/cpp_upgrade/lock.json`. The standard library and actual compiled
header/runtime dependency closure are recorded for each native build.

The qualifier executes **56 vector/deque cases and 112 JSON composition cases
per version**, each through independent direct C++, the generated bridge called
from Hepta, and a Python list/JSON oracle. It checks thirteen actual bridge C
export symbols, unchanged public API bytes and generated implementation bytes
after normalizing only the selected-version directory. No per-version adapter,
contract or consumer changes are allowed. Generation, compilation, linking and
execution time are observed; human review hours and agent tokens remain
unmeasured.

## Full allocation-failure observation, including termination

Every route and pipeline first runs a separate calibration invocation of the
actual binary. Its raw output supplies the allocation-site denominator. Each
site then runs in an isolated process; caught failures must restore the ordinary
allocation baseline, preserve output and recover on the following call.

The first full development run observed four allocation sites for each
vector/deque route and thirty-five for each JSON composition route, on each
release. All **156** fault attempts were executed. **132** were caught, cleaned
up and recovered. The remaining **24** terminated with `SIGABRT` and
`std::bad_alloc`: JSON sites 30–35 for both direct C++ and Hepta bridge routes on
both releases. The upstream library's allocating noexcept destruction remains
unrecoverable at those sites. The report keeps
`all_allocation_failure_paths_recovered=false`.

`ok=true` in this observation protocol means the fixed sources, native
comparisons, upgrade and complete failure observations passed their stated
checks. Its status is `complete_observation_with_foreign_termination`; it does
not mean every foreign failure is recoverable. These records count **two
bridge upgrade variants and zero native C++ implementation migrations**.

Three actual negative controls are retained: a native method-signature
rejection, a generated wrong result that disagrees with the independent oracle,
and an actual removed destructor that leaves a measured allocation live.

## Reproduce

```sh
python tools/qualify_cpp_composed.py \
  --workdir /tmp/new-cpp-composed-run \
  --cxx /absolute/path/to/g++ \
  --rustc /absolute/path/to/pinned/rustc

python -m unittest tests.test_cpp_pipelines -v
```

The work directory must be new. Plans, expected outputs, all native stdout and
stderr, source/artifact hashes, intermediate failures and per-site outcomes are
retained. The validator compares summaries with actual calibration/fault/raw
outputs; removing a failure row cannot preserve its denominator. These checks
verify retained local consistency, not third-party execution attestation.
