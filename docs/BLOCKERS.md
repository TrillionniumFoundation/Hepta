# Hepta blocker ledger

用户目标保持不变：一门适合 AI agent coding、保留甚至超越 Rust 的性能与资源管理优势，并具有 C ABI / 硬件适配能力的新语言，正式命名 **hepta**。

本次实现是该目标的第一个可执行阶段。**整个生产语言目标尚未完成**；以下两组不能相互替代。实现了 bootstrap 不会把普遍性能、真机、安全证明或 agent 实证自动标为关闭。

## 第一阶段的实现与验证门槛

这些项目已实现；最终快照是否全部通过由 `artifacts/release-validation.json` 和其引用的证据决定。

| ID | 门槛 | 闭合证据 |
| --- | --- | --- |
| M01 | 名称、源码工程和版本化语法 | Hepta 0.1.0、SPEC.md、严格 AST parser |
| M02 | 类型与真实借用验证 | 正反例 + 固定 rustc 非空 metadata；不以frontend-only代替 |
| M03 | 调用链效果与资源条款 | fixed-point、未知效果/预算拒绝、隐式分配/阻塞负例 |
| M04 | 正常路径线性资源 | Buffer/Task移动、分支、循环、错误式早返回、泄漏及重复消费负例 |
| M05 | 真实原生程序 | parser、ownership、tasks 三个可执行样例 |
| M06 | 本机 C ABI | 双向调用、结构体按值返回、标量/嵌套/数组/指针声明差分矩阵 |
| M07 | 无标准库对象 | x86-64 / AArch64 / Cortex-M / Windows x64 对象编译；符号检查 |
| M08 | Agent 检查与修改接口 | inspect/patch、过期身份、合同变化、源码注入、非合作写入边界 |
| M09 | 有界范围性能事实 | 独立Rust/C基线、正确性、机器码比较、固定参数与随机运行顺序 |
| M10 | 可重放交付 | 工具链校验和、源码身份、执行报告、测试与安装/复现命令 |

M07 是交叉对象资格，**没有把未执行的目标记为运行资格**。M09 是报告中被测函数的事实，**没有扩大到所有程序**。M08 的事务只覆盖单编译单元、合作写入者及已声明合同，**不证明实现行为等价**。

## 本轮审查中发现并修复的实际缺陷

- 假rustc进程返回0可能被误当原生验证；现在检查版本身份及非空产物。
- 显式失效工具链曾静默回退；现在拒绝。
- read/mut标量被错误发射为引用值；现在按值读取正确解引用。
- C/C++关键词、typedef与标准宏冲突可能生成非法头文件；现在保守拒绝。
- 已验证候选在暂存期间可能覆盖新内容；增加替换前复核并明示合作写入者边界。
- unsafe效果可能通过普通调用包装洗掉显式边界；现在调用点也要求unsafe块。
- Task/Buffer泛型闭角紧邻等号的词法拆分；已修复并纳入回归。
- 局部名称可能遮蔽生成的函数名字；当前子集拒绝相关碰撞。

准确的测试数量、最终源码身份和运行结果以最终报告为准。
