# R10 actual prefix to the original eight groups

This is authoring of an explicit development successor. No binder, helper
gate, semantic Native/VM test, aggregate execution, CI or default selection is
performed by the authoring freeze. The R9 five-pass/one-fuel-failure result is
unchanged. The real R10 prefix has generated and compiled; its independent
terminal reader must succeed before these scripts accept its inputs.

## Exact binding order

1. Root runs the independent R10 prefix reader. It checks the original 6,777
   fresh inputs, all three owners, 70 old capsule members, 36 complete input
   copies, both six-buffer calls, canaries, frame and ELF, and the two Core
   projections with all nine new edit paths. It writes its actual result.
2. `prepare_controls_author.py` requires that result's path and exact Git blob
   as explicit arguments. It reads every new actual source/image/ELF role,
   original owners and complete generation reports. It rejects a missing,
   failed, changed, or predicted result. It preserves the original 948 input
   roles and adds 14 actual R10 roles.
3. `verify_controls_author.py` reads all 67 controls and all 14 new roles,
   checks the whole old-plan inverse and ten precise existing-file changes.
   The actual ELF length must equal the Root result and remain within 1 MiB.
4. `make_handoff.py` rechecks the complete consumed control bytes and the
   new actual roles, then freezes `HANDOFF.json`. None of these stages executes
   a product. Their exclusive output writes make an accidental second binding
   fail; no attempt directory is overwritten.
5. A separately reviewed helper boundary gate must pass before Root launches
   the unchanged original eight groups once. That new gate supplements the
   original cases; it cannot alter, omit, replace or relabel any of them.

The executable path and explicit environment remain from the original plan;
only its HOME and the independent output roots change. The single outer
watchdog is 1,800 + 3 seconds. Every original product owner remains 180 + 3
seconds; compiler 20 seconds / 10 CPU seconds; each VM 10,000,000 steps,
1 MiB heap, depth 128. The 3 GiB entry floor, one-attempt and fail-stop rules
are unchanged. A failed group prevents all later groups.

## Exact source scope

The frozen 3,180-file source and ordinary B3/profile compiler remain original.
Only this private test reference accepts the R10 source and actual image; the
public R5 profile must reject it. The three private reference function bodies,
the original `run_controls.py`, the original oracle plan and all original
support function bodies are byte-for-byte retained. New complete inputs are
recorded under R10 role names. Legacy R8 output basenames are explicit retained
names inside the new scope, not an assertion that the R8 image was executed.

The three aggregate methods change only exact source-bound SHA/length
literals. The original kernel fixture literal is `232b616...` and is inverted
from the original method, not guessed from the later R4 fixture's hash.
All test bodies, assertions, IDs, order and original raw input bytes remain.

The R9 full-body author scripts are saved in `before/`. The 42 and 8 R9 label
changes and explicit paths/extra scalar proof are fully invertible to those
scripts. No old preproof history is republished as a new event.

## Evidence and limits

All actual initial/final buffers, canaries, source/request/image pins, elapsed
time and original owner receipts remain required. No actual byte is replaced
by an expected oracle; missing evidence is a failure. Independent terminal
readback must inspect every physical span, including both guard ends, even
where an old runtime validator only recorded their booleans.

No old fuel failure, ordinary-encoding qualification, matching-current-cold,
installation, public entry acceptance or whole-Native conclusion transfers to
this successor. The helper gate and eight groups are still unexecuted.
